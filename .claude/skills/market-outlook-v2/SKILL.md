# 東証取引見通し・振り返り v2

```yaml
---
name: market-outlook-v2
description: 東証取引見通し・振り返り v2（データ自動取得+バリデーション+構造化8ステップ分析）
user-invocable: true
allowed-tools: Read, Write, Bash, Agent, WebSearch, WebFetch
aliases: ["/market-outlook-v2", "/mo-v2"]
---
```

## 概要

1日2回（AM/PM）実行に対応した東証マーケットスキル v2。v1からの主な変更点:
- メインエージェントがデータ取得+バリデーションを実行（サブエージェントはJSON受け取りのみ）
- 構造化8ステップ分析フローの導入
- 出力構成を9セクション構造に刷新

- **AM（見通し）**: 夜中の米国市場結果をベースに、当日の東証取引見通しを提供
- **PM（振り返り）**: 日中の日本市場結果を集約し、値動きの要因分析・AM予想との比較を実施

## 処理時間・コンテキスト最適化

- **目標処理時間**: 15分以内（サブエージェントタイムアウト: 600秒）
- **WebSearchクエリ上限**: 合計6クエリ（AM: 3, PM: 3）
- **WebFetch上限**: 合計5URL
- **ETF API**: フォールバック含め最大3回
- **yfinance取得済み数値のWebSearch再確認禁止**
- **同一URLへの再アクセス禁止**
- **AM実行時はPM専用セクションを参照しない**

### コンテキスト最適化設計

- サブエージェントへの読み込みファイル: 2つに限定（market-data-collection-v2.md + output-formats-v2.md）
- SKILL.md自体はサブエージェントに渡さない

## パラメータ一覧

| パラメータ | 値 | 用途 |
|-----------|-----|------|
| VIX係数（通常） | 0.05% | シナリオ分析レンジ幅 |
| VIX係数（VIX>30） | 0.04% | 高VIX時の縮小係数 |
| 横ばい判定閾値 | ±0.5% | 的中判定の横ばい基準 |
| 微小変動閾値 | ±0.1% | 判定不能の基準 |
| 時間帯判定境界 | 15:30 JST | AM/PM自動判定 |
| 高ボラモード閾値 | VIX > 30 or 日経前日比 > ±3% | 高ボラモード発動 |
| 危機モード閾値 | VIX > 35 | 危機モード発動 |
| actual_flow横ばい閾値 | ±0.3% | 過去コンテキストの実績FLAT判定基準 |

**VIX係数の算出ロジック:**
- 通常時: `レンジ = CME ± (VIX × 0.05%)`（例: VIX=20 → CME±1.0%）
- VIX>30時: `レンジ = CME ± (VIX × 0.04%) × 1.5`（高ボラモードの1.5倍拡大適用後）
  - 0.04%への縮小は過大レンジ防止のダンパー。1.5倍拡大との組み合わせで適度な拡幅を実現

**過去コンテキスト補正**:
- 予測方向とtrend_summaryが同方向 → confidence維持
- 予測方向とtrend_summaryが逆方向 → confidence 1段階下げ候補（CME・VIXの根拠が強い場合は維持可）
- RANGE_BOUND → confidence「中」を上限に

|------|-------------------|-------------------|
| WTI原油 | エネルギー・資源、商社 | 化学、運輸・航空、電力・ガス |
| 金 | 金鉱株ETF | （直接的な悪影響は限定的） |

### イールドカーブ分析

| スプレッド(10Y-3M) | 状態 | 東証への示唆 |
|-------------------|------|------------|
| > 1.0% | ノーマル | 景気拡大期待、銀行・金融セクターに追い風 |
| 0〜1.0% | フラット | 景気減速懸念、ディフェンシブセクター選好 |
| < 0% | 逆転 | 景気後退リスク上昇、グロース→バリューシフトに注意 |

### マクロレジーム分類

| レジーム | 条件 | 東証への示唆 |
|---------|------|------------|
| ゴルディロックス（適温） | 株↑・金利安定・原油安定・VIX低 | 全セクターに追い風。グロース優位 |
| 金融相場 | 株↑・金利↓・VIX低〜中 | グロース・小型株優位。REIT・不動産に追い風。金利水準>3.5%は「利下げ期待の買い」、≤3.5%は「金融緩和の深化」 |
| リフレ | 株↑・金利↑・原油↑・VIX低〜中 | シクリカル・バリュー優位。銀行・資源に追い風 |
| デフレ懸念 | 株↓・金利↓・原油↓・VIX↑ | ディフェンシブ・債券型ETFに退避 |
| スタグフレーション懸念 | 株↓・金利↑・原油↑・VIX↑ | 最も厳しい環境。全セクターに逆風 |

※ 複数の特徴が混在する場合は「混合」と記載。

## 高ボラモード・危機時ガードレール

### 高ボラモード（VIX > 30 or 日経前日比 > ±3%）

| 項目 | 通常時 | 高ボラモード時 |
|------|--------|-------------|
| difficulty | 判定に応じて1-5 | 最低4（★★★★）に引き上げ |
| シナリオレンジ幅 | CME基準 ± VIX×係数 | 通常の1.5倍に拡大 |
| レポート冒頭 | 通常のサマリー | サマリー直後に市場環境注記を挿入 |

### 危機モード（VIX > 35）

高ボラモードの全ルールに加え:
- confidence: 強制的に「低」
- 方向性判断: 「予測困難な環境」を総合判断に明記

### 反動シナリオルール

前日比±4%超の翌日AMでは、シナリオ分析に反動シナリオを必ず含める。

## 使用方法

```
/market-outlook-v2              # 時間帯自動判定（15:30前=am, 15:30以降=pm）
/market-outlook-v2 am           # AM: 今日の東証見通し
/market-outlook-v2 pm           # PM: 本日の結果・振り返り
/market-outlook-v2 portfolio    # 自動判定 + ポートフォリオモード
/market-outlook-v2 am portfolio # AM + ポートフォリオ
/market-outlook-v2 pm portfolio # PM + ポートフォリオ
```

- 引数順序は自由（`portfolio pm` も可）
- am/pm未指定時は現在時刻（JST）で自動判定（15:30が境界）
- 有効引数: `am`, `pm`, `portfolio`。不正引数は無視して警告出力
- `am pm` 同時指定: 自動判定にフォールバック

## 実行フロー（4段階）

```
1. モード判定（メイン）
   ├─ timing: 引数 or 現在時刻（15:30境界）
   ├─ mode: general / portfolio
   └─ パラメータ算出: date, prev_business_day, is_trading_day, year_month, current_time
        ↓
2. データ自動取得+バリデーション（メインがBash直接実行）
   ├─ market_data_quick.py [--pm] → JSON取得・変数保持
   ├─ market_outlook_context.py --json → 過去5日トレンド取得・変数保持
   └─ market_data_validate.py → バリデーション実行
        ├─ FAIL時: ユーザーに通知し続行可否確認
        └─ WARN時: 警告表示して続行
        ↓
3. 分析+ドラフト生成（サブエージェント: general-purpose x1）
   ├─ 指示書2ファイルを読ませる:
   │   ├─ market-data-collection-v2.md
   │   └─ output-formats-v2.md
   ├─ ステップ2で取得したJSON（market_data, context, validation結果）をパラメータとして渡す
   └─ SKILL.md自体はサブエージェントに渡さない（コンテキスト最適化）
        ↓
4. ファイル保存（メイン）
   └─ reports/market-outlook/YYYYMMDD_{am|pm}_v2.md
```

### ステップ2: データ自動取得コマンド

```bash
# 1. yfinanceデータ取得
# AM実行時
docker compose exec backend python scripts/market_data_quick.py
# PM実行時
docker compose exec backend python scripts/market_data_quick.py --pm

# 2. 過去5日トレンド取得
docker compose exec backend python scripts/market_outlook_context.py --json

# 3. バリデーション（パイプで実行）
# AM
docker compose exec backend python scripts/market_data_quick.py | docker compose exec -T backend python scripts/market_data_validate.py
# PM
docker compose exec backend python scripts/market_data_quick.py --pm | docker compose exec -T backend python scripts/market_data_validate.py
```

※ バリデーション結果がFAILの場合、index_rangeエラーが含まれていれば転記ミスの可能性が高い。
   market_data_quick.pyを再実行してJSONを再取得すること。

### ステップ3: サブエージェント起動プロンプト

```
以下の指示書を読み、構造化8ステップ分析に基づくドラフトを生成してください。

指示書: .claude/skills/market-outlook-v2/agent-instructions/market-data-collection-v2.md
出力フォーマット: .claude/skills/market-outlook-v2/agent-instructions/output-formats-v2.md

パラメータ:
- timing: {timing}
- mode: {mode}
- date: {date}
- prev_business_day: {prev_business_day}
- is_trading_day: {is_trading_day}
- year_month: {year_month}
- current_time: {current_time}

取得済みデータ:
※ 以下のJSONはステップ2でBash実行した結果をそのままコピー&ペーストすること。
※ 値の手動書き換え・要約・省略は禁止。転記ミス防止のため、必ず生のJSON出力全体を貼付すること。
- market_data: [ステップ2-1のJSON出力全体をそのまま貼付]
- context: [ステップ2-2のJSON出力全体をそのまま貼付。取得失敗時は「取得失敗」と記載]
- validation: [ステップ2-3のJSON出力全体をそのまま貼付]

タイムアウト: 600秒
```

レポート内の各数値に出典を記録: yfinance由来 `[yf]`、WebSearch/WebFetch由来はソース固有名タグ（`[bloomberg]`, `[nikkei]`等）。`[ws]`は使用禁止

## 禁止表現リスト

### 類型1: 断定・投資助言（RC3対応）
| 禁止パターン | 代替表現 |
|-------------|---------|
| 「必ず上がる」「確実に下落する」等の断定 | 「上昇が見込まれる」「下落圧力が強い」 |
| 「○○を買うべき」「売り推奨」等の売買指示 | 「注目テーマとして○○が挙げられる」 |
| 確率値の使用（「80%の確率で上昇」等） | 「データ整合性: 高/中/低」で表現 |
| 「暴落」「急騰」の安易な使用 | 具体的な数値で事実を記述 |
| 特定銘柄の目標株価提示 | テーマ・セクター単位での注目に留める |

### 類型2: データ性質の偽装（RC1対応）
| 禁止パターン | 代替表現 |
|-------------|---------|
| ETF代替データを指数名のみで表記 | ETFコード+名称+「指数代替」注記 |
| 「推定」値の混入（yfinance取得値に「推定」付与） | [yf]タグ付きで事実として記載 |

### 類型3: 情報ソースの偽装（RC2対応）
| 禁止パターン | 代替表現 |
|-------------|---------|
| 二次情報を一次情報として記載 | 「〜と報じた」「〜と解釈された」等の留保表現 |
| 推測を事実として記載 | 根拠明示+「〜の可能性がある」等の留保 |

### 類型4: 必須データの欠落（RC4対応）
| 禁止パターン | 代替表現 |
|-------------|---------|
| PM必須データ（売買代金・騰落銘柄数・業種別概況）の「データ不足」表記 | WebFetchフォールバック実施。不可時は「取得失敗」と明記 |

### 類型5: 低信頼度指標の過信（RC5対応）
| 禁止パターン | 代替表現 |
|-------------|---------|
| 一目均衡表の個別数値を主要判断根拠に使用 | 概要のみ（「雲の上/下」等の位置関係）で記載 |

**運用ルール**: 予想精度メタデータの蓄積は内部品質管理目的に限定。精度統計の外部公開・宣伝利用は禁止。

### 方向性表現
| 場面 | 推奨表現例 |
|------|-----------|
| 上昇見通し | 「上昇圧力が優勢」「買い優勢の展開が見込まれる」 |

### 確度表現
| 場面 | 推奨表現例 |
|------|-----------|
| 確度が高い | 「データ整合性が高い」「複数の指標が同方向を示している」 |

### 不確実性表現

|------|-----------|
| レンジが広い | 「通常より広めのレンジを想定」 |

## フォールバックルール

- portfolio取得失敗時 → 一般モードとして出力し、その旨を明記
- PM時セクター別データ不可 → セクション省略
- 注目ETF全フォールバック失敗 → セクション省略 + `<!-- etf_recommendation_unavailable -->`
- 非営業日 → PM出力の本日結果テーブルを省略

## ファイル保存ルール

- **AM保存先**: `reports/market-outlook/YYYYMMDD_am_v2.md`
- **PM保存先**: `reports/market-outlook/YYYYMMDD_pm_v2.md`
- **同一timing・同日のファイルが存在する場合**: 上書き
- **保存後**: ファイルパスをユーザーに通知
