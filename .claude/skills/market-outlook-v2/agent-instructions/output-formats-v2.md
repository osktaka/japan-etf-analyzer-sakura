# 出力フォーマット定義 v2

## 共通ルール

### 免責事項テンプレート

全レポートの冒頭（タイトル・更新日時の直後）に記載:

```
*本レポートはAIによる自動生成です。投資判断の参考情報であり、投資助言ではありません。*
```

### レポート利用ガイド

免責事項の直後に記載:

> **このレポートの使い方**
> - 本レポートはAIが公開データを分析した参考情報です
> - 個別銘柄の売買推奨ではありません。投資判断はご自身の責任で行ってください
> - 「見立て」→「位置づけ」→「監視ポイント」→「注目ETF」の順に読むと効率的です
> - 数値は取得時点のものです。最新値は各情報源で確認してください

### VIX記述ルール

VIX特定水準（20、25、30等）を分岐点として言及する場合、心理的節目であり理論的根拠はない旨を併記。

### メタデータ分割基準

- **構造化データ**（prediction等）= YAMLフロントマター（ファイル先頭）
- **運用フラグ**（sector_data_unavailable等）= HTMLコメント（本文末尾）

### ETF分類タクソノミー

| 分類 | 説明 |
|------|------|
| 指数連動 | 日経225/TOPIX/S&P500等のインデックス連動 |
| セクター | 特定業種・テーマに連動（半導体、銀行、IT等） |
| 防御 | ディフェンシブ目的（債券、金、低ボラティリティ等） |
| 反発確認 | 下落後のリバウンド局面で注目 |
| 継続確認 | トレンド継続の確認用 |
| 高配当 | 配当利回り重視 |
| REIT | 不動産投資信託 |
| 債券 | 国内外債券連動 |
| 金 | 金価格連動 |
| インバース | 指数の逆方向に連動（短期向き） |
| レバレッジ | 指数の倍率で連動（短期向き・値動き大） |

### ETF位置づけ

| 位置づけ | 説明 |
|---------|------|
| 反発狙い | 下落からのリバウンドを期待 |
| 継続狙い | 上昇トレンドの継続を期待 |
| 防御目的 | リスク回避・ポートフォリオ防御 |
| 市場全体の確認用 | 指数連動ETFで市場全体の方向性を確認 |
| セクター主導確認用 | 特定セクターの強弱を確認 |
| リスク回避確認用 | リスクオフ局面の度合いを確認 |

## 自己検証チェックリスト

### [A] 数値整合性（最優先）
- [ ] セクション1の結論とセクション2の指標テーブルが矛盾しない
- [ ] テクニカル値がmarket_data JSONの値と一致
- [ ] CME値がYAMLのcme_nikkeiと一致
- [ ] 為替レンジがドル円現在値を含む

### [B] YAML
- [ ] AM: 全13フィールドが存在し適切な値
- [ ] PM: 全7フィールドが存在し適切な値

### [C] セクション存在
- [ ] 9セクション全て存在
- [ ] AM: 監視ポイントがif-then-else形式（最低3つ）
- [ ] PM: 朝の見立てとの比較が含まれている（AMファイル存在時）

### [D] ソース品質
- [ ] 全ソースが当日または過去7営業日以内
- [ ] 汎用見通しレポートを当日ソースとして未使用

### [E] 分析の深さ
- [ ] 主因が1つに絞られている
- [ ] 位置づけが4カテゴリのいずれかで判定
- [ ] ETFに分類・位置づけ・有効/無効シナリオが付与
- [ ] クロスアセット環境にリスクアペタイト判定あり（AM）
- [ ] マクロレジームがクロスアセット内に記載（AM）
- [ ] テクニカルシグナル集計あり（取得成功時）
- [ ] 原油・金±2%超の場合、セクター分析に影響言及
- [ ] イールドカーブの状態と金融セクター示唆あり（AM）

### [F] YAML-本文整合性
- [ ] YAMLの `high_volatility: false` の場合、本文中に「高ボラティリティ」「不確実性が通常より高い」等の表現がないこと
- [ ] YAMLの `high_volatility: true` の場合、本文にその旨の記述があること
- [ ] YAMLの `crisis_mode: true` の場合、本文に「予測困難な環境」等の記述があること
- [ ] YAMLの `confidence` と本文の確度表現が一致していること（低→「データ整合性: 低」「不確実性が高い」等）
- [ ] YAMLの `risk_appetite` と本文のリスクアペタイト記述が一致していること
- [ ] YAMLの `macro_regime` と本文のマクロレジーム記述が一致していること

※ テクニカル・クロスアセットデータの取得失敗時は該当チェックをスキップ。

## ソースマッピングルール

### 出典タグ体系

本文中の出典タグは、末尾Sourcesセクションのエントリと1対1で対応させること:

| タグ | 用途 | 末尾Sources対応 |
|------|------|----------------|
| `[yf]` | yfinanceから取得した数値 | 「Yahoo Finance (yfinance)」として1行で記載 |
| `[bloomberg]` | Bloomberg記事から取得した情報 | 該当記事URLを記載 |
| `[nikkei]` | 日本経済新聞から取得した情報 | 該当記事URLを記載 |
| `[reuters]` | ロイター記事から取得した情報 | 該当記事URLを記載 |
| `[その他ソース名]` | 上記以外のソース | 該当URLを記載 |

### ルール
- `[ws]` は使用禁止。WebSearchで取得した情報には、実際の情報源名をタグとして使用すること
- 各Sourceに取得日を付記すること（例: `[2026-03-19取得]`）
- Sourcesに記載するURLは、実際にWebSearch/WebFetchで取得したものに限る
- Sourcesに記載がないソースを本文でタグ付きで引用してはならない
- 複数のソースから同じ情報を確認した場合は `[bloomberg][nikkei]` のように併記可

## 後方互換ルール

PM実行時のAMファイルパース順:
1. YAMLフロントマター（`---`で囲まれたブロック）
2. HTMLコメント形式（`<!-- prediction: ... -->`）からパース
3. どちらも不可: 「AM予想データの読み取りに失敗しました」と明記

新規作成レポートは常にYAMLフロントマター形式。
