# 予測ツリー生成指示書 v2

## 概要

中期見通し（3日→1週間→2週間）を予測ツリー方式で構造化する。3ラウンドの分岐・プルーニングを経て、最も現実的な予測パスを提示する。

## 前提パラメータ

- timing: `{timing}`（am / pm）
- date: `{date}`
- market_data: メインから渡されるJSON
- context: 過去5日トレンド
- forecast_tree_previous: 前回の予測ツリー（初回はなし）

---

## ドライバー軸の設計

### 固定軸1: 金融政策

| 項目 | 内容 |
|------|------|
| 対象 | FOMC/日銀の方向性、金利見通し、利下げ/利上げ期待 |
| データソース | yfinance（米10年債利回り、米3ヶ月債利回り）+ WebSearch |
| 分岐の切り口 | 次回会合の政策変更有無、市場の織り込み度合い |

### 固定軸2: テクニカル（週足パターン）

| 項目 | 内容 |
|------|------|
| 対象 | 週足RSI、25日/75日MA位置、サポート/レジスタンス水準 |
| データソース | yfinance（既存market_dataから算出） |
| 分岐の切り口 | MA上/下、RSI過熱/中立/売られ過ぎ、主要サポート維持/割れ |

### 自由軸（毎回選定）

| 項目 | 内容 |
|------|------|
| 候補 | 地政学リスク / 国内政策 / 需給動向 / セクターローテーション / 為替トレンド / 商品市場 |
| 選定基準 | 当日のWebSearch結果から最も市場インパクトが大きいテーマを1つ選択 |
| データソース | WebSearch |

**自由軸の選定ルール**:
- market_dataとWebSearch結果を照合し、直近で最も価格変動に寄与しているテーマを選ぶ
- 前回ツリーと同じ自由軸を連続選択してもよい（テーマ継続中の場合）
- 選定理由を1文で記録する

---

## 3ラウンド分岐・プルーニング手順

### ラウンド1: 3日後の分岐

各ドライバー軸について:
1. **分岐生成**: 2-3個の分岐シナリオを生成
   - 各分岐に「条件」「結果・日経影響」を明記
   - 条件は定量的に記述（例: 「ドル円が150円を割る」「VIXが25を超える」）
2. **プルーニング**: 以下の基準で不適切な分岐を除外
3. **残存分岐**: 各軸1-2個に絞る

### ラウンド2: 1週間後の展開

ラウンド1の残存分岐それぞれについて:
1. **展開生成**: 1-2個の展開シナリオを生成
2. **プルーニング**: 基準適用
3. **残存展開**: 各パスから1個に絞る

### ラウンド3: 2週間後の最終予測

ラウンド2の残存パスそれぞれについて:
1. **最終予測生成**: 日経平均の水準感と市場環境を記述
2. **プルーニング**: 基準適用
3. **最終パス選定**: 蓋然性順に3パス以内に絞る

---

## プルーニング基準

| 基準 | 定量条件 | 例 |
|------|---------|-----|
| 矛盾チェック | 残存分岐の前提と論理的に矛盾 | 利上げ+利下げが同時に残らない |
| 時間軸チェック | 設定期間内に実現不可能 | 法改正が3日では完了しない |
| データ整合性 | 現在のマクロレジーム・トレンドと矛盾 | UPTREND中に「急落継続」は低優先 |
| 前例チェック | 過去の予測課題で同パターンの失敗あり | prediction_issuesの類似事例参照 |

**切り捨て時の必須記録**: プルーニングで除外した分岐には必ず「復活条件」を1文で記録する。

復活条件の書式: `← プルーニング除外、復活条件: {具体的な条件}`

## 前回ツリーとの差分更新ルール（AM時）

前回の予測ツリー（`forecast_tree_previous`）が存在する場合:

1. **継続判定**: 前回の各分岐について、現在のmarket_dataで条件が維持されているか確認
2. **更新対象**:
   - 条件が変化した分岐 → 新しい分岐に置換
   - プルーニング除外の復活条件が成立した分岐 → 復活させてツリーに組み込む
   - 時間軸が進んだ分岐（3日後→現在） → 実績を記録し、次の時間軸に移行
3. **差分マーカー**: 更新された分岐には `[更新]`、新規分岐には `[新規]`、復活分岐には `[復活]` を付与
4. **自由軸の再選定**: テーマが継続中なら同じ軸を維持、新テーマが台頭していれば変更

## PM時の検証ルール

PM実行時は、3日前のAMツリーの「3日後」分岐を検証する。

### 検証手順

1. 3日前のAMレポートファイル（`reports/market-outlook/YYYYMMDD_am_v2.md`）のセクション10から予測ツリーを取得する（※ `forecast_tree_latest.md` は最新版で上書きされるため、3日前のツリーは残っていない）
2. 「3日後」に設定された各分岐の条件を、本日の実績データと照合
3. 各分岐について「実現/未実現/部分的実現」を判定
4. 結果をメタデータとして記録

### 検証結果の記録フォーマット

```markdown
## 予測ツリー検証（YYYY-MM-DD PM）

**検証対象**: YYYY-MM-DD AM起点のツリー → 3日後予測

| 軸 | 分岐ID | 予測条件 | 実績 | 判定 |
|----|--------|---------|------|------|
| 金融政策 | A | {条件} | {実績} | 実現/未実現/部分的 |
| テクニカル | C | {条件} | {実績} | 実現/未実現/部分的 |
| {自由軸} | E | {条件} | {実績} | 実現/未実現/部分的 |

**的中パターン**: {どの軸の予測が当たりやすいかの傾向を1文で}
```

## AM/PMでの役割分担

| タイミング | 予測ツリーの役割 |
|-----------|----------------|
| **AM** | 新規ツリー生成 or 前回ツリーの更新。当日のmarket_dataを反映して分岐を再評価 |
| **PM** | 3日前のAMツリーの短期予測を実績と照合。的中/外れを記録 |
| **holiday AM** | 前夜の米国データで分岐を更新（予測なしモードでもツリーは更新可） |

---

## 禁止事項

- 確率値（%）の使用 → 蓋然性の序列（最高/高/中/低）で表現
- 3軸以外のドライバーの追加（複雑性の抑制）
- プルーニング基準を無視した分岐の残存
- 復活条件なしでの分岐除外
- 前回ツリーを無視した完全再生成（差分更新が原則）

## 出力

完成した予測ツリーMarkdownを直接返却する。ファイル保存はメインエージェントが行う。
