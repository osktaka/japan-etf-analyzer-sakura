# X投稿実行スキル

```yaml
---
name: x-publish
description: tmp_x_posts_v2.mdの内容をXに投稿
user-invocable: true
allowed-tools: Read, Edit, Bash, Glob
aliases: ["/x-publish", "/xpub"]
---
```

## 概要

`reports/tmp_x_posts_v2.md` の投稿文をX（旧Twitter）に投稿する。
cron自動実行（`--auto`）・対話実行の両方に対応。

## 引数

| 引数 | 説明 | デフォルト |
|------|------|-----------|
| `--auto` | 確認なしで投稿（cron用） | なし（対話時はプレビュー確認） |
| `--production` | `[テスト]` タグを除去して投稿 | なし（テストタグ付き） |
| `--dry-run` | 投稿せずプレビューのみ表示 | なし（実投稿） |
| `--file <path>` | 投稿対象ファイルを明示指定（指定時は自動選択をスキップ） | なし（自動選択）|

**使用例**:
```
/x-publish                                                # 対話モード（プレビュー→確認→投稿）
/x-publish --dry-run                                      # プレビューのみ
/x-publish --auto                                         # cron用（テストタグ付き）
/x-publish --auto --production                            # cron本番用（テストタグ除去）
/x-publish --auto --production --file reports/tmp_x_posts_v2_1400.md  # cron用（対象ファイル明示）
```

## 中間ファイルフォーマット（入力契約）

`reports/tmp_x_posts_v2_HHMM.md` は `/market-x-draft` または `/market-intraday` スキルが生成する。
ファイル名のHHMMは実行時の日本時間（例: `tmp_x_posts_v2_0700.md`, `tmp_x_posts_v2_1200.md`）。
フォーマット仕様は `.claude/skills/market-x-draft/SKILL.md` の「出力フォーマット」セクションを参照。

パース方法:
- `## 投稿N` 見出しで各投稿を識別
- `---` で投稿を区切る
- 本文・ハッシュタグを抽出（AM/PMはタイトル行【...】付き、日中観察はタイトル行なし）

## 実行フロー

### Step 1: 投稿文読み込み

1. `--file` 指定時はそのパスを対象ファイルとする
2. 未指定時はBashで `ls -t reports/tmp_x_posts_v2_*.md 2>/dev/null | head -1` を実行し、mtime最新のファイルを対象とする
3. 対象ファイルをReadで読み込む
4. `## 投稿N` + `---` でパースし、投稿を抽出（AM/PM: 3投稿、日中観察: 1投稿）
5. ファイルが存在しない場合 → エラー通知して終了

### Step 1.5: 日付整合性チェック

対象ファイルの1行目が想定する日付と実行日（JST）が一致するか検証する。古いファイルの誤選択を防ぐ最終セーフティネット。

1. 対象ファイル1行目から正規表現 `\d{4}-\d{2}-\d{2}` で日付を抽出
2. Bashで `TZ=Asia/Tokyo date +%Y-%m-%d` を取得して比較
3. 判定:
   - 日付抽出失敗（フォーマット破損） → エラー終了
   - 日付不一致 → エラー終了（対象ファイルパス・期待日付・実日付をログに出力、投稿しない）
   - `--dry-run` 時も判定は実施し、不一致時はプレビュー前に停止

### Step 2: プレビュー・確認

**対話モード（デフォルト）**:
- 3投稿のプレビューを表示
- `--production` 指定時は `[テスト]` 除去後のテキストを表示
- ユーザーの確認を待つ（投稿/キャンセル/編集）

**`--auto` モード**:
- プレビュー・確認をスキップ

**`--dry-run` モード**:
- プレビューのみ表示して終了

### Step 3: X投稿実行（リトライ付き）

各投稿について以下を順次実行（**最大3回リトライ、それでも失敗ならスキップ**）:

1. `--production` 指定時: テキストから `[テスト]` を除去
2. `docker compose exec backend python scripts/x_post.py --text "投稿テキスト"` をBash実行
3. JSON結果を確認し、`success: false` の場合はエラー種別に応じて対処:

#### リトライ判定表

| エラー種別 | JSON内の手がかり | 対処 | リトライ |
|-----------|-----------------|------|---------|
| 文字数超過 | `"X count ... exceeds limit"` | 投稿文を短縮して再投稿（情報を絞り込む、修飾語を削る、ハッシュタグを減らす） | ○ |
| レート制限 | `"Too Many Requests"` / `429` | 60秒待機して再投稿 | ○ |
| 重複投稿 | `"duplicate"` | **スキップ**（同じ内容が既に投稿済みのため再投稿しない）| × |
| 認証エラー | `401` / `403` | **全投稿中止**（リトライしても無意味） | × |
| その他 | 上記以外 | 30秒待機して再投稿 | ○ |

#### リトライフロー

```
投稿実行 → 成功？ → Yes → 次の投稿へ
                  → No  → リトライ回数 < 3？
                           → Yes → エラー対処 → 再投稿
                           → No  → この投稿をスキップ → 次の投稿へ
```

4. **投稿間隔: 90秒**（sleep 90）で次の投稿を実行（Bashタイムアウト: 180秒指定）
5. 最終結果に各投稿の成功/失敗/リトライ回数を報告

### Step 4: 履歴更新

投稿成功した投稿を `.claude/x-posts-history.md` に追記:

タイプは中間ファイルのヘッダー行から取得する:
- `# X投稿 YYYY-MM-DD AM（3投稿構成）` → AM
- `# X投稿 YYYY-MM-DD PM（3投稿構成）` → PM
- `# X投稿 YYYY-MM-DD 日中観察（1投稿構成）` → 日中観察
- `# X投稿 YYYY-MM-DD 米国プレマーケット（1投稿構成）` → 米国プレマーケット
- `# X投稿 YYYY-MM-DD 米国観察（1投稿構成）` → 米国観察

投稿数は中間ファイルの内容に応じて可変（AM/PM: 3投稿、日中観察/米国プレマーケット/米国観察: 1投稿）。

```markdown
### YYYY-MM-DD（マーケット速報 {タイプ}）

- パターン: マーケット速報型
- 投稿1:
（投稿1全文）
```

## エラーハンドリング

| エラー | 対応 |
|--------|------|
| 投稿ファイル未存在 | エラー通知して終了 |
| API認証エラー（401/403） | **全投稿中止**、認証情報の確認を促す |
| 文字数超過 | 投稿文を短縮して最大3回リトライ |
| レート制限（429） | 60秒待機して最大3回リトライ |
| 重複投稿 | **スキップ**（同じ内容が既に投稿済みのため再投稿しない） |
| その他のAPIエラー | 30秒待機して最大3回リトライ |
| 3回リトライ後も失敗 | その投稿をスキップして次へ進む |
| Docker未起動 | エラー通知して終了 |

最終結果に成功/失敗/スキップの内訳とリトライ回数を報告する。
