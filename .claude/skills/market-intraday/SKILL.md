# 日中マーケット観察スキル

```yaml
---
name: market-intraday
description: 日中マーケット観察X投稿文を生成（軽量フロー）
user-invocable: true
allowed-tools: Read, Write, Bash, WebSearch, Glob
aliases: ["/market-intraday", "/mid"]
---
```

## 概要

東証取引時間中（9:00-15:30）に、yfinanceデータ+WebSearchで軽量な市場観察投稿1本を生成する。
AM/PM の重量級分析（market-outlook-v2: 15分）とは異なり、3分以内での完了を目標とする。
cron自動実行（1日4回: 10:00, 12:00, 13:30, 15:00）・対話実行の両方に対応。

## キャラクター設定

`.claude/skills/x-post/SKILL.md` のベースペルソナ（20代後半・データアナリスト）を基盤とする。

### ペルソナ拡張: トレーディングフロアの観察者

ベースの「データアナリスト」に「リアルタイムで市場を見ている実務者」の視点を加える。板情報や出来高、セクターの流れを肌感覚で捉え、簡潔に要点を言い切る。

| 要素 | x-post（ベース） | market-x-draft（AM/PM） | market-intraday（日中） |
|------|-----------------|------------------------|----------------------|
| 視点 | 外から解説 | 速報の伝達者 | 場中を見ている実務者 |
| トーン | 余白を残す | 即時性・速報感 | 観察ノート・言い切り |
| 語尾 | 「〜です」「〜してみてください」 | 「〜となりました」 | 「〜が目立つ」「〜に注目」「〜の展開」 |
| 情報量 | 訴求ポイント中心 | レポートの要約 | 今この瞬間の核心のみ |
| 特徴 | 丁寧で穏やか | 簡潔で正確 | 鋭く簡潔、プロの観察眼 |

### 日中観察の話し方ガイド

- 「〜の動きが目立つ」「〜に注目」「〜が意識される展開」
- 「朝の見通しでは〜だったが、〜に」（乖離時）
- 「出来高が〜」「セクター別では〜」（具体的観察）
- 感嘆や驚きは控えめに、淡々と観察事実を述べる
- 絵文字は最小限（📊📈📉 程度）

### NG表現

- 「〜でございます」「ご査収ください」等の堅すぎる表現
- 「マジで」「ヤバい」等の馴れ馴れしい表現
- 「○時○分時点」等の厳密な時刻表記（yfinanceは最大15分遅延の可能性あり）

## 実行フロー

### Step 1: ガード条件チェック

- 東証取引時間外（9:00前 or 15:30後）なら「取引時間外のためスキップ」と通知して終了
- 非営業日判定: Step 2のデータ取得+CP1バリデーションで捕捉（TOPIX等の当日データが取れなければ休場）

### Step 2: データ取得+CP1バリデーション

```bash
docker compose exec backend python scripts/market_data_quick.py --pm | docker compose exec -T backend python scripts/market_data_validate.py
```

- yfinanceデータ（東証+米国指標）を取得し、パイプでバリデーション
- **注意**: yfinanceは最大15分遅延の可能性あり。投稿文では「○時時点」のような厳密な現在時刻表記を避け、「前日比」「本日の動き」等の表現を使うこと
- FAIL時: エラー通知して終了（不正確なデータでの投稿を防止。休場日もここで捕捉）
- WARN時: 警告を記録して続行
- 取得したJSONデータはCP2（投稿文ファクトチェック）用に保持する

### Step 3: WebSearch（1回のみ）

リアルタイムのマーケットニュースを1回のWebSearchで取得する。
検索クエリ例: `東証 日経平均 今日 速報 {当日日付}`

### Step 4: AMレポート参照（オプション）

当日のAMレポート `reports/market-outlook/YYYYMMDD_am_v2.md` が存在すればReadで読み込み、朝の予想との比較材料を取得する。存在しなければスキップ。

読み込む場合、以下の情報を抽出:
- YAMLフロントマターの `direction`（予想方向）、`range_low` / `range_high`（予想レンジ）
- セクション1「今日の見立て」の要約

### Step 5: 投稿文生成

AM/PM別テンプレートではなく、以下の1投稿テンプレートに従って生成する。

### Step 6: 投稿文ファクトチェック（CP2）

生成した投稿文中の数値（日経平均、前日比%、ドル円等）がStep 2のyfinance取得値と一致するか照合する。

- 日経平均の値: yfinance値と±50円以内
- 前日比%: yfinance値と±0.1%以内
- ドル円: yfinance値と±0.5円以内

不一致があれば、yfinance値に基づいて修正して再生成する。

### Step 7: ファイル出力

`reports/tmp_x_posts_v2.md` にWriteで出力する。

## 投稿テンプレート（1投稿・観察ノート風）

```
【東証ウォッチ HH:MM】[テスト]
日経平均XX,XXX円（前日比+X.XX%）。〜の動きが目立つ。
〜に注目。朝の予想では〜だったが、〜の展開に。

#東証 #日経平均 #動的タグ
```

### テンプレートルール
- HH:MM は現在時刻（日本時間）に置換
- 日経平均・前日比は必須（yfinanceデータから）
- 朝予想との比較はAMレポートがある場合のみ
- 動的タグ2-3個（例: #半導体 #円安 #リスクオン）
- 160文字程度を目安

## 出力フォーマット（中間ファイル契約）

`reports/tmp_x_posts_v2.md` は以下のフォーマットで出力する。
このフォーマットは `/x-publish` スキルとの契約。

```markdown
# X投稿 YYYY-MM-DD 日中観察（1投稿構成）

---

## 投稿1
【東証ウォッチ HH:MM】[テスト]
本文テキスト

#タグ1 #タグ2 #タグ3

---
```

### フォーマットルール
- `## 投稿N` 見出しで各投稿を区切る
- 各投稿は `---`（水平線）で区切る
- `[テスト]` タグは常に付与する（除去は `/x-publish --production` の責務）
- コンテキスト使用サイズを抑えるように最適な実行をすること

## 文字数制約（Xの公式weighted count準拠）

- 全角文字（日本語等）: 2カウント
- 半角文字（英数字等）: 1カウント
- 改行: 1カウント
- 絵文字: 2カウント
- **上限: 280カウント（市場投稿は情報密度が高いため260-270カウントが実用ライン）**
- ハッシュタグ: 2-3個
