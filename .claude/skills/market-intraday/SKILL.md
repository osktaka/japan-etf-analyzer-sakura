# 場中マーケット観察スキル

```yaml
---
name: market-intraday
description: 場中マーケット観察X投稿文を生成（東証/米国自動判定・軽量フロー）
user-invocable: true
allowed-tools: Read, Write, Bash, WebSearch, Glob
aliases: ["/market-intraday", "/mid"]
---
```

## 概要

東証または米国市場の取引時間中に、yfinanceデータ+WebSearchで軽量な市場観察投稿1本を生成する。
AM/PM の重量級分析（market-outlook-v2: 15分）とは異なり、3分以内での完了を目標とする。

### 対応市場とスケジュール

| 市場 | 取引時間(JST) | cron実行時刻 | 回数 |
|------|-------------|-------------|------|
| 東証 | 9:00-15:30 | 9:30, 10:30, 12:00, 13:00, 14:00, 15:00 | 6回 |
| 米国 | 23:30-6:00 (冬) / 22:30-5:00 (夏) | 22:00, 0:00, 3:00 | 3回 |

## キャラクター設定

`.claude/skills/x-post/SKILL.md` のベースペルソナ（20代後半・データアナリスト）を基盤とする。

### ペルソナ拡張: トレーディングフロアの観察者

ベースの「データアナリスト」に「リアルタイムで市場を見ている実務者」の視点を加える。板情報や出来高、セクターの流れを肌感覚で捉え、簡潔に要点を言い切る。

| 要素 | x-post（ベース） | market-x-draft（AM/PM） | market-intraday（場中） |
|------|-----------------|------------------------|----------------------|
| 視点 | 外から解説 | 速報の伝達者 | 場中を見ている実務者 |
| トーン | 余白を残す | 即時性・速報感 | 観察ノート・言い切り |
| 語尾 | 「〜です」「〜してみてください」 | 「〜となりました」 | 「〜が目立つ」「〜に注目」「〜の展開」 |
| 情報量 | 訴求ポイント中心 | レポートの要約 | 今この瞬間の核心のみ |
| 特徴 | 丁寧で穏やか | 簡潔で正確 | 鋭く簡潔、プロの観察眼 |

### 話し方ガイド（カテゴリ別バリエーション）

**語尾**:「〜が目立つ」「〜で推移」「〜に転じた」「〜を試す展開」「〜が意識される」
**接続**:「序盤の流れが一変」「前場とは景色が違う」「じわじわと〜」「一服感が漂う」「潮目が変わり〜」
**観察**:「出来高を伴って〜」「セクター間の温度差」「方向感に乏しい」「需給が引き締まり〜」「物色の矛先が〜に」
- 感嘆や驚きは控えめに、淡々と観察事実を述べる
- 絵文字は1-2個をアイコン的に使用（📊📈📉⬆️⬇️↗️↘️➡️ 程度。行頭に置くと視認性UP）

**リズム**: 文の長さに緩急をつける。全ての文が同じ長さにならないこと。
- 短・長: 「売り加速。日経53,200円、高値から800円幅の下落で〜」
- 長・短: 「円安159円台の追い風にもかかわらず買い手は現れず。地合い弱い。」
- 短・長・短: 「後場反転。53,500円割れで一気に売り優勢に。買い材料なし。」
体言止め・短文を積極的に織り交ぜる。句読点で区切る文は2-4文。

### NG表現

- 「〜でございます」「ご査収ください」等の堅すぎる表現
- 「マジで」「ヤバい」等の馴れ馴れしい表現
- 「○時○分時点」等の厳密な時刻表記（yfinanceは最大15分遅延の可能性あり）

## 実行フロー

### Step 1: 市場モード判定

現在の日本時間から対象市場を自動判定する:

| 時刻(JST) | モード | サブモード | 対象市場 |
|-----------|--------|-----------|---------|
| 9:00〜15:30 | `tokyo` | - | 東証 |
| 22:00〜22:59 | `us` | `preview` | 米国（開場前プレビュー） |
| 23:00〜6:00 | `us` | - | 米国（取引中実況） |
| それ以外 | `skip` | - | 「市場取引時間外のためスキップ」と通知して終了 |

判定ロジック: 現在時刻が22:00台（22:00〜22:59）なら`preview`サブモード、それ以外のus時間帯なら通常`us`。
夏時間の確認: 22:00 JST = 09:00 EDT（夏）/ 08:00 EST（冬）。米国市場開場は09:30 ET。両季節ともプレマーケット時間帯。

非営業日判定: Step 2のデータ取得+CP1バリデーションで捕捉。

### Step 2: データ取得+CP1バリデーション

**東証モード**:
```bash
docker compose exec backend python scripts/market_data_quick.py --pm | docker compose exec -T backend python scripts/market_data_validate.py
```

**米国モード**:
```bash
docker compose exec backend python scripts/market_data_quick.py | docker compose exec -T backend python scripts/market_data_validate.py
```

**米国プレマーケットモード**（サブモード `preview`、22:00 JST）:
```bash
docker compose exec backend python scripts/market_data_quick.py --pre-us | docker compose exec -T backend python scripts/market_data_validate.py
```

22:00では `--pre-us` フラグにより米国先物（ES=F, NQ=F）+東証終値（^N225）を追加取得する。
S&P500/NASDAQ現物は前日終値のため、先物の前日比で方向感を判断すること。

- **注意**: yfinanceは最大15分遅延の可能性あり。投稿文では「○時時点」のような厳密な現在時刻表記を避け、「前日比」「本日の動き」等の表現を使うこと
- FAIL時: エラー通知して終了（不正確なデータでの投稿を防止。休場日もここで捕捉）
- WARN時: 警告を記録して続行
- 取得したJSONデータはCP2（投稿文ファクトチェック）用に保持する

### Step 3: WebSearch（1回のみ）

**東証モード**: `東証 日経平均 今日 速報 {当日日付}`
**米国モード**: `US stock market today S&P500 {当日日付}` または `米国株 今夜 速報 {当日日付}`

### Step 4: レポート参照（オプション）

**東証モード**: 当日AMレポート `reports/market-outlook/YYYYMMDD_am_v2.md` があればReadで朝予想との比較材料を取得（direction, range_low, range_high, セクション1要約）
**米国モード**: 当日PMレポート `reports/market-outlook/YYYYMMDD_pm_v2.md` があればReadで夕方の見通しとの比較材料を取得

存在しなければスキップ。

### Step 4.5: 当日投稿コンテキスト取得（連続性の核）

前回までの投稿を読み込み、ストーリーの連続性を確保する。

1. Globで `reports/tmp_x_posts_v2_*.md` を検索（更新日時順）
2. 各ファイルのヘッダー行 `# X投稿 YYYY-MM-DD ...` から日付を抽出
3. 参照対象を決定:
   - **東証モード**: 当日日付のファイルのうち、自分のHHMMより前のもの全て
   - **米国プレマーケット（22:00）**: 当日日付のファイル（東証9:30〜15:00の投稿）。前日日付は不要（前夜の米国アークとは別ストーリー）
   - **米国モード（0:00/3:00）**: 当日日付のファイル + 前日日付のファイル。日付をまたぐため、前日22:00のプレマーケット投稿が含まれる
4. 投稿本文 **および `<!-- snapshot: ... -->` メタデータ**を抽出しStep 5に渡す
5. **直前の投稿1件を重点参照**し、それ以前は要約的に参照する。「直前」は更新日時順で直近のファイルとする（ファイル名HHMMではなく実際の時系列で判定）
   - 22:00の直前 → 東証15:00の投稿（同日）
   - 0:00の直前 → 前日22:00のプレマーケット投稿
   - 3:00の直前 → 当日0:00の投稿
6. **メタデータの数値と現在値を比較**し、日中の軌跡（高値→調整→戻り等）を正確に把握する
   - 例: 10:00に54,000円 → 12:00に53,616円 → 現在53,737円 の場合、「加速」ではなく「高値圏からの調整後、後場で持ち直し」が正確

**前回投稿が0件の場合**: 連続性指示をスキップし、通常の独立投稿として生成する。

### Step 5: 投稿文生成（連続性ルール適用）

モードに応じたテンプレートで1投稿を生成する。
前回投稿コンテキストがある場合は、以下のストーリーアークと連続性ルールを適用する。

#### ワンメッセージ原則

1投稿 = 1つの核心メッセージ + 日経数値（必須）+ 補足最大1つ。

核心メッセージの決め方:
1. Step 2のデータから「今、最も動きが大きい事実」を1つ選ぶ（=核心）
2. その事実に「なぜ？」「だから何？」を1文で添える
3. 日経平均の数値・前日比は常に含める（信頼性担保）
4. 補足指標は最大1つ。合計で核心+日経+補足1 = 最大3要素まで

#### 東証ストーリーアーク

| 時刻 | 役割 | 物語上の位置 | 接続パターン例 |
|------|------|-------------|---------------|
| AM投稿 | 今日の予想提示 | 起（設定） | 「今日は〜の展開を予想」 |
| 9:30 | 寄付き直後の初動 | 承（展開） | 「朝は〜としたが、寄付きは〜」 |
| 10:30 | 前場中盤 | 承（深化） | 「序盤の〜から、〜の動きに変化」 |
| 12:00 | 前場の総括 | 転（変化） | 「午前中は〜で推移、〜が意外な動き」 |
| 13:00 | 後場寄付き直後 | 転（深化） | 「昼休みを挟んで〜、午前の流れが〜」 |
| 14:00 | 後場中盤 | 転（収束） | 「後場に入り〜、方向感が〜」 |
| 15:00 | 引け前の総括 | 結（結末） | 「結局〜で着地。朝の予想は〜」 |

#### 米国ストーリーアーク

| 時刻 | 役割 | 物語上の位置 | 接続パターン例 |
|------|------|-------------|---------------|
| PM投稿 | 夕方の見通し | 前提（外部参照） | （market-outlook-v2の投稿、存在すれば参照） |
| 22:00 | 今夜のプレビュー | 起（設定） | 「東証は〜で引け、今夜は〜に注目」 |
| 0:00 | 序盤の実況 | 承（展開） | 「プレマーケットでは〜だったが、開場後は〜」 |
| 3:00 | 中盤の観察 | 結（中間結果） | 「序盤の〜から一転し〜」 |

#### 連続性ルール（7つ）

1. **接続表現は1文（15-25文字）に収める**:「朝は弱気としたが一転、」程度。連続性の表現に投稿全体の1/4以上を使わない
2. **朝予想との対比は1日2回まで**。それ以外は以下の接続バリエーションで繋ぐ:
   - 数値差分:「前場から+300円」「午前の上昇幅を維持」
   - セクター変化:「午前は銀行主導だったが、後場はハイテクに物色移行」
   - 時間帯の特徴:「後場に入り出来高が細り〜」「引け前の駆け込み買いで〜」
3. 同じ数値の繰り返しを避け、変化量で語ること
4. ストーリーアークの自分の役割を意識すること
5. **前回と同じアーキタイプの繰り返しを禁止**。アーキタイプ表を参照し、前回と異なる型を選択する
6. **冒頭の書き出しが前回と同じ** → アーキタイプを変更する
7. **投稿内で同じ語尾が2回以上出現**（例: 「〜展開。〜展開。」）→ 語尾を差し替える

#### 視点ローテーション（東証モード）

日経平均は毎回必須だが、**2番目に言及する指標はその時刻で最も変化が大きい・興味深いものを選択**する。固定しないこと。

| 時刻 | 推奨フォーカス |
|------|---------------|
| 9:30 | 寄付き初動・前日海外の影響・為替 |
| 10:30 | セクター別強弱・出来高の質 |
| 12:00 | 前場の勝者と敗者・意外な動き |
| 13:00 | 後場の方向感・REIT/グロースの動向 |
| 14:00 | 引けに向けた需給・出来高トレンド |
| 15:00 | 一日の総括・セクターローテーション |

取得済み指標: グロース250、銀行、REIT(1343.T)、情報通信(1626.T)、TOPIX(1306.T)、為替、出来高分析。
推奨フォーカスは目安であり、**データ上で最も動きがある指標を優先**する。

#### 例外: 市場急変時

VIX急騰（前回投稿時から+3以上）や日経平均が前回から±500円以上変動した場合は、ストーリーアークを中断して**速報優先**で投稿する。ただし「午前中は穏やかだったが急転、」のように前回との対比は維持する。

### Step 6: 投稿文ファクトチェック（CP2）

生成した投稿文中の数値がStep 2のyfinance取得値と一致するか照合する。

**東証モード**:
- 日経平均: ±50円以内
- 前日比%: ±0.1%以内
- ドル円: ±0.5円以内

**米国モード**:
- S&P500: ±5pt以内
- 前日比%: ±0.1%以内
- VIX: ±0.5以内

**米国プレマーケットモード**:
- 日経平均: ±50円以内
- S&P500先物: ±5pt以内
- 前日比%: ±0.1%以内
- VIX: ±0.5以内

不一致があれば、yfinance値に基づいて修正して再生成する。

**Xカウントチェック**（CP2の一部）:
投稿文のXカウント（全角2/半角1/改行1/URL23/絵文字2）が280以内であることを確認する。
超過している場合は情報を絞り込んで再生成する。目安は260-270カウント。
確認コマンド: `docker compose exec backend python scripts/x_post.py --dry-run --text "投稿文"` でx_countフィールドを確認。

### Step 7: ファイル出力

`reports/tmp_x_posts_v2_HHMM.md`（HHMMは実行時の日本時間）にWriteで出力する。

**任意実行時（`--now`）**: プロンプトに「tmp_x_posts_v2_now.md」の指示がある場合はそのファイル名を使う。これにより任意実行のファイルは常に上書きされ、余計なファイルが蓄積しない。

## 投稿テンプレート

**毎回異なるアーキタイプを選択すること。前回投稿と同じアーキタイプの連続使用は禁止。**
Step 4.5で取得した直前投稿の構造を確認し、異なるアーキタイプを選ぶ。
各アーキタイプの「例」は全文サンプルであり、冒頭だけでなく「フック→展開→締め」の3要素を示している。

### 東証モード（5アーキタイプから選択）

各アーキタイプは「フック→展開→締め」の投稿全体構造を定義する。冒頭だけでなく投稿全体の流れが変わる。

| 型 | 構造 | 効果 | 例 |
|----|------|------|-----|
| 速報型 | 事実（短文）。解釈（1文）。 | 速報感・信頼性 | 「売り加速。日経53,200円、高値から800円幅の下落。出来高急増が示す機関の手仕舞い。」 |
| 発見型 | 意外な事実 → 背景 → 示唆 | 知的好奇心 | 「円安159円台なのに買い手不在。日経53,658円、昨日の大幅高の利確が重い。為替の追い風だけでは支えきれない地合い。」 |
| 対比型 | A vs B → だから何 | 構造的理解 | 「大型堅調、小型壊滅。日経-0.2%の裏でグロース250は-3%超。資金の行き先が二極化している。」 |
| 転換型 | 前→後の変化 → 意味 | ストーリー性 | 「朝の楽観が午後に試される。54,000円台を維持できず53,500円割れ、後場は売り優勢に転換。」 |
| 俯瞰型 | 全体観 → 核心の一言 | プロ感・余韻 | 「日経53,297円で着地。終日右肩下がり、+1,500円の反発は一日で帳消しに近い。明日の海外勢の反応が焦点。」 |

### 米国プレマーケットモード（3アーキタイプから選択）

| 型 | 構造 | 例 |
|----|------|-----|
| 橋渡し型 | 東証結果→今夜の焦点 | 「東証は日経53,600円で引け。S&P先物+0.3%、今夜はPCE発表に注目。」 |
| 先物型 | 先物の動き→背景 | 「S&P先物じわり上昇。東証の反発を引き継ぎ、リスクオンの流れ。」 |
| イベント型 | 注目材料→市場の構え | 「今夜はFOMC。S&P先物は様子見、東証53,600円の勢いを持ち越せるか。」 |

#### プレマーケットモード固有ルール
- 前半で東証の結果を1文でまとめ、後半で今夜の注目点を提示
- S&P500は**先物（ES=F）の値**を使用する（現物は前日終値で情報価値が低い）
- 「予想」「見通し」ではなく「注目」「焦点」等の表現を使う（投資助言回避）
- WebSearchで今夜の米国イベント（経済指標発表、決算等）を確認し、あれば言及

### 米国モード（3アーキタイプから選択）

| 型 | 構造 | 例 |
|----|------|-----|
| 速報型 | 事実（短文）→解釈 | 「S&P反発。5,500回復、テック主導で+1.2%。VIX20割れが示す安心感。」 |
| テーマ型 | 材料→影響→示唆 | 「FOMC議事要旨でタカ派色。S&P5,480(-0.5%)、金利上昇が重荷。」 |
| 俯瞰型 | 全体観→核心 | 「S&P5,520で折り返し。序盤の買いが続かず、引けにかけて失速。」 |

### テンプレートルール
- `[テスト]` で始め、続けて本文を記載する（タイトル行なし）
- 主要指数・前日比は必須（yfinanceデータから）
- レポート参照がある場合のみ予想との比較を含める
- 動的タグ2個推奨（最大3個）
- **140-160文字（240-270カウント）を目標**。余裕があれば補足情報（セクター動向、為替等）を追加する

## 出力フォーマット（中間ファイル契約）

`reports/tmp_x_posts_v2_HHMM.md` は以下のフォーマットで出力する。
このフォーマットは `/x-publish` スキルとの契約。

### 東証モード
```markdown
# X投稿 YYYY-MM-DD HH:MM 日中観察（1投稿構成）

<!-- snapshot: nikkei=XXXXX, topix=XXXX, usdjpy=XXX.X, bank=+X.XX%, growth=+X.XX% -->

---

## 投稿1
[テスト] 本文テキスト
#タグ1 #タグ2 #タグ3

---
```

### 米国プレマーケットモード
```markdown
# X投稿 YYYY-MM-DD HH:MM 米国プレマーケット（1投稿構成）

<!-- snapshot: nikkei=XXXXX, sp500_futures=XXXX, nasdaq_futures=XXXXX, vix=XX.X, usdjpy=XXX.X -->

---

## 投稿1
[テスト] 本文テキスト
#タグ1 #タグ2 #タグ3

---
```

### 米国モード
```markdown
# X投稿 YYYY-MM-DD HH:MM 米国観察（1投稿構成）

<!-- snapshot: sp500=XXXX, nasdaq=XXXXX, vix=XX.X, us10y=X.XX, usdjpy=XXX.X -->

---

## 投稿1
[テスト] 本文テキスト
#タグ1 #タグ2 #タグ3

---
```

### フォーマットルール
- `## 投稿N` 見出しで各投稿を区切る
- 各投稿は `---`（水平線）で区切る
- `[テスト]` タグは常に付与する（除去は `/x-publish --production` の責務）
- **`<!-- snapshot: ... -->` にyfinance主要数値を記録する**（次回投稿時の軌跡把握用。HTMLコメントのためX投稿やMarkdown表示に影響しない）

### エンゲージメント向上ガイドライン（柔軟に適用）

以下は投稿の質を高めるための推奨指針。全てを毎回適用する必要はなく、投稿の内容・文脈に応じて自然に使い分ける。

- **フック**: 冒頭に具体的な数字（+1.2%等）やキーワードで引きを作る（タイトル行なし設計のため【括弧】は使わない）
- **空行で段落分離**: 意味の区切りに空行を入れ、タイムラインでの視認性を高める
- **数字は具体的に**: ±記号付き（+0.98%）、カンマ区切り（38,500円）で信頼感と即読性を両立
- **ハッシュタグ**: 2個推奨。末尾にまとめて配置
- **市場方向性の矢印**: 主要指数の前日比の後ろに矢印を付与。±1%以上で⬆️⬇️、±0.3%超〜±1%未満で↗️↘️、±0.3%以内で➡️（例: （+1.2%）⬆️、（-0.3%）↘️）
