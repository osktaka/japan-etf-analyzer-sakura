# Phase 2: マージ分析会議 指示書

## 前提

- 作業ディレクトリ: `{WORK_DIR}`（メインエージェントから渡される）
- Docker内パス: `/app/{WORK_DIR}`
- スキルディレクトリ: `{skill_dir}`（メインエージェントから渡される）

## データ受け渡しルール

- **入力**: `{WORK_DIR}/` 配下の会議結果ファイル + 定量データ
- **出力**: `{WORK_DIR}/20_merge_meeting.md`
- **メインへの戻り値**: ファイルパスと文字数のみ。会議内容は一切返さないこと

## スキップ判断基準

このフェーズにスキップ条件はない。常に実行する。

---

## 目的

3つの独立したブレインストーミング会議の結果を統合し、矛盾を解消し、最終的な分析結論を導出する。

## 入力ファイル

| ファイル | 内容 |
|---------|------|
| `{WORK_DIR}/10_meeting_1.md` | リスク・リターン効率会議 |
| `{WORK_DIR}/10_meeting_2.md` | 分散・アロケーション会議 |
| `{WORK_DIR}/10_meeting_3.md` | 銘柄品質・入替判断会議 |
| `{WORK_DIR}/05_shared_calculations.md` | 定量データ参照用 |
| `{WORK_DIR}/0a_market_environment.md` | 市場環境（存在する場合） |

## マージ会議のキャラクター（固定ロール）

テーマに応じて名前・専門をサブエージェントが自律生成する。ロールのみ固定:

- **天才（統合アナリスト）**: 3会議を横断分析し、共通パターン・構造的洞察を抽出。「つまり3つの会議が示しているのは...」
- **初心者（素朴な読者）**: 3会議間の矛盾に素朴な疑問を投げかける。「会議1と会議3で正反対のことを言ってますが...」
- **ポジティブ（シナジー発見者）**: 各会議のベストアイデアを組み合わせて新提案。「会議2のあのアイデアと会議1のこれを組み合わせたら...」
- **心配性（盲点発見者）**: 全会議で見落とされたリスクを指摘。「3つの会議全部で誰も言ってないんですが...」

## マージ会議の進行構造

以下の流れで自然に進行させる（明示的なフェーズ分けは出力に含めない。あくまで内部ガイド）:

1. **概観**（約2,000字）: 天才が3会議の全体像を俯瞰的に整理。初心者が「3つの会議で言ってることが違うのは何で？」と核心的疑問。各キャラが担当する論点を宣言
2. **矛盾の解消**（約3,000字）: 3会議間で矛盾する結論を取り上げ、なぜ矛盾が生まれたかを分析。どちらの前提が妥当かを議論
3. **シナジー発見**（約3,000字）: 各会議の独自アイデアを組み合わせ、単独会議では出なかった新しいアイデアを生成
4. **盲点の補完**（約2,000字）: 3会議全てで触れられなかった観点を心配性が指摘。天才がその重要性を評価
5. **収束**（約2,000字）: 統合的結論の導出。アクション優先度の合意形成

## キャラ演じ分けの指針

- **天才（統合アナリスト）**: 抽象と具体を行き来。3会議の構造的パターンを見出す。「みんなが見落としているのは、3つの会議全てに共通する前提が...」「つまり本質的には...」。論理的だが決して冷たくない
- **初心者（素朴な読者）**: 3つの会議を「普通の人」の目で読んだ感想。「すみません、会議1と2で全然違うこと言ってるんですが、どっちが正しいんですか？」「素人考えですが...」。純粋な疑問が議論を深める触媒
- **ポジティブ（シナジー発見者）**: 異なる会議のアイデアを組み合わせる。「会議2のあの視点と会議3のこのアイデア、合わせたら面白くないですか？」「ワクワクしませんか？」。楽観的だが根拠のある楽観主義
- **心配性（盲点発見者）**: 全会議で抜け落ちた視点を指摘。「3つの会議全部で誰も言ってないんですが...」「最悪の場合...」。慎重だが建設的（必ず対策案も述べる）

## 会議ルール（厳守）

1. **深掘りか横展開のみ**: 同意のみの発言は禁止。必ず深掘り（なぜ？具体的には？）か横展開（別の観点では？）を伴うこと
2. **批判的思考**: 本質を突くアイデアと反論を活発に行う
3. **根拠と理由の明確化**: 自分の意見を正当化するために必ず根拠を述べる
4. **否定には代替案**: 否定する場合は必ず代替案を提示する
5. **初心者にもわかりやすく**: 専門用語を使う場合は天才が補足説明するか、初心者が質問する形で自然に解説する
6. **発言の均等化**: 4人がほぼ均等に発言すること（偏りなし）
7. **文字数**: 会議トランスクリプト部分は最低10,000字以上。限界まで議論を続ける
8. **3つの会議結果を「素材」として参照しながら議論する**
9. **各会議での発言を「会議1では〜」「会議3の{名前}が〜」と引用可能**
10. **3会議間の矛盾点・補完点・盲点を中心に議論する**
11. **既出アイデアの単なる繰り返し禁止。深化・統合・新結合のみ**

## 入替候補の外部検証

会議3（銘柄品質・入替判断会議）で入替候補銘柄が提案された場合、マージ会議の議論に先立ち以下を実施する:

1. WebSearch/WebFetchで入替候補銘柄の最新情報を取得
   - 直近1ヶ月のニュース・プレスリリース
   - 資金流出入トレンド
   - 構造的逆風（規制変更、指数改定等）
2. 検証結果をマージ会議内で議論の素材として使用
3. 検証結果の判定:
   - **推奨**: 構造的問題なし。入替候補として有効
   - **要再検討**: リスク要因あり。条件付きで検討
   - **非推奨**: 構造的逆風あり。入替候補から除外

## 作業手順

1. Readで3つの会議ファイル（`{WORK_DIR}/10_meeting_1.md`、`{WORK_DIR}/10_meeting_2.md`、`{WORK_DIR}/10_meeting_3.md`）を読み込む
2. Readで `{WORK_DIR}/05_shared_calculations.md` を読み込む（定量データ参照用）
3. Readで `{WORK_DIR}/0a_market_environment.md` を読み込む（存在する場合）
4. 各会議の議事録セクションから論点・結論・洞察を抽出
5. 入替候補銘柄がある場合、WebSearch/WebFetchで外部検証を実施
6. テーマに応じて4名のキャラクター（名前・専門）を自律生成
7. 統合会議トランスクリプトを生成（10,000字以上）
8. 統合議事録を作成（横断分析テーブル、矛盾解消、シナジー、盲点、検証結果、最終結論）
9. 上記の出力ファイル構造に従い、Writeツールで `{WORK_DIR}/20_merge_meeting.md` に書き出す
10. 完了判定を返す（**会議内容は一切返さない。ファイルパスと文字数のみ**）

## 完了判定基準

| 条件 | 判定 |
|------|------|
| 10,000字以上のトランスクリプト + 統合議事録をファイル書き出し済み | Yes |
| 4名全員がほぼ均等に発言している | Yes の必要条件 |
| 3会議の内容を引用・参照している | Yes の必要条件 |
| 横断分析テーブルが記載されている | Yes の必要条件 |
| 合意レベル（全会議一致/2会議一致/意見分裂）が各アクションに付与されている | Yes の必要条件 |
| 入替候補がある場合、外部検証結果が記載されている | Yes の必要条件 |
| 同意のみの発言が含まれている | No → 深掘りor横展開に修正 |
| 否定時に代替案がない | No → 代替案を追加 |
| 文字数不足（10,000字未満） | No → 議論を追加 |

## 注意事項

- 出力は全て日本語で記述すること
- 会議の内容をサブエージェントの返答に含めないこと（コンテキスト保護）
- ファイルへの書き出しのみが成果物
- 入替候補の外部検証はWebSearch/WebFetchツールを使用する。ツールが利用できない場合は「外部検証ツール利用不可のためスキップ」と記載する
