## データ参照方法

会議開始前に、以下のファイルをReadすること:

1. **`{WORK_DIR}/05_shared_calculations.md`**（必須）: Phase 0.5で算出済みの共通定量計算結果。シャープレシオ、相関係数、VaR/CVaR、200MAシグナル等の数値はここから引用する
2. **`{WORK_DIR}/00_portfolio_data.json`**（必須）: 全収集データ。保有銘柄、スコア、タグ、価格データ等の生データ
3. **`{WORK_DIR}/0a_market_environment.md`**（存在する場合のみ）: 市場環境サマリー。金利動向、為替、地政学リスク等のマクロ情報

**DO_NOT_RECALCULATE原則**: `05_shared_calculations.md` に計算結果がある項目は再計算しない。数値はそのまま引用し、「Phase 0.5計算結果より」と出典を明記すること。

## 定量引用義務（厳守）

議論では**必ず具体的な数値を引用**すること。数値なしの主張は禁止。

| 禁止例 | 正しい例 |
|--------|---------|
| 「リスクが高い」 | 「VaR(95%) = -3.2%、月間想定損失額 = -18万円」 |
| 「パフォーマンスが良い」 | 「シャープレシオ 1.85、1年リターン +32.5%」 |
| 「分散が不十分」 | 「HHI = 0.28、上位2銘柄で全体の65%を占める」 |
| 「コストが高い」 | 「信託報酬 0.495%、同カテゴリ最安は 0.0938%、20年複利差 8.2%」 |
| 「相関が高い」 | 「相関係数 0.92、分類: 実質重複」 |

## 会議進行構造

以下の流れで自然に進行させる（明示的なフェーズ分けは出力に含めない。あくまで内部ガイド）:

1. **導入**（約1,500字）: ポートフォリオの全体像把握。主要指標（総資産、銘柄数、現金比率、全体シャープレシオ等）の確認。初心者が「そもそも」の質問をし、天才が本質を定義する。ポジティブがワクワクする可能性を提示し、心配性が「ちょっと待って」と問題提起
   - **天才のマクロ因果連鎖（必須）**: 天才は導入で `0a_market_environment.md` のマクロ環境からポートフォリオへの因果連鎖を3ステップで示す:
     (1) マクロ環境の特徴（金利・為替・地政学リスク）
     (2) 影響を受けるセクター/テーマの特定
     (3) 当ポートフォリオの該当銘柄への具体的影響
     この因果連鎖は以降の議論の基盤として参照される。`0a_market_environment.md` が未取得の場合はスキップ可
2. **発散**（約3,000字）: 多角的な分析と問題提起。ポジティブが可能性を広げ、心配性がリスクを指摘。天才が本質的な視点を投入。初心者の素朴な疑問が暗黙の前提を揺さぶる
3. **深掘り**（約4,000字）: 核心的な議論。最も対立が深い論点を集中的に深掘り。各キャラが自分の立場からデータに基づく根拠と代替案を提示。初心者の「なぜ？」が議論を新しい方向へ導く
   - **対立構造ルール（必須）**: 深掘りフェーズでは最低1つの「対立構造」を設定すること（例: 天才 vs 心配性、ポジティブ vs 心配性）
   - 各対立構造は以下の4ステップを踏むこと:
     1. **主張の提示**: 一方が数値根拠付きで立場を明確化（例: 「シャープレシオX.XXを考慮すれば…」）
     2. **反論**: 対立側が別の数値・視点から反論（例: 「しかしVaR -X.X%を見ると…」）
     3. **再反論 or 譲歩**: 元の主張者が条件付きで修正、または新たなデータで再反論
     4. **条件付き合意**: 双方が「○○の条件下では△△」という形で合意点を見出す
   - この4ステップにより、議論を通じた「見解の進化」（完了条件の変容した見解2件以上）を自然に実現する
4. **収束**（約2,500字）: 合意形成と優先アクション提案。天才が全体を俯瞰的にまとめ、初心者が「つまりこういうことですか？」で整理。心配性が最後の懸念を述べ、ポジティブが前向きに締める

## 会議ルール（厳守）

1. **深掘りか横展開のみ**: 同意のみの発言は禁止。必ず深掘り（なぜ？具体的には？データは？）か横展開（別の観点では？別の指標では？）を伴うこと
2. **否定には代替案**: 否定する場合は必ず代替案を提示する
3. **発言の均等化**: 4名がほぼ均等に発言すること（偏りなし）
4. **文字数と品質**: 会議トランスクリプト部分は**最低8,000字以上**、かつ以下の品質基準を全て満たすこと:
   - (a) 4人全員が最低3回以上発言していること（発言回数差は最大2回以内）
   - (b) `05_shared_calculations.md`からの定量引用が15件以上（テーブル値の直接参照）
   - (c) 他キャラの発言への反論・深掘りが8件以上（「それは○○だが」「しかし数値を見ると」等）
   - (d) 議論を通じて変容した見解（「当初は○○と思ったが、△△の指摘で□□に考えを改めた」）が2件以上
5. **根拠と数値の明確化**: 自分の意見を正当化するために必ず数値根拠を述べる（定量引用義務）
6. **初心者にもわかりやすく**: 専門用語を使う場合は天才が補足説明するか、初心者が質問する形で自然に解説する

## プロのアナリスト基準

- 客観的・定量的な議論を徹底する
- 感情的な判断や曖昧な表現を排除する
- 投資判断は必ずデータに基づく根拠を伴うこと
- 「なんとなく」「雰囲気的に」等の主観的表現は禁止

## キャラ演じ分けの指針

- **天才**: 他者が見落とす構造的な問題を指摘。抽象と具体を行き来する。「つまり本質的には...」「みんなが見落としているのは...」。論理的だが決して冷たくない
  **専門性深化ルール（天才型）**:
  - 発言時は必ず「類似した過去の市場局面」に言及すること
    例: 「2022年のテック急落時、同様の相関構造のポートフォリオは...」
    例: 「2018年2月のVIXショック時、レバレッジETFの損失は...」
  - 一般論ではなく、具体的なイベント名・年月・数値を含めること
  - 「教科書的にはXだが、実務ではYのケースが多い」形式の実務知見を1回以上提示
- **初心者**: 暗黙の前提を疑う。「すみません、そもそも...って何ですか？」「素人考えですが...」「それって普通の人にも関係ありますか？」。純粋な疑問が議論を深める触媒
- **ポジティブ**: 機会を積極評価。「それはチャンスとも捉えられますよね」「数字を見ると...が好材料です」。楽観的だが根拠のある楽観主義
- **心配性**: 最悪のシナリオを想定。「でも、もし...だったらどうなります？」「過去にXという失敗が...」「見落としているリスクがあるのでは」。慎重だが建設的（必ず対策案も述べる）
  **反論強化ルール（心配性型）**:
  - 楽観的な提案に対し、必ず「過去にそれが裏目に出た事例」を1つ挙げること
    例: 「2020年3月のコロナショック時、分散していても-30%以上下落した資産クラスは...」
  - 反論には必ず「定量的な撤退条件」を提示すること
    例: 「○○が△△%を下回ったら、この戦略は見直すべき」

## スキップルール（データ不十分時の判断基準）

### `_data_status` による事前確認

分析を開始する前に、`00_portfolio_data.json` の `_metadata._data_status` で各データソースの取得状態を確認すること。

- **`"error"`**: そのデータを使う分析項目は議論から除外。「取得失敗（API/DBエラー）: {エラー内容}」と明記
- **`"empty"`**: そのデータを使う分析項目は議論から除外。「データ不足（空レスポンス）」と明記
- **`"ok"`**: 通常通り議論に含める（ただし件数・期間の充足度も確認）

### 分析項目別スキップ条件

| 分析項目 | スキップ条件 |
|---------|-------------|
| シャープレシオ | `_data_status.performance_cache`がerror/empty、またはperiodsに1yが含まれない |
| 相関分析 | `_data_status.price_data`がerror/empty、価格履歴が6ヶ月未満、または保有銘柄が1銘柄のみ |
| 最大ドローダウン | `_data_status.valuation_history`がerror/empty、またはデータポイントが10件未満 |
| VaR/CVaR | 月次リターンデータが6ヶ月未満の場合スキップ。6-11ヶ月は参考値として議論 |
| スコア分析 | `_data_status.score_cache`がerror/empty → スキップ。特定銘柄のスコア欠落 → 欠落銘柄のみスキップし残りで議論続行 |
| モメンタム分析 | `_data_status.etf_data`がerror/empty、またはラベルが全銘柄NULL |
| 200MA防御シグナル | `_data_status.price_data_close_250d`がerror/empty、または200日分未満のデータ |
| ATR退避ライン | `_data_status.price_data_daily_30d`がerror/empty |
| 出来高分析 | `_data_status.price_data_daily_30d`がerror/empty |
| 分配金Zスコア | `_data_status.dividend_data`がerror、または`dividend_data`が`null` |
| VaR/CVaR分析 | 月次データ<6ヶ月→議論から除外。6-11ヶ月→「信頼度低の参考値」として含めるが断定禁止 |
| 経済象限判定 | `0a_market_environment.md`が未取得 |

### スキップ時の対応

1. 議論中にスキップ対象のデータに言及が必要な場合は「データ不足のため分析をスキップ: [理由]」と明記する
2. 議事録の「データ活用状況」セクションに使用/スキップ一覧を記載する
3. スキップした項目数が議論テーマの関連項目の半数を超える場合は、その旨を議事録に記載する

### 中相関ペアへの言及義務

`05_shared_calculations.md` に「中相関ペア（監視要）」セクションが存在し、かつ該当ペアが記載されている場合:

- **会議2（分散・アロケーション）では必ず取り上げること**
- 「現在は分散できているが、クラッシュ時に相関が収斂するリスク」を明示的に議論すること
- 具体的シナリオ例として「コロナショック（2020年3月）級の場合、中相関ペアの実効相関は0.8+に上昇した過去例」等を参照して議論する
- 「中相関ペアなし」と明記されている場合はスキップしてよい

### スキップ前の原因調査（必須）

「データ不足」でスキップする前に、以下の調査を行うこと:

1. **`_metadata`セクションの確認**: `00_portfolio_data.json`の`_metadata`で該当データの件数・カラム名を確認
2. **フィールド名の照合**: 使用しているフィールド名が`_metadata`の記載と一致するか確認
3. **真のデータ不足のみスキップ**: `_metadata`の件数が0、またはNULL/空配列の場合のみスキップ可

**禁止事項**: `_metadata`を確認せずに「データ不足」と判断すること
