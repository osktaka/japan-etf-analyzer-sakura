# Phase 0b: トレンドサマリー生成 指示書

## 前提

- 作業ディレクトリ: `{WORK_DIR}`（メインエージェントから渡される）
- Docker内パス: `/app/{WORK_DIR}`

## データ受け渡しルール

- **入力**: `reports/{USER}/metrics.json`（過去蓄積データ）+ `reports/{USER}/HISTORY.md`
- **出力**: `{WORK_DIR}/0b_trend_summary.md`
- **メインへの戻り値**: 完了メッセージ1行のみ。データ全文やテーブル全体を返さないこと

## フォールバック

以下のいずれかに該当する場合、フォールバック出力を生成して**正常完了**する:

- `reports/{USER}/` ディレクトリが存在しない
- `reports/{USER}/metrics.json` が存在しない
- `metrics.json` のパースエラー（不正なJSON等）

**フォールバック出力**（`{WORK_DIR}/0b_trend_summary.md` に書き込む）:

```markdown
# トレンドサマリー

初回分析のためトレンドデータなし。次回以降の分析でトレンドが蓄積されます。
```

フォールバック時の戻り値: 「トレンドサマリー完了（初回分析のためデータなし）」

---

## 実行手順

### 1. 入力ファイルの読み込み

1. `reports/{USER}/metrics.json` を読み込む
   - 存在しない場合 → フォールバック
   - JSONパースエラー → フォールバック
2. `reports/{USER}/HISTORY.md` を読み込む
   - 存在しない場合 → metrics.json のデータのみで生成（HISTORY.md依存セクションは「データなし」と記載）

### 2. metrics.json の構造

metrics.jsonはトップレベルが配列（`analyses`ラッパーなし）。各エントリの構造:

### 3. トレンドサマリーの生成

`metrics.json` の配列から過去の分析データを読み取り、以下のフォーマットで `{WORK_DIR}/0b_trend_summary.md` を生成する。

**分析回数N**: 配列の要素数

---

## 出力フォーマット

```markdown
# トレンドサマリー（過去N回分析に基づく）

## 資産推移トレンド

| 日付 | 総資産 | 前回比 | 累計変化率 |
|------|--------|-------|-----------|
| 2026-02-12 | 1,000,000円 | -- (初回) | -- |
| 2026-02-14 | 991,130円 | -8,870円 | -0.89% |

**トレンド判定**: （上昇傾向/下降傾向/横ばい/変動大 のいずれかを判定し、根拠を1行で記載）

## メトリクス推移

| 指標 | {日付1} | {日付2} | ... | 変化方向 |
|------|---------|---------|-----|---------|
| 現金比率 | 1.58% | 1.59% | ... | → |
| 保有銘柄数 | 5 | 5 | ... | → |

## ポートフォリオ構成変化

（銘柄の入れ替え履歴を簡潔に記載。holdings配列の差分から検出する）

- 2026-02-12: 初回構築（1475, 1329, 1615, 1489, 1597）
- 2026-02-XX: 2558を追加、1329を縮小

## 5軸スコア推移（score_axes）

| 軸 | {日付1} | {日付2} | ... | トレンド |
|-----|---------|---------|-----|---------|
| 配当力(dividend_power) | 68.4 | 62.0 | ... | ↓ |
| コスト効率(cost_efficiency) | 80.9 | 84.0 | ... | ↑ |
| 規模信頼性(scale_reliability) | 96.6 | 96.2 | ... | → |
| 売買品質(trading_quality) | 92.5 | 95.4 | ... | ↑ |
| リターン(return_performance) | 67.2 | 78.9 | ... | ↑ |

## アクション実行状況

（HISTORY.mdの「未実行アクション」セクションと、metrics.jsonの各回top_actionsを突合して記載）

| 提案日 | アクション | 視点一致度 | 実行状況 |
|--------|-----------|-------|---------|
| 2026-02-14 | 1329/1475重複解消 | 100% | 未実行 |
| 2026-02-14 | 海外ETF追加 | 100% | 未実行 |

## 注目すべきトレンド

（3-5項目の箇条書きで、以下の観点から注目点を抽出する）

- 資産推移の傾向と要因
- スコアの改善/悪化傾向
- 繰り返し提案されているが未実行のアクション
- ポートフォリオ構成の変化パターン
- リスク指標の変動
```

### 4. 判定基準

**トレンド判定の基準**:

| 判定 | 条件 |
|------|------|
| 上昇傾向 | 直近3回以上で総資産が連続増加 |
| 下降傾向 | 直近3回以上で総資産が連続減少 |
| 横ばい | 累計変化率が±1%以内 |
| 変動大 | 上記いずれにも該当せず、変動幅が±3%以上 |

**変化方向の記号**:

| 記号 | 意味 |
|------|------|
| ↑ | 前回より改善/増加 |
| ↓ | 前回より悪化/減少 |
| → | 変化なし（±0.1以内） |

## 収集結果の保存先

`{WORK_DIR}/0b_trend_summary.md` に保存する。Phase 4の統合エージェントがこのファイルを直接読み込む。

**メインへの戻り値**: 「トレンドサマリー完了（過去N回分析データ）」の1行のみ。サマリー全文を返さないこと。
