## レポート生成ルール

### テンプレート準拠

`report-guide.md` のテンプレート構造に従ってレポートを生成する。

### クイックサマリー生成ルール（必須）

- **クイックサマリーは全セクション生成完了後に最後に書く**（全体を把握した上での要約を確保するため）
- クイックサマリーのトップ3アクションは、セクション10・12の提案から最優先の3件を抽出し、タイムラインラベル（今日/今週/来月）を付与する
- クイックサマリーの最大リスクは、マージ会議の反論ラウンドから最重要リスクを1文で要約する
- クイックサマリーの5秒ダッシュボードのα欄には、必ずベンチマーク名を明記する

### データソースの優先順位

1. **テーブルデータ**: `00_portfolio_reference.md` からそのまま転記（数値の丸め・フォーマット変更禁止）
2. **定量計算結果**: `05_shared_calculations.md` の値を正とする（Phase 0.5のプログラマティック計算結果）
3. **市場環境**: `0a_market_environment.md` から抽出
4. **トレンド**: `0b_trend_summary.md` から抽出（存在しない場合は「初回分析のためトレンドデータなし」）
5. **会議結論**: `20_merge_meeting.md` の統合議事録から各セクションの内容を抽出

## 品質チェック（レポート保存前に実施）

品質チェックは **Tier 1（必須・ブロッキング）** と **Tier 2（推奨・非ブロッキング）** に分類される。

- **Tier 1**: 全項目PASSしないとレポート保存不可。不合格時は修正して再チェック
- **Tier 2**: 不合格でもレポート保存可。不合格項目はセクション15に「⚠️ Tier 2未達: {項目名}」として警告注記する

---

### 【Tier 1: 必須・ブロッキング】

### エグゼクティブサマリー品質チェック（必須）

- [ ] 5秒ダッシュボードに4指標（総資産/含み損益率/年間コスト/α）が揃っているか
- [ ] トップ3アクション各項に「実行コスト」と「期待改善幅」が記載されているか
- [ ] リスクサマリーにVaR損失額が円建てで記載されているか

### 行数制限チェック（必須）

- 最終レポートが600行を超える場合、以下の順で圧縮して再生成する:
  1. セクション13.2（用語解説）: 2回目以降は新規用語のみに削減
  2. セクション9（議論サマリー）: 主要対立点テーブル5行以内に圧縮
  3. セクション11（最適化前後比較）: テーブル1つ + コメント3行以内に簡略化

### Tier 1追加チェック（ブロッキング）

- [ ] クイックサマリーが30行以内か
- [ ] エグゼクティブサマリーがクイックサマリーと重複していないか（5秒ダッシュボード・トップ3アクションの再掲がないこと）
- [ ] 全セクションの行数が行数バジェット内か（report-guide.md「行数バジェット」参照）
- [ ] セクション9以外にキャラクター名の直接引用がないか（天才、初心者、ポジティブ、心配性等の名前がセクション9以外に含まれていないこと）

### 最大DD計測期間統一チェック（必須）

- 最大ドローダウンは `valuation_history` の全期間データを使用すること
- レポート内に計測開始日を明記すること（例: 「計測期間: YYYY-MM-DD〜YYYY-MM-DD」）
- セクション4とセクション11.1の最大DD値が同一期間で算出されていること

### 数値整合性チェック（必須）

レポート保存後、`{WORK_DIR}/00_portfolio_reference.md` のチェック値セクションとレポート内の数値を照合する:

```bash
python3 -c "
import re, sys

with open('/app/{WORK_DIR}/00_portfolio_reference.md', encoding='utf-8') as f:
    ref = f.read()
with open('./reports/{username}/{REPORT_FILENAME}', encoding='utf-8') as f:
    report = f.read()

# チェック値セクションから期待値を抽出
ref_total = re.search(r'合計評価額:\s*([\d,]+)円', ref)
ref_asset = re.search(r'総資産:\s*([\d,]+)円', ref)
ref_count = re.search(r'銘柄数:\s*(\d+)', ref)
ref_cash = re.search(r'現金残高:\s*([\d,]+)円', ref)

# レポートのセクション1.2から実値を抽出
report_total = re.search(r'合計評価額:\s*([\d,]+)円', report)
report_asset = re.search(r'総資産:\s*([\d,]+)円', report)
report_count = re.search(r'保有銘柄数:\s*(\d+)', report)
report_cash = re.search(r'現金残高:\s*([\d,]+)円', report)

errors = []
if ref_total and report_total:
    if ref_total.group(1) != report_total.group(1):
        errors.append(f'合計評価額: 参照={ref_total.group(1)}円 vs レポート={report_total.group(1)}円')
if ref_asset and report_asset:
    if ref_asset.group(1) != report_asset.group(1):
        errors.append(f'総資産: 参照={ref_asset.group(1)}円 vs レポート={report_asset.group(1)}円')
if ref_count and report_count:
    if ref_count.group(1) != report_count.group(1):
        errors.append(f'銘柄数: 参照={ref_count.group(1)} vs レポート={report_count.group(1)}')
if ref_cash and report_cash:
    if ref_cash.group(1) != report_cash.group(1):
        errors.append(f'現金残高: 参照={ref_cash.group(1)}円 vs レポート={report_cash.group(1)}円')

if errors:
    print('数値整合性エラー:')
    for e in errors:
        print(f'  - {e}')
    print('00_portfolio_reference.md から再転記して修正してください')
    sys.exit(1)
else:
    print('数値整合性チェック: OK')
"
```

不一致があった場合: レポートのセクション1.1/1.2/11.2を `00_portfolio_reference.md` の値で上書きし、再度保存する。

### Rf精度チェック（Tier 1）

- `05_shared_calculations.md` の計算メタデータから「リスクフリーレート」行の出典を確認する

  - 実際値が使われていた場合: 出典URL（mof.go.jp等）をセクション2に記載する

### 【Tier 2: 推奨・非ブロッキング】

以下の項目は不合格でもレポート保存可。不合格項目はセクション15に警告注記として記録する。

### Phase 0.5→レポートの数値トレーサビリティチェック（推奨）

`05_shared_calculations.md` に記載された定量計算結果がレポートにそのまま転記されていることを確認する:

- [ ] シャープレシオ値（各銘柄・ポートフォリオ加重）が一致すること
- [ ] 相関係数（各ペア）が一致すること
- [ ] 最大ドローダウン値が一致すること
- [ ] VaR/CVaR値が一致すること
- [ ] 計算メタデータ（リスクフリーレート値、市場代理ETF）が一致すること

不一致があった場合: レポートの数値を `05_shared_calculations.md` の値で上書きする。

### サマリー←→詳細の整合性チェック（必須）

- [ ] サマリーで「分散良好」と評価している場合 → セクション3で相関係数0.85超の「実質重複」ペアが存在しないこと
- [ ] サマリーで「リスク管理良好」と評価している場合 → セクション5でVaR警告レベルの指摘がないこと
- [ ] サマリーの総合評価トーン（ポジティブ/ネガティブ）と、詳細分析の個別指摘が方向性で矛盾しないこと

不一致があった場合: サマリーの評価表現を詳細分析の結果に合わせて修正する。

### LLM自由記述の妥当性チェック（必須）

- [ ] 改善後シャープレシオが現状の2倍超の場合 → 根拠が明記されていること
- [ ] 改善後コストが現状の50%未満の場合 → 代替銘柄の信託報酬が記載されていること
- [ ] 定量目標が保守的推定（x0.75）ルールに従っていること
- [ ] セクション10の各提案に「根拠チェーン」（データ→計算結果→解釈→提案理由の4段）が記載されているか

### 品質ゲートチェック（必須）

| 検証項目 | 判定基準 |
|---------|---------|
| リスクフリーレート出典 | 取得元URLが mof.go.jp または boj.or.jp であること |
| VaR注釈のデータ点数記載 | VaR/CVaRセクションにデータ点数と信頼度が記載されていること |
| 免責事項セクション | レポート冒頭に免責事項セクションが存在すること |
| 前回レポートとのRf差 | `reports/{username}/metrics.json` の直近エントリと比較 |

### 定量目標の整合性チェック（必須）

- セクション10の各Phase定量目標とセクション11.1の指標比較テーブルが整合していること
- 全Phase完了時の最終目標値 = セクション11.1の改善後の値であること

### 資金フロー整合性チェック（必須）

- セクション11.2.1の売却額・購入額・税コスト・差額が算術的に整合していること
  - 差額 = 売却額合計 - 譲渡益税概算 - 購入額合計
  - 改善後現金残高 = 改善前現金残高 + 差額
- 改善前総資産 ≒ 改善後総資産であること（税コスト分のみ差が許容される）
  - 乖離が税コスト以上の場合、売却額・購入額の計算を再確認する

### 集中度改善検証（推奨）

- セクション11.1で「銘柄数削減」を提案しつつ「分散改善」を主張している場合、最大セクター比率・HHIが実際に改善（低下）していることを確認する
- 「銘柄数簡素化」と「テーマ集中低下」は異なる概念であることを混同していないか確認する
  - 銘柄数が減っても、異なるセクター・テーマに分散していれば集中度は改善しうる
  - 逆に、同一セクター内で統合した場合は集中度が悪化する
- 不整合がある場合: セクション14の評価表現を修正し、集中度の変化を正確に記述する

### ポートフォリオSR整合性チェック（推奨）

- セクション2.2の正式値（ポートフォリオリターン直接計算）と `05_shared_calculations.md` の値が一致すること
- 加重平均値が正式値を大幅に上回っている場合（銘柄間の正の相関が高い証拠）、その旨の注記がレポートに含まれていること
  - 例: 「加重平均SR X.XXに対し、ポートフォリオ直接計算SR X.XX。銘柄間の正相関により分散効果が限定的」

### 洞察転記完全性チェック（推奨）

- `20_merge_meeting.md` 末尾の「📋 Phase 3向け洞察エクスポート」セクションを全て読む
  - 各「複合戦略」がセクション10（最適化シミュレーション）に明記されているか確認する
  - 各「盲点」がセクション9.4（少数派意見ハイライト）またはセクション12（検討オプション）に含まれているか確認する
  - シナリオ統合マトリックスがセクション5.4（シナリオ別行動計画）に反映されているか確認する
  - セクション12（検討オプション）にロバスト性列が含まれているか確認する
  - ロバスト性「低」のアクションがセクション10（最適化シミュレーション）からセクション12に格下げされているか確認する
  - 欠落している場合はセクション14「まとめ」に追記する
  - チェック結果をセクション15「実行時間」に記録: `洞察転記: {複合戦略N件} / {盲点N件} 全て反映済み`

### 処理時間チェック（推奨）

- `timing.json` から各フェーズの実行時間を取得し、合計を算出する
  - 合計30分以内の場合: セクション15に `処理時間合計: {実際時間}分（目標30分以内: 達成）` と記載する
  - 合計30分超過の場合: セクション15に `⚠️ 目標超過: {実際時間}分（目標30分）` と記載する
  - 最も時間がかかったフェーズを特定して `最長フェーズ: {フェーズ名} ({時間}秒)` を記録する

### 数値整合性・単位統一チェック（推奨）

- 全ての金額が「円」単位でカンマ区切り（例: ¥1,234,567）であるか確認
- アロケーション比率の合計が99.5〜100.5%の範囲内か確認
- 「現金比率 + 保有銘柄比率合計 = 100%」の整合性確認
- 日付表記の統一（YYYY/MM/DD形式で統一）
- レポート内でRf値が複数回登場する場合、同じ値が使われているか確認
- **チェック不合格の場合**: レポート保存前に該当箇所を修正してから再度このチェックを実施

## トーンガイドライン

Phase 1の内部分析（会議トランスクリプト）では率直な表現を許容するが、**最終レポートへの転記時**に以下のトーン変換を行う:

| 内部表現 | 最終レポート表現 |
|---------|----------------|
| SELL / 売却推奨 | 入替検討 |
| BUY / 購入推奨 | 追加検討 |
| HOLD | 継続保有 |
| 推奨 | 検討 / 目安 |
| すべき | が有効 / が望ましい |
| 〜を勧める | 〜の選択肢がある |

### 禁止語（最終レポート内）

- 「推奨」（免責否定文を除く）
- 「すべき」
- 「SELL」「BUY」（英語表現）
- 「〜しなさい」「〜してください」（命令形）

## レポート作成手順

1. `{WORK_DIR}/` 配下のファイルを読み込む（入力ファイル表の読込範囲に従う）
2. `{skill_dir}/report-guide.md` を読み込む
3. `00_portfolio_data.json` の `_metadata._data_status` を確認し、「データ活用状況」テーブルを生成
4. テンプレートに従い、各セクションを実データで埋める（セクション別データソース対応表に従う）
5. セクション9にブレインストーミング議論サマリーを記載（`20_merge_meeting.md` の統合議事録から抽出）
6. セクション10の入替提案に外部検証結果を反映（`20_merge_meeting.md` の「入替候補の外部検証結果」から転記）
6.5. セクション10.5（取引実行判定）を生成: セクション10の全Phase提案を走査し、以下の基準で即時実行対象を判定する
   - Phase 1の売買提案（売却/購入/入替/増額/縮小）: 無条件で実行対象候補
   - Phase 2-4の売買提案: 実行トリガー・前提条件が本日の市場環境（セクション0）で充足しているか照合
   - 非売買アクション（ルール策定、監視開始、モニタリング）: 対象外として明示的に除外
   - 該当なしの場合は「即時実行対象なし」＋理由を出力
6.6. 進行中計画の照合（HISTORY.mdに進行中の売買計画がある場合のみ実行）:
   a. `0b_trend_summary.md` の「進行中の売買計画ステータス」テーブルを読み込む
   b. ステータスが traded の段階は実行対象から除外する（二重取引防止）
   c. 各計画のトリガー条件を本日の市場データ（`0a_market_environment.md` + `05b_trader_indicators.md`）と照合する
   d. 時系列条件（N日連続等）は計画の「継続カウント」を参照し、本日のデータで更新する
   e. トリガー充足した計画の次段階アクションを即時実行対象に追加する
   f. 同一銘柄に売買方向が矛盾する計画（例: 損切りと追加購入）が同日発動する場合、警告を出力し自動実行を保留する
   g. 全進行中計画の照合結果をテーブル出力する（report-guide.mdの「進行中計画の照合結果」テンプレートに従う）
   h. 手順6.5 + 6.6の合計取引件数が5件を超える場合、優先度順に5件に絞り超過分を「次回持ち越し」として記載する
7. 品質チェックを全て実施
8. `./reports/{username}/` ディレクトリを作成（存在しない場合）
9. レポート本体を保存: `./reports/{username}/YYYYMMDD_{username}_v2.md`
10. `reports/{username}/metrics.json` に追記（v1 phase34-integration.md の手順7a参照）
11. 実行時間・コンテキスト使用量をセクション15に記載
12. メインに保存先パスのみ返す
