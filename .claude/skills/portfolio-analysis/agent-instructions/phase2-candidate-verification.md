## 処理フロー

### Step 1: 候補の抽出と統合

1. Phase 1出力ファイルを全て読み込む
2. 各ファイルから `<!-- PHASE2_CANDIDATES_START -->` と `<!-- PHASE2_CANDIDATES_END -->` マーカー間の行を抽出する
3. 「候補なし」と記載されているファイルはスキップする
4. 全ファイルの候補を統合し、重複を排除する（etf_codeが同じ候補は1件にまとめる。REASONは全出典を統合）

### Step 2: 候補の絞り込み（上限5件）

**debateモード**:
- 2体以上のアナリストが推奨する候補を優先する
- 優先度: 5体推奨 > 4体推奨 > 3体推奨 > 2体推奨 > 1体のみ（上限5件）
- 同一優先度内では、SELL > ADD_CLASS > BUY の順で優先する（既存銘柄の問題解決が先）
- 上限5件に絞り込む

**normalモード / speedモード**:
- 全アナリストの候補を統合する
- 重複排除後、SELL > ADD_CLASS > BUY の順で優先する
- 上限5件に絞り込む

### Step 3: 外部調査（WebSearch）

各候補に対して以下の3観点をWebSearchで調査する。

**1. 中長期トレンド**:
- 検索クエリ例: 「{銘柄名} 2026年 見通し」「{アセットクラス} 中長期 トレンド」
- 直近のニュースだけでなく、半年〜数年スパンの構造的な方向性を把握する

**2. 構造的リスク/追い風**:
- 検索クエリ例: 「{関連政策} 影響 {セクター}」「{経済指標} 見通し 2026年」
- 政策変更、規制動向、人口動態、技術革新など構造的な要因を調査する

**3. 専門家見通し（最低2つの異なるソースから）**:
- 検索クエリ例: 「{銘柄名 or アセットクラス} アナリスト 見通し」「{関連テーマ} 専門家 予測」
- 証券会社レポート、経済メディア、専門家コメントなど異なるソースから最低2件取得する
- 取得した情報には必ず出典URLを付記する

### Step 4: Phase 0aとの整合性検証

`{WORK_DIR}/0a_market_environment.md` の内容と外部調査結果を照合し、以下を検証する:

- Phase 0aの「分析への示唆」が短期材料のみに基づいていないか確認する
- 中長期的な構造要因と矛盾していないか検証する
- 矛盾がある場合は、どちらの見立てがより構造的・持続的かを判断し、根拠を記載する

### Step 5: 判定の付与

各候補に以下のいずれかの判定を付与する:

| 判定 | 基準 |
|------|------|
| 支持 | 外部調査で中長期的にPhase 1の推奨を裏付ける根拠が確認された |
| 条件付き支持 | 方向性は妥当だが、特定条件（タイミング、市場環境変化等）に依存する |
| 要再検討 | 外部調査で矛盾する情報が見つかり、Phase 1の推奨根拠が弱まった |
| 非推奨 | 中長期的な構造要因がPhase 1の推奨と明確に矛盾する |

### Phase 1既存フィルタリングとの役割分担

- **Phase 1（score-analyst/allocation-analyst）**: Phase 0aデータによる事前品質ゲート（タグ重複・スコア・市場環境整合性）
- **Phase 2（本フェーズ）**: WebSearchによる中長期構造分析（専門家見通し・トレンド検証）

Phase 1で通過した候補であっても、Phase 2で中長期的な構造要因と矛盾が見つかった場合は「要再検討」「非推奨」に格下げする。**Phase 2の「非推奨」判定は、Phase 3+4統合エージェントに対し当該候補をアクションアイテムの「即時実行」枠から除外する拘束力を持つ**。「要再検討」判定は「条件付き・観察期間付き」に格下げする。

## 候補が0件の場合

Phase 1の全出力ファイルで「候補なし」と記載されている場合、以下の内容で `20_candidate_verification.md` を作成して正常完了する:

```markdown
# Phase 2: 入替候補の外部検証レポート

調査日時: YYYY-MM-DD HH:MM
調査対象: 0件

入替候補なし（Phase 1で入替提案がないため検証対象なし）
```

メインへの戻り値: 「Phase 2完了: 0件検証（入替候補なし）」

```markdown
調査日時: YYYY-MM-DD HH:MM
調査対象: N件

外部検証未実施（検索失敗）

## 未検証候補一覧
{Phase 1から抽出した候補リストを転記}
```

メインへの戻り値: 「Phase 2完了: N件検証対象（外部検証未実施・検索失敗）」

### 個別候補のWebSearchが失敗した場合

- その候補のみ「検証不可（検索失敗）」と記載し、判定は「要再検討」とする
- 他の候補の検証は続行する

```markdown
## 候補X: {etf_code} {name}（SELL/BUY/ADD_CLASS）

### Phase 1での推奨根拠
- {Phase 1の候補サマリーから転記}

### 外部調査結果
検証不可（検索失敗）

### 検証結論
- **判定**: 要再検討
- **理由**: 外部検証が実施できなかったため、Phase 1の推奨根拠のみで判断が必要
- **リスク付記**: 中長期トレンドの確認が取れていない点に注意
```
