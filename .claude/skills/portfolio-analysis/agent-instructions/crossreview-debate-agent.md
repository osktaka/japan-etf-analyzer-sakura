## ペルソナ間の対立軸（双方向サイクル型）

クロスレビュー構造は双方向サイクル型:

```
A(積極) ←→ B(堅実) ←→ C(異論) ←→ D(マクロ) ←→ E(長期) ←→ A(積極)
```

各ペルソナはサイクル上の隣接2名のみをレビューし、同じ2名からレビューを受ける:

| ペルソナ | レビュー対象 | 被レビュー元 | 対立軸 |
|---------|------------|------------|-------|
| A | B, E | B, E | A↔B:リターンvsリスク / A↔E:短期vs長期 |
| B | A, C | A, C | B↔A:リスクvsリターン / B↔C:安定信仰vs安定の罠 |
| C | B, D | B, D | C↔B:批判的検証 / C↔D:ボトムアップvsトップダウン |
| D | C, E | C, E | D↔C:仮説vs反証 / D↔E:マクロサイクルvs超長期構造 |
| E | D, A | D, A | E↔D:長期vs中期 / E↔A:構造vs短期リターン |

### 対立軸マトリクス

| 対立ペア | 主要な対立点 | 着眼点 |
|---------|------------|-------|
| A↔B | リターン追求 vs リスク回避 | 非効率銘柄を即入替か回復を待つか？ |
| B↔C | 安定信仰 vs 安定の罠 | 分散しているつもりが実は集中していないか？ |
| C↔D | ボトムアップ反証 vs トップダウン仮説 | 構造的リスクは個別データとマクロデータのどちらが先行指標か？ |
| D↔E | 中期マクロサイクル vs 超長期構造 | 金利サイクルに対応すべきか、構造変化に焦点を当てるべきか？ |
| E↔A | 長期構造 vs 短期リターン | 高リターンだがコスト高い銘柄を長期保有すべきか？ |

## 独立性維持ルール（必須）

クロスレビューを実施する際、以下のルールを厳守すること:

1. **参照制限**: 各ペルソナはサイクル上の隣接2名のみをレビューする。レビュー対象外のペルソナの分析ファイルは参照禁止（2者間の直接比較に集中する）
2. **ペルソナ一貫性**: 各ペルソナの発言は、そのペルソナの★★★重点項目に基づくこと。★の項目で強い主張をしない
3. **合意の検証**: 「全ペルソナ同意」と記載する前に、各ペルソナの立場から反対できる根拠がないか必ず検証する
4. **同意の制限**: 第1ラウンドでは「同意する点」を最大2項目に制限し、相違点の掘り下げを優先する
5. **反証のデータ要求**: analyst-Cが反対意見を述べる際は、定量データまたは具体的事例に基づくこと。データ根拠のない反対は記載しない
6. **転記数値の照合**: 分析結果内の共通計算結果が`05_shared_calculations.md`と一致するか照合する。不一致時は`05_shared_calculations.md`を正とし「計算値修正」と注記

## Round 1: 相互レビュー

### 入力ファイル（担当ペルソナ別）

担当ペルソナに応じて、以下のファイルのみを読み込む（サイクル上の隣接2名の分析ファイル）:

| 担当ペルソナ | 読み込む分析ファイル |
|------------|-----------------|
| A | `10_analyst_b_analysis.md`, `10_analyst_e_analysis.md` |
| B | `10_analyst_a_analysis.md`, `10_analyst_c_analysis.md` |
| C | `10_analyst_b_analysis.md`, `10_analyst_d_analysis.md` |
| D | `10_analyst_c_analysis.md`, `10_analyst_e_analysis.md` |
| E | `10_analyst_d_analysis.md`, `10_analyst_a_analysis.md` |

共通参照ファイル:

| ファイル | 内容 |
|---------|------|
| `{WORK_DIR}/05_shared_calculations.md` | 共通定量計算結果（転記数値の照合用） |
| `{WORK_DIR}/20_candidate_verification.md` | Phase 2 入替候補の外部検証結果（存在する場合のみ） |

### 手順

1. 担当ペルソナに対応する隣接2名の分析ファイルのみを読み込む（独立性維持ルール#1遵守）
2. 各分析に対し、見解の相違・見落とし・データ解釈の妥当性・総合判断の優先順位をレビュー
3. Phase 2の外部検証結果との整合性を確認する（`20_candidate_verification.md`が存在する場合）:
   - Phase 1で推奨した入替候補がPhase 2で「要再検討」「非推奨」と判定された場合、その根拠を踏まえてレビューに反映する
   - Phase 2で「構造的リスク」が指摘された候補について、他のペルソナの推奨理由が短期的材料のみに基づいていないか検証する
4. 出力形式に従って記載する

### 出力ファイル

- `{WORK_DIR}/31_crossreview_{persona}.md`

### 出力形式（2名それぞれに対して記載）

```
=== analyst-X による analyst-Y のレビュー ===

0. 相手のペルソナ前提:（1-2行で簡潔に）

1. 見解の相違:
   - [対立軸を踏まえた相違点と根拠]

2. 見落としの指摘:
   - [相手が軽視しがちな観点]

3. 同意する点:
   - [相手の優れた分析点]

4. 総合判断の比較:
   - トップ3アクションの対比
   - ペルソナ起因 vs データ解釈起因の分類
```
