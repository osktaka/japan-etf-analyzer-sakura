# Phase 1: score-analyst（スコア・モメンタム分析）指示書

## 共通ルール

### 前提

- 作業ディレクトリ: `{WORK_DIR}`（メインエージェントから渡される）
- Docker内パス: `/app/{WORK_DIR}`

### データ受け渡しルール（共通原則）

- **入力**: `{WORK_DIR}/portfolio_data.json`（全収集データ）、`{WORK_DIR}/market_environment.md`（市場環境サマリー）
- **出力**: 分析結果を `{WORK_DIR}/` 配下の指定ファイルに保存（ファイル名は下記で定義）
- **メインへの戻り値**: 完了メッセージ1行のみ。データ全文やテーブル全体を返さないこと

### データ検証ルール（必須）

分析の前に、必ず `_metadata` セクションを確認し、以下を実行すること:

1. **フィールド名の確定**: `_metadata` に記載されたカラム名・perspective名を使用する。ハードコーディングしない。
2. **データ件数の確認**: `_metadata.{section}.count` が0でないことを確認する。
3. **スキップ前の原因調査**: データが空または取得できない場合、以下の順で原因を調査する:
   a. `_metadata` でデータ件数が0以上か確認 → 0以上なら「フィールド名の不一致」を疑う
   b. 実データの最初のレコードのキー一覧を出力して確認
   c. 正しいキー名で再取得を試みる
   d. それでもデータが取得できない場合のみ「データ不足」としてスキップ
4. **スキップ時の報告**: スキップする場合は、調査した内容（確認したキー名、件数等）を出力に含める
5. **`_data_status`の事前確認**: `_metadata._data_status` で自分が使うデータソースの取得状態を確認する。
   - `"error"` → そのデータを使う分析項目はスキップ（理由: 「取得失敗」+ `_data_status`のerror内容を転記）
   - `"empty"` → そのデータを使う分析項目はスキップ（理由: 「データ不足（空レスポンス）」）
   - `"ok"` → 通常通り分析を実施（ただし件数・期間の充足度も確認）

**注意**: 各データの存在確認は`portfolio_data.json`の該当セクションを実際に確認して判断すること（推測でスキップしない）。

### スキップ理由の記載ルール

出力ファイルに記載する際、理由を以下の3分類で明記すること:

- 「取得失敗（API/DBエラー）」: `_data_status` のstatusが "error" の場合
- 「データ不足（空レスポンス）」: `_data_status` のstatusが "empty" の場合
- 「データ不足（条件未充足）」: データは存在するが分析に必要な条件を満たさない場合（例: performance_cacheはあるが1yデータがない）

### 市場環境の活用（共通原則）

Phase 0aで収集した市場環境サマリー（`{WORK_DIR}/market_environment.md`）の情報も分析の判断材料に含めること。各アナリストの専門領域に関連する市場環境要因がある場合は、明示的に言及すること。具体的な活用例は以下で定義する。

## 分析項目

### A. 加重平均スコア
保有比率で加重したポートフォリオ全体のスコア。5軸バランスと視点別の総合評価を分けて出力。

**背景**: 5軸スコア（配当力・コスト効率・規模信頼性・売買品質・リターン）は各銘柄の客観的評価であり、視点によって値は変わらない。視点で変わるのは5軸の重み付けで算出される `total_score`（総合スコア）のみ。

**保有比率の算出**:
- `holdings` の各銘柄の `current_value` からポートフォリオ総額を算出
- 保有比率 = `current_value / 総額`（**小数値 0.0〜1.0** で扱う。例: 32.2% → 0.322）
- **絶対禁止**: パーセンテージ値（32.2等）をそのまま掛け算しないこと

**計算式**:
- 5軸加重平均: `Σ(銘柄iの軸Xスコア × 銘柄iの保有比率)` ※保有比率は小数（0-1）、視点に依存しない
- 視点別総合: `Σ(銘柄iのtotal_score(視点Y) × 銘柄iの保有比率)` ※保有比率は小数（0-1）、視点ごとに異なる

**バリデーション**: 計算結果は **0〜100の範囲** に収まるはず。範囲外なら保有比率のスケール（%と小数の混同）を確認する

**出力形式**:

#### 5軸加重平均（ポートフォリオ全体）
| 配当力 | コスト効率 | 規模信頼性 | 売買品質 | リターン |
|-------|-----------|-----------|---------|---------|
| 72 | 65 | 88 | 75 | 58 |

#### 視点別総合スコア加重平均
| 視点 | 総合スコア |
|------|----------|
| バランス | 72.5 |
| 高配当 | 68.3 |
| 低コスト | 75.1 |
| 成長性 | 70.8 |
| 安定性 | 71.2 |
| 流動性 | 69.5 |

**判定基準（ポートフォリオ全体の軸バランス評価）**:
- 5軸加重平均で最も低い軸を「最弱軸」として特定
- 最弱軸と最強軸の差が30点以上 → 「バランスに偏りあり」と評価。参考情報として全ETF母集団の中央値（50点）との比較も併記（ただし判定には使わない）

**弱い軸の特定**:
- リターンスコアが低い（50-60）→ 高リターン銘柄の追加を検討
- コスト効率が低い（65）→ 低コスト銘柄への入れ替えで改善可能

### B. モメンタム分析
失速/上昇中の銘柄のグルーピング。失速銘柄の合計比率と影響度。

**分類基準（momentum_label）**: 上昇加速 / 上昇中 / 横ばい / 下降中 / 下降加速

**出力形式**:
```
モメンタム分布:
- 上昇加速: 2銘柄（25%） / 上昇中: 3銘柄（35%） / 横ばい: 1銘柄（10%）
- 下降中: 2銘柄（30%）← 要注意
下降中銘柄: 9012 DEF ETF（20%, 3ヶ月-8.5%） / 3456 GHI ETF（10%, 3ヶ月-5.2%）
```

**市場環境との連関分析（下降中/下降加速の銘柄のみ）**:
1. 銘柄のtag_data（経済情勢タグ）を取得
2. `market_environment.md` の「分析への示唆」と照合して失速要因を推定（例: 金利上昇局面 + タグ「金利低下」→ 金利環境が逆風の可能性）
3. タグ照合だけで判定しない（偏り防止）。以下を併用して総合判断する:
   - パフォーマンス実績: 1m/3mリターンが負だが6m/1yが正 → 一時的 / 3m以上負が継続 → 構造的
   - 同タグ銘柄比較: 同タグ群が全体的に下落 → 一時的（市場要因） / 当該銘柄のみ → 構造的（銘柄固有）
4. 項目D（代替提案）で「構造的→入替推奨 / 一時的→様子見」の判断材料に使用

**出力例**: `下降中 1597 MAXIS J-REIT（10%, 3ヶ月-5.2%）: 金利上昇×タグ「金利低下」→逆風 → 判定: 一時的（1m-3%, 6m+2%）`

### C. 低スコア銘柄の深掘り
各銘柄の弱い軸を特定、改善可能性を評価。

**分析方法**:
1. 各銘柄の5軸スコアを取得（バランス視点）→ 平均スコア未満の軸を抽出
2. 弱い軸が2つ以上ある銘柄を優先的に深掘り対象にする
3. 同一カテゴリの高スコア銘柄と比較
4. 全銘柄が平均に近い場合は「スコアバランス良好」と明記（無理に改善候補を出さない）

**出力形式**:
```
低スコア銘柄: 9012 DEF ETF
弱い軸:
- コスト効率: 45点（平均65点）→ 信託報酬0.55%（カテゴリ平均0.35%）
- リターン: 38点（平均58点）→ 1年リターン2.5%（カテゴリ平均8.2%）
改善可能性: 代替候補 1357 国内株式ETF（コスト85点/リターン72点）→ ポートフォリオスコア+12点
```

### D. 代替銘柄提案
おすすめAPIの結果と比較し、低スコア銘柄の代替候補を提案。スコア改善シミュレーション。

**視点の選択基準**:
低スコア銘柄の「最も弱い軸」に応じて、参照するおすすめAPI視点を選択する:
- 配当力が最弱 → `recommendations.dividend` / コスト効率が最弱 → `recommendations.low-cost`
- 複数軸が同程度に弱い、またはリターンが最弱 → `recommendations.balance`

**偏り緩和ルール（必須）**:
- 保有銘柄と重複する候補は除外。保有銘柄のtag_dataを参照し、不足セクター/テーマを特定して該当タグの候補を優先
- 1つの視点で候補が不足（2件以下）の場合、他の視点からも補完抽出する
- 異なるセクター/テーマから最低2件を含めること。確保できない場合はasset（資産クラス）タグの多様性で代替し、その旨を記載

**提案フォーマット**:
```
入れ替え提案:
1. 9012 DEF ETF → 1357 国内株式ETF
   スコア+12点（58→70） / コスト削減: 年間約2,000円 / リターン改善期待: +7.3%pt
   概算税コスト: 約6,094円（含み益+30,000円 × 20.315%）/ 損益分岐: 約3.0年
   ※ NISA口座保有の場合は税コスト不要
2. 3456 GHI ETF → 2558 海外株式ETF
   スコア+8点（62→70） / 相関低下: 0.85→0.45 / リスク調整後リターン改善
   概算税コスト: 0円（含み損のため税負担なし）
```

**税コスト算出方法**:
- holdingsデータの `unrealized_pnl`（含み損益）を使用
- `概算税コスト = max(0, unrealized_pnl) × 20.315%`（所得税15.315% + 住民税5%）
- 含み損の場合は税コスト0円と記載
- `損益分岐期間 = 概算税コスト ÷ 年間改善効果`（年間コスト削減額またはリターン改善による年間期待収益増）
- 税コストが年間改善効果の5年分を超える場合、入替の推奨度を1段階下げる（例: 強く推奨 → 推奨、推奨 → 要検討）

**市場環境フィルタリング（必須）**:
代替銘柄を提案する際、`{WORK_DIR}/market_environment.md` の「分析への示唆」セクションと照合すること:
- 提案銘柄の主要タグ（tag_dataの経済情勢タグ）に逆風となる市場環境が示唆されている場合、リスク付記を必須とする
  （例: 金利上昇局面でのREIT系ETF提案 → 「現在金利上昇局面のため短期的に価格下落リスクあり」と付記）
- 逆風が明確な場合は代替候補の優先順位を下げ、他の候補を優先する
- market_environment.md が存在しない場合はフィルタリングをスキップし、その旨を記載する
- **注記**: 特定口座（源泉徴収あり）を前提とした概算。NISA口座の場合は非課税。実際の税額は取得価額・売却タイミングにより変動する

### E. 運用会社集中リスク
manager別の銘柄数・評価額比率。

**出力形式**:
| 運用会社 | 銘柄数 | 評価額 | 比率 | 判定 |
|---------|-------|--------|------|------|
| 野村アセットマネジメント | 3 | 250万円 | 45% | 要モニタリング（テーマ集中あり） |
| 三菱UFJ国際投信 | 2 | 150万円 | 27% | 参考情報 |

**注記**: ETFの原資産は信託財産として分別管理されており、運用会社の経営破綻が直ちに投資家の損失につながるリスクは限定的。ただし、同一運用会社の銘柄が同一セクター/テーマに集中している場合は、実質的なセクター集中リスクとして警告すること。また、運用品質の低下（トラッキングエラー悪化、コスト上昇等）にも注意。

### F. タグベース分散度
地域/セクター/経済環境タグの分布評価。

**出力形式**:
```
地域分散: 国内40% / 米国35% / 先進国15% / 新興国10% → 評価: 良好（4地域に分散）
セクター分散: テクノロジー50%（集中リスク） / 金融20% / ヘルスケア15% / その他15% → 評価: テクノロジーへの過度な集中
経済環境:
- 為替: 円安55% / 円高5% / 中立40%
- 景気感応: 景気敏感X% / ディフェンシブX% / 中立X%
評価: 円安に偏り（円高時のダウンサイドリスク大）。景気敏感比率が高い場合は景気後退リスクにも注意
※ 政策タグ（防衛関連/インフラ/半導体政策）・金利タグ（金利上昇/金利低下）は該当保有銘柄がある場合のみ、市場環境の政策動向と照合して追い風/逆風を付記
```
