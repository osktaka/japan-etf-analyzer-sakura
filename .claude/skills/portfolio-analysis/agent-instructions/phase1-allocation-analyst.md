# Phase 1: allocation-analyst（アセットアロケーション分析）指示書

## 共通ルール

### 前提

- 作業ディレクトリ: `{WORK_DIR}`（メインエージェントから渡される）
- Docker内パス: `/app/{WORK_DIR}`

### データ受け渡しルール（共通原則）

- **入力**: `{WORK_DIR}/00_portfolio_data.json`（全収集データ）、`{WORK_DIR}/0a_market_environment.md`（市場環境サマリー）、`{WORK_DIR}/0b_trend_summary.md`（トレンドデータ、存在する場合のみ）
- **出力**: 分析結果を `{WORK_DIR}/` 配下の指定ファイルに保存（ファイル名は下記で定義）
- **メインへの戻り値**: 完了メッセージ1行のみ。データ全文やテーブル全体を返さないこと

### データ検証ルール（必須）

分析の前に、必ず `_metadata` セクションを確認し、以下を実行すること:

1. **フィールド名の確定**: `_metadata` に記載されたカラム名・perspective名を使用する。ハードコーディングしない。
2. **データ件数の確認**: `_metadata.{section}.count` が0でないことを確認する。
3. **スキップ前の原因調査**: データが空または取得できない場合、以下の順で原因を調査する:
   a. `_metadata` でデータ件数が0以上か確認 → 0以上なら「フィールド名の不一致」を疑う
   b. 実データの最初のレコードのキー一覧を出力して確認
   c. 正しいキー名で再取得を試みる
   d. それでもデータが取得できない場合のみ「データ不足」としてスキップ
4. **スキップ時の報告**: スキップする場合は、調査した内容（確認したキー名、件数等）を出力に含める
5. **`_data_status`の事前確認**: `_metadata._data_status` で自分が使うデータソースの取得状態を確認する。
   - `"error"` → そのデータを使う分析項目はスキップ（理由: 「取得失敗」+ `_data_status`のerror内容を転記）
   - `"empty"` → そのデータを使う分析項目はスキップ（理由: 「データ不足（空レスポンス）」）
   - `"ok"` → 通常通り分析を実施（ただし件数・期間の充足度も確認）

**注意**: 各データの存在確認は`00_portfolio_data.json`の該当セクションを実際に確認して判断すること（推測でスキップしない）。

### スキップ理由の記載ルール

出力ファイルに記載する際、理由を以下の3分類で明記すること:

- 「取得失敗（API/DBエラー）」: `_data_status` のstatusが "error" の場合
- 「データ不足（空レスポンス）」: `_data_status` のstatusが "empty" の場合
- 「データ不足（条件未充足）」: データは存在するが分析に必要な条件を満たさない場合（例: performance_cacheはあるが1yデータがない）

### 市場環境の活用（共通原則）

Phase 0aで収集した市場環境サマリー（`{WORK_DIR}/0a_market_environment.md`）の情報も分析の判断材料に含めること。各アナリストの専門領域に関連する市場環境要因がある場合は、明示的に言及すること。具体的な活用例は以下で定義する。

### トレンドデータの活用（共通原則）

`{WORK_DIR}/0b_trend_summary.md` が存在する場合、過去の分析結果との比較情報を分析に活用すること。存在しない場合（初回分析時等）はトレンドに関する言及をスキップし、通常通りの分析を行う。

**共通ルール**:
- 同じ指摘が過去N回連続している場合は「繰り返し指摘（N回連続）」と明記し、優先度を引き上げる
- メトリクスが改善/悪化トレンドにある場合は、その方向性を分析の判断に反映する
- 過去の提案が実行/未実行かを確認し、新規提案との整合性を確保する

## 市場環境の活用

Phase 0aで収集した市場環境サマリー（`{WORK_DIR}/0a_market_environment.md`）の情報も分析の判断材料に含めること。特に為替動向（円安/円高）が地域配分の評価に、政策動向（金融緩和/引き締め）がアセットクラス推奨に影響する場合は明示的に言及すること。
欠落アセット提案（項目D）では、市場環境の政策動向と保有銘柄の政策タグ（防衛関連/インフラ/半導体政策）を照合し、政策追い風セクターへのエクスポージャー有無にも言及すること。

## トレンドデータの活用

前述の共通ルール「トレンドデータの活用（共通原則）」を基本とする。特に以下の観点で活用すること:

- **構成変化の効果検証**: 過去の分析回からの銘柄入替・比率変更が、地域/セクター/テーマ別配分にどのような効果をもたらしたかを評価する。配分の改善/悪化トレンドを明示する
- **未実行アクションの蓄積度**: 過去に提案された配分改善アクション（欠落アセット追加、集中リスク緩和等）が未実行のまま蓄積している場合は「未実行提案（N回連続）」として優先度を引き上げる。蓄積が3回以上の場合は特に強調する
- **配分偏りの固定化検出**: 地域/セクター集中度が複数回にわたり同水準で推移している場合は「構造的偏り」として認識し、改善の緊急度を明示する

### D. 欠落アセットクラス
資産クラスタグから未保有の資産を特定。

**出力形式**:
```
保有資産クラス:
- 株式: 95%
- REIT: 5%

欠落資産クラス:
- 債券: 0%（推奨: 10-20%、安定性向上）
- コモディティ: 0%（推奨: 5-10%、インフレヘッジ）

推奨銘柄の選定:
- `recommendations.balance` から欠落資産クラスタグ（債券/コモディティ/REIT等）を持つ銘柄を抽出
- 該当なしの場合 → `recommendations.low-cost` も参照（長期保有前提のため低コスト優先）
- いずれにも該当なしの場合 → 一般的な代表銘柄を提示（例: 債券→2621, コモディティ→1540）
- 注意: おすすめAPIは大型指数連動型が上位固定のため、欠落クラスに該当する銘柄が上位に含まれない場合がある。その場合はフォールバック例を使用し、APIに該当なしの旨を記載する
```

**推奨銘柄の品質ゲート（必須）**:
推奨銘柄を選定した後、以下を確認し不合格の場合は候補から除外すること:

1. **タグ重複チェック（高相関の推定）**: `00_portfolio_data.json`の`tag_data`で、推奨銘柄と既保有銘柄のタグを比較する。地域・セクター・テーマタグが3つ以上一致する場合→「既保有XXXXとタグ高重複（N個一致）、実質的な分散効果が限定的」として候補から除外し、同アセットクラスの別銘柄を探す
2. **スコア検証**: `score_cache`（recommendations API結果に含まれる）から推奨銘柄のスコアを確認。総合スコアが50点未満→「低スコア（XX点）」として候補から除外
3. **タグ×市場環境の構造的整合性**: 推奨銘柄の経済情勢タグ（tag_dataの「経済情勢」カテゴリ）と`0a_market_environment.md`の示唆が**構造的に矛盾**する場合（例: 「金利低下」タグ×金利上昇局面）→ 候補から除外し、同アセットクラスの別銘柄を探す。別銘柄がない場合は「該当アセットクラスは市場環境の好転を待って追加検討」と記載

**市場環境フィルタリング（必須）**:
欠落アセットを推奨する際、`{WORK_DIR}/0a_market_environment.md` の「分析への示唆」セクションと照合すること:
- 推奨する資産クラスに逆風となる市場環境が示唆されている場合、リスク付記を必須とする
  （例: 金利上昇局面での長期債推奨→「現在金利上昇局面のため短期的に価格下落リスクあり」と付記）
- 逆風が明確な場合は「現時点では見送り推奨」と判定可能
- フィルタ後も候補が不足する場合は「市場環境リスク付きで提案」と明記

### E. 現金比率の妥当性評価
summaryのcash_balanceとtotal_valueから現金比率を算出、動的推奨比率と比較。

**計算式**:
```
現金残高 = summary.data.cash_balance
現金比率 = 現金残高 / (summary.data.total_value + 現金残高)
```

**動的推奨比率の決定（必須）**:

静的な「5-10%」ではなく、quant-analystの200MAシグナル集計とeconomic_quadrantに基づいて動的に推奨比率を決定する。

debateモード: `05_shared_calculations.md` の `ma200_signal`（ポートフォリオ防御レベル）と `economic_quadrant`（経済象限判定）を参照。
normalモード: quant-analystの出力（セクションG「テクニカル防御シグナル」、セクションD「経済象限シナリオ」）を参照。

**4段階の動的推奨レンジ**:

| モード | 条件 | 推奨現金比率 | 判断基準 |
|--------|------|------------|---------|
| 攻撃 | 防御銘柄0%かつ成長×インフレ下降象限 | 5-10% | 全銘柄が200MA上方、マクロ環境良好 |
| 中立 | 防御銘柄30%未満または象限不明 | 10-20% | 一部銘柄に警戒シグナルあり、またはデータ不足 |
| 防御 | 防御銘柄30%以上または成長下降象限 | 20-30% | 多数銘柄が200MA下方、またはマクロ環境悪化 |
| 最大防御 | 防御銘柄50%以上かつ成長下降×インフレ上昇象限 | 30-50% | 大半の銘柄が下降トレンド、スタグフレーション懸念 |

**フォールバック**: 200MAシグナル・economic_quadrantの両方が取得できない場合は、従来の静的推奨（5-10%）を使用し、「（動的推奨データ不足のため静的基準を適用）」と付記する。片方のみ取得可の場合は、取得できたデータのみで判定する（200MAのみ→防御銘柄比率で判定、象限のみ→象限で判定）。

**出力形式**:
```
現金残高: 50万円
現金比率: 8.3%
動的推奨: 10-20%（中立モード）
  根拠: 防御銘柄比率15%（200MA下方: 1489, 1597）、経済象限: 成長鈍化×インフレ安定
判定: 適正（下限付近のため余力はやや少ない）
```

**現金のディフェンシブ機能評価（必須）**:

現金比率に応じた段階的評価（動的推奨レンジに対する相対評価）:
- 推奨レンジ下限未満: ディフェンシブ機能不足。買い増し余力・緊急対応力が限定的
- 推奨レンジ内: 基本的な防御力あり。買い増し余力を確保
- 推奨レンジ上限超: 十分なディフェンシブ機能あり。追加の低リターン資産（債券・REIT等）は優先度低い

判定ルール:
- 現金比率が動的推奨レンジの上限を超える場合、項目Dの欠落アセット提案で債券・REIT等の低リターン資産は「現金で十分なディフェンシブ機能があるため、追加は優先度低い」と判定すること
- ただし、現金以外に分散効果（株式との低相関）を求める場合は、市場環境フィルタを通した上で提案可能

### G. リバランス観点の気づき

**目的**: 具体的な目標比率を押し付けず、「現在の状況でどう考えるか」の気づきを与える。売り推奨は行わない（入替提案は既存のscore-analyst/Phase 2が担当）。

**データソース**（全て allocation-analyst の既存入力で完結）:
- `00_portfolio_data.json`: holdings, performance_cache, tag_data, price_data_close_250d, etfs.momentum_label
- `0a_market_environment.md`: economic_quadrant
- debateモード: `05_shared_calculations.md` の ma200_signal を参照可

#### G-1. トレンド複合評価

**目的**: 価格上昇で評価額比率が膨らんだ銘柄を特定し、トレンド継続性と組み合わせて判断する。

**計算**（allocation-analyst自身が実行）:
- `price_data_close_250d` から直近終値と200日SMAを算出し、200MA乖離率を計算
- debateモード: `05_shared_calculations.md` の `ma200_signal` を参照
- 200MA乖離率 ≥ 20% の銘柄を「比率肥大化候補」として抽出

**トレンドとの複合判定**:

| 200MA乖離率 | モメンタムラベル | 判定 |
|------------|----------------|------|
| ≥ 20% | 上昇加速/上昇中 | 上昇継続中（保持優先） |
| ≥ 20% | 横ばい | 上昇鈍化（要観察） |
| ≥ 20% | 下降中/下降加速 | トレンド転換サイン（リバランス検討） |

**フォールバック**: `price_data_close_250d` が200日未満の場合は「データ不足のためスキップ」。モメンタムラベルのみで簡易判定（上昇系→保持優先、下降系→要観察）。

**出力フォーマット**:
```
比率肥大化 × トレンド評価:
- XXXX（200MA乖離 +XX.X%）: 上昇継続中 → 保持優先。トレンド転換時にリバランス検討
- XXXX（200MA乖離 +XX.X%）: トレンド転換サイン → 比率調整を検討する局面
該当なし: 200MA乖離率20%超の銘柄はなし（現時点でリバランス観点の緊急度は低い）
※ トレンド継続中は比率拡大を理由に売りを急ぐ必要はない
```

#### G-2. 同一テーマ重複クラスターの効率比較

**クラスター検出**: `tag_data` の「地域」「セクター」「テーマ」で2つ以上一致する銘柄群を特定

**クラスター内効率比較**（allocation-analyst自身が計算）:
- `performance_cache` から1年リターン・ボラティリティを取得
- シャープレシオ = (1年リターン - リスクフリーレート) / ボラティリティ
- 信託報酬は補足情報として併記（判断の主軸にはしない）

**判定**:
- クラスター内でシャープレシオに大きな差（最大と最小の差 ≥ 0.5）がある場合: 「効率差あり。低効率銘柄はクラスター内整理候補」
- 差が小さい場合: 「同等の効率。意図的な分散として機能」
- 注記: 「シャープレシオは過去実績であり将来を保証しない。定期的なモニタリングを推奨」

**フォールバック**: `performance_cache` の1年データがない銘柄はシャープレシオ比較から除外し、「データ不足（1年未満）」と記載。クラスター内全銘柄がデータ不足の場合はG-2自体をスキップ。

**出力フォーマット**:
```
重複クラスター分析:
[半導体クラスター] 2644 / 200A / 2243（合計 XX万円 / XX%）
  シャープレシオ比較:
  - 200A: SR X.XX（信託報酬 0.XX%）
  - 2644: SR X.XX（信託報酬 0.XX%）
  - 2243: SR X.XX（信託報酬 0.XX%）
  → 気づき: [効率差が大きければ「低効率銘柄の整理余地あり」/
             同等なら「意図的な分散として機能している」]
  ※ 過去実績に基づく比較。定期的なモニタリングを推奨
```

#### G-3. 景気感応度 × 経済象限評価

**景気感応度分類**（既存の経済情勢タグをそのまま使用）:
- `tag_data` の経済情勢カテゴリから「景気敏感」「ディフェンシブ」タグを参照
- タグ未付与の銘柄は「中立」に分類

**Section E（現金比率）との役割分担**:
- Section E: 「現金をどの程度持つべきか」→ 量の判断
- Section G-3: 「株式部分の構成が現在の経済環境に合っているか」→ 質の判断

**経済象限との照合**（`0a_market_environment.md` の economic_quadrant を参照）:

| 現在象限 | 景気敏感比率が高い場合 | ディフェンシブ比率が高い場合 |
|---------|-------------------|------------------------|
| 成長上昇 × インフレ下降 | 現在の相場環境と整合・保持有利 | 機会損失の可能性 |
| 成長上昇 × インフレ上昇 | 整合だが素材・コモディティ優位 | インフレヘッジ不足を確認 |
| 成長下降 × インフレ下降 | 下落被弾リスクが高い構成 | 適切なディフェンシブ配置 |
| 成長下降 × インフレ上昇 | スタグフレーションリスク・最も注意 | 金等インフレヘッジの有効性高い |

**フォールバック**: economic_quadrant が取得できない場合は「象限データなし」として景気感応度の比率のみ出力（文脈評価はスキップ）。
