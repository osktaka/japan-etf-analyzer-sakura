# 市場データ収集・ドラフト生成 指示書

## 前提（共通）

- タイミング: `{timing}`（`am` または `pm`）
- モード: `{mode}`（`general` または `portfolio`）
- 日付: `{date}`、前営業日: `{prev_business_day}`
- 営業日フラグ: `{is_trading_day}`
- 年月: `{year_month}`、現在時刻: `{current_time}`

## データ取得フロー

### Step 0: yfinanceによる定量データ取得（AM/PM共通）

```bash
# AM実行時
docker compose exec backend python scripts/market_data_quick.py
# PM実行時
docker compose exec backend python scripts/market_data_quick.py --pm
```

- JSON出力を解析し、取得成功した指標をレポートに使用

**AM用取得指標（11指標 + 派生データ）:**
- 米国株式: S&P500, NASDAQ, Dow Jones, SOX(フィラデルフィア半導体指数)
- リスク指標: VIX
- 米国債券: 10年債利回り, 13週国債利回り（短期金利）
- 先物: CME日経先物
- 為替: ドル円
- 商品: WTI原油, 金
- 派生データ: イールドカーブスプレッド（10年-3ヶ月）、MACD(12,26,9)、一目均衡表（雲）、テクニカルシグナル集計

**PM用追加指標:**
- 日経平均, TOPIX(ETF代替), グロース250(ETF), REIT(ETF), 銀行(ETF), IT(ETF)
- テクニカル: RSI(14), SMA(25/75), ボリンジャーバンド(20,2σ), MACD(12,26,9), 一目均衡表, 出来高比

- 失敗した指標（errorsに記載）のみWebFetchで補完
- スクリプト実行自体が失敗した場合はStep 1のWebSearchで定量データも取得

**出来高データの注意**: ^N225（日経平均指数）のVolumeはyfinanceで0を返すため、出来高5日平均比（volume_ratio）はETF代替指標（1306.T: TOPIX連動型ETF）から取得する。market_data_quick.pyのvolume_ratioが0.0の場合はセクション内で「N/A」と表示する。

#### Step 0.5: confidence（データ整合性）の定量判定

yfinanceデータを取得後、以下のルールでconfidenceを判定する:

**高（データ整合性が高い）**:
- CMEの方向（前日比の符号）とVIXの方向（VIX上昇なら下落示唆、VIX下落なら上昇示唆）が一致
- かつ VIX < 22
- かつ ドル円の前日比が±0.5%以内

**低（不確実性が高い）**:
- VIX > 28
- または S&P500/NASDAQ/Dowの3指数のうち2つ以上が逆方向（例: S&P上昇だがNASDAQ/Dow下落）
- または 当日に重要経済指標発表（日銀会合、FOMC、雇用統計、CPI等）がある場合

**中（標準）**:
- 上記「高」「低」のいずれにも該当しない場合

**注意**: 最終的なconfidenceはこの定量判定を基本とするが、定性情報（ニュース・地政学リスク等）により1段階調整可能（例: 定量的には「高」だが地政学リスクにより「中」に引き下げ）

**クロスアセットによるconfidence補正:**
- リスクアペタイトが「リスクオン」かつ CMEが上昇 → confidence据え置きまたは1段階引き上げ
- リスクアペタイトが「リスクオフ」かつ CMEが上昇 → 矛盾シグナル → confidence 1段階引き下げ
- 金が前日比+2%超の急騰 → 地政学リスクの可能性 → confidence 1段階引き下げ

### Step 0.7: クロスアセット環境判定（AM/PM共通）

yfinanceデータからクロスアセット環境を判定し、レポートに反映する。

**リスクアペタイト判定:**

以下の5シグナルを統合（各シグナルの前日比方向で判定）:

| # | シグナル | リスクオン条件 | リスクオフ条件 | yfinanceキー |
|---|---------|-------------|-------------|-------------|
| 1 | VIX | 下落 or < 20 | 上昇 and > 25 | vix |
| 2 | 金 | 下落 | 上昇 | gold |
| 3 | 米10年債利回り | 上昇 | 下落 | us10y |
| 4 | イールドカーブ | > 0.5%（スティープ） | < 0%（逆転） | yield_curve.spread_10y3m |
| 5 | ドル円 | 円安（上昇） | 円高（下落） | usdjpy |

- **リスクオン**: 4つ以上がリスクオン → セクター影響マップでシクリカルに追い風
- **リスクオフ**: 4つ以上がリスクオフ → ディフェンシブ・金関連に追い風
- **混合**: その他 → セクター選別が重要

**商品→セクター伝播:**

| 原油(WTI)の動向 | 東証への影響 |
|---------------|------------|
| 上昇（+2%超） | エネルギー・商社セクターに追い風、化学・運輸に逆風 |
| 下落（-2%超） | 化学・運輸・航空に追い風、エネルギー関連に逆風 |
| 小動き（±2%以内） | セクター影響は限定的 |

**イールドカーブ→東証:**

| スプレッド状態 | 東証への示唆 |
|-------------|------------|
| ノーマル（> 1.0%） | 銀行・金融に追い風（利ざや拡大期待） |
| フラット（0〜1.0%） | ディフェンシブ選好（景気減速懸念） |
| 逆転（< 0%） | 全体的にリスクオフ。グロース銘柄に特に注意 |

この判定結果はレポートの「クロスアセット環境」セクション、「セクター影響マップ」、および「因果チェーン」に反映する。

#### Step 0.8: マクロレジーム分類（AM限定）

クロスアセットシグナルからマクロレジームを判定する:

| 判定条件 | レジーム |
|---------|---------|
| S&P500↑ かつ 金利安定(変動<5bp) かつ 原油安定(変動<2%) かつ VIX<20 | ゴルディロックス |
| S&P500↑ かつ 金利↓ かつ 金利水準≤3.5% かつ VIX<28 | 金融相場 |
| S&P500↑ かつ 金利↓ かつ 金利水準>3.5% かつ VIX<28 | 金融相場（引締め環境下） |
| S&P500↑ かつ 金利↑ かつ 原油↑ かつ VIX<28 | リフレ |
| S&P500↓ かつ 金利↓ かつ 原油↓ かつ VIX↑ | デフレ懸念 |
| S&P500↓ かつ 金利↑ かつ 原油↑ かつ VIX↑ | スタグフレーション懸念 |
| 上記いずれにも該当しない | 混合 |

※ 「↑」「↓」は前日比の符号。「安定」は閾値内の変動。
※ 金利水準の閾値（3.5%）は米10年債利回りの歴史的中央値付近。金融相場の判定において、引締め環境下（>3.5%）の金利低下は「利下げ期待」、緩和環境下（≤3.5%）の金利低下は「金融緩和の深化」と解釈する。
※ レジーム判定はクロスアセット環境セクションの「マクロ環境の読み」に反映する。

**バリュエーション参考水準（テンプレート内で参照可）:**
日経平均PER（予想ベース）の目安水準。yfinanceからは直接取得不可のため、以下のガイドラインに基づき定性的に言及する:
- PER 12倍以下: 割安圏（過去のボトム水準）
- PER 12-14倍: やや割安〜適正
- PER 14-16倍: 適正圏
- PER 16-18倍: やや割高
- PER 18倍超: 割高圏（過去のピーク水準）
※ 具体的なPER値はWebSearchで取得可能な場合のみ記載。取得不可時は省略。

### Step 1: WebSearch（定性情報のみ）

**AM（timing=am）**:

| クエリ | 検索文字列 |
|--------|-----------|
| ニュース・テーマ | `日本 経済 マーケット 見通し 重要ニュース {date}` |
| 経済指標カレンダー | `経済指標 発表 カレンダー 今日 {date}` |
| 決算カレンダー | `日本 企業 決算 発表 今週 {date}` |

※ S&P500/NASDAQ/Dow等の定量データはyfinanceで取得済みのためWebSearch不要

**PM（timing=pm）**: WebSearch 2クエリ + WebFetch補完 1クエリ = 合計3

| 種別 | クエリ | 検索文字列 |
|------|--------|-----------|
| WebSearch | 東証結果・ニュース | `日経平均 東証 売買代金 注目ニュース {date}` |
| WebSearch | 需給データ | `東証 信用残 投資部門別売買 需給 {date}` |
| WebFetch | セクター別騰落補完 | yfinanceで不足する場合のみ（下記テーブル参照） |

**セッション別情報の取得**: PM時のWebSearchで前場・後場の値動きの違いが判明した場合、「セッション別の振り返り」セクションに反映する。特に前場と後場で値動きの方向が異なった場合（前場安→後場高等）は、転換の要因を分析すること。

※ TOPIX はyfinance（1306.T ETF）経由で取得。WebSearchは「ニュース + 売買代金」に限定
※ セクター騰落は銀行ETF(1615.T)・IT ETF(1626.T)等のyfinanceデータで代替。詳細セクター別はWebFetch補完

**PM時のWebFetch補完**:

| 不足データ | WebFetch先 | 備考 |
|-----------|-----------|------|
| セクター別騰落 | Yahoo!ファイナンス 業種別株価指数 | yfinanceセクターETFで不足する場合のみ |
| 売買代金 | Yahoo!ファイナンス 市場概況ページ | |

※ データ取得失敗時は該当項目を「N/A」と明示する（値を推測しない）

### コンテキスト節約ルール

処理時間15分以内・コンテキスト消費最小化のため:
- WebSearchは合計6クエリ以内（AM: ニュース1クエリ+経済指標1クエリ+決算1クエリ、PM: 東証結果1クエリ+需給1クエリ+補完1クエリ）
- WebFetchは合計3URL以内（失敗時のみ追加、上限5URL）
- Step 3（注目ETF）のAPI呼び出しはフォールバック含め最大3回
- 同一URLへの再アクセス禁止
- yfinanceで取得済みの数値はWebSearchで再確認しない

### Step 2: portfolioモード時のAPI取得

`{mode}` が `portfolio` の場合のみ:

```bash
curl -s http://localhost:8902/api/v1/demo/portfolio/holdings
```

保有比率上位5銘柄に絞る。API失敗時は `<!-- portfolio取得失敗 -->` を出力末尾に付与。

### Step 3: 注目ETF収集

AM/PM共通:

1. **keyword検索**: `curl -s "http://localhost:8902/api/v1/etfs?keyword={テーマ}&momentum_labels=上昇加速,上昇維持&sort=return_1m&order=desc&limit=5"`
2. **tag_idsフォールバック**: `curl -s "http://localhost:8902/api/v1/tags"` → tag_idで再検索
3. **tag-momentumフォールバック**: `curl -s "http://localhost:8902/api/v1/market/tag-momentum"`
4. **最終フォールバック**: セクション省略

日本株ETF最低1銘柄必須。3-5銘柄を目標。
PM時はStep 3で「今日の注目ETF」と「明日の注目ETF」の両方を収集。

### Step 4: ドラフト生成

output-formats.md のテンプレートに従いドラフトを生成する。

- 出力フォーマット参照: `agent-instructions/output-formats.md`
- timingに応じてAM/PMテンプレートを選択
- modeに応じてポートフォリオセクションを追加/省略
- PM実行時、AMレポートのYAMLフロントマターからprediction全フィールド（direction, confidence, cme_nikkei, range_low, range_high, difficulty）を読み取り、PM「AM予想との比較」セクションおよび「予想精度メタデータ」に反映する
- WebSearchで需給データ（信用残・投資部門別売買）が取得できた場合、PMレポートに「需給環境」セクションを追加
- 取得できなかった場合はセクション省略（`<!-- supply_demand_unavailable -->` コメントを挿入）
- PM時の需給データ（信用残・投資部門別売買）は積極的に取得する。「取得可能時のみ」ではなく、毎回必ずWebSearchで取得を試みること
- 信用倍率の閾値ルール: 5倍超→「過熱警戒」、2倍未満→「需給良好」、2-5倍→「標準」
- AM時にも前週の投資主体別売買データに言及することを推奨（WebSearchで取得可能な場合のみ）

### Step 5: 自己検証チェック（Self-Validation）

ドラフト生成後、以下のチェックリストを全項目確認してから出力すること。1項目でも不合格の場合は修正してから出力する。

#### [A] 数値整合性チェック（最優先）
- [ ] 3行サマリーの日経平均前日比（円・%）が「主要指標サマリー」テーブルの値と一致している
- [ ] 3行サマリーのCME日経先物が「主要指標サマリー」テーブルの値と一致している
- [ ] AMレポートの場合: 本文中の全ての数値が指標テーブルの値と矛盾していない
  - 矛盾発見時: 指標テーブル（yfinance値）を正として3行サマリーを修正する

**[A] 数値整合性チェック（最優先）** の追加ルール:
- 3行サマリーの数値（前日比%等）が「主要指標サマリー」テーブルの値と**小数第2位まで**一致すること
- テクニカル環境セクションの値がmarket_data_quick.pyの出力JSON値と一致すること
- CME日経先物の値がYAMLフロントマターのcme_nikkeiと一致すること
- 為替見通しのレンジがドル円の現在値を含むこと（現在値がレンジ外の場合は修正）

#### [B] YAMLフロントマター必須フィールドチェック（AM限定）
以下のフィールドが全て存在し、適切な値が設定されていることを確認する:
- [ ] `direction`: 上昇|下落|横ばい のいずれか
- [ ] `confidence`: 高|中|低 のいずれか
- [ ] `cme_nikkei`: 整数値
- [ ] `range_low`: ベースシナリオ下限（整数値）
- [ ] `range_high`: ベースシナリオ上限（整数値）
- [ ] `difficulty`: 1-5（整数値）
- [ ] `causal_chain`: 因果チェーン要約（50文字以内の文字列）
- [ ] `key_assumption`: シナリオの核心前提（文字列）
- [ ] `invalidation_signal`: 前提が崩れるシグナル（文字列）
- [ ] `high_volatility`: true/false
- [ ] `crisis_mode`: true/false
欠落フィールドが1つでもある場合は補完してから出力する。

#### [B-PM] YAMLフロントマター必須フィールドチェック（PM限定）
以下のフィールドが全て存在し、適切な値が設定されていることを確認する（AMファイルが不在の場合は乖離関連フィールドをnullとする）:
- [ ] `direction_hit`: true/false/null
- [ ] `range_hit`: true/false/null
- [ ] `cme_deviation`: 整数値またはnull
- [ ] `cme_deviation_pct`: 小数値またはnull
- [ ] `core_premise_hit`: true/false/partial/null
- [ ] `invalidation_triggered`: true/false/null
- [ ] `notes`: 一言評価文字列（空文字不可、最低10文字以上）
欠落フィールドが1つでもある場合は補完してから出力する。

#### [C] セクション存在チェック
**AM限定:**
- [ ] 「本日の市場環境」セクション（不確実性★）が含まれている
- [ ] 「レポート利用ガイド（📖 このレポートの使い方）」が免責事項の直後に含まれている
- [ ] 「シナリオ分析」テーブルに「各シナリオの前提条件と確認指標」が含まれている

**PM限定:**
- [ ] 「AM予想との比較」セクションが含まれている（AMファイル存在時）
- [ ] 「予想精度メタデータ」が含まれている
- [ ] 「明日の注目ETF」セクションが含まれている

**AM/PM共通:**
- [ ] 3行サマリーが総合判断の前に含まれている
- [ ] 注目テーマ/ニュースが3件以上含まれている
- [ ] 注目ETFが3-5銘柄含まれている（日本株ETF最低1銘柄）
- [ ] ソース一覧が含まれている

#### [D] ソース品質チェック
- [ ] 全ソースが当日または過去7営業日以内の記事/データである
- [ ] 年次・月次の見通しレポート（「2026年の日本株見通し」等の汎用レポート）は当日のソースとして**使用しない**
  - 例外: その見通しレポートが当日の相場に直接的な影響を与えたニュースとして取り上げる場合のみ可
- [ ] ソースとして採用する記事は、当日または前営業日に発生した具体的なイベント・データに関するものであること

#### [E] 分析深度チェック
- [ ] **注目テーマ（AM）**: 各テーマに「伝播経路」が明示されている（米国→東証→セクター の形式）
- [ ] **注目ニュース（PM）**: 各ニュースに影響セクターまたはETFが特定されている
- [ ] **AM予想との比較（PM）**: key_assumption と invalidation_signal の検証結果が明示されている
- [ ] **為替見通し（AM）**: 予想レンジの下限・上限それぞれに根拠が記述されている
- [ ] **ETF推薦**: 日本株ETFが最低1銘柄以上含まれている（日本株以外のみの場合は補完する）
- [ ] **需給環境（PM）**: 需給データが取得できた場合、値動きの要因分析に需給要因への言及がある
- [ ] **クロスアセット環境（AM）**: リスクアペタイト判定が記載され、セクター影響マップと整合している
- [ ] **商品市場（AM/PM）**: 原油・金の動向がセクター分析に反映されている（前日比±2%超の場合は必須言及）
- [ ] **イールドカーブ（AM）**: スプレッド状態が記載され、金融セクターへの示唆が含まれている
- [ ] **MACD（AM/PM）**: テクニカル環境テーブルにMACD情報が含まれている（取得成功時）
- [ ] **一目均衡表（AM/PM）**: テクニカル環境テーブルに雲の位置が含まれている（取得成功時）
- [ ] **マクロレジーム（AM）**: マクロレジーム分類がクロスアセット環境セクション内に記載されている
- [ ] **テクニカルシグナル集計（AM/PM）**: テクニカル環境セクションにシグナル集計（強気X/弱気Y/中立Z）が記載されている（取得成功時）
- [ ] **テクニカルシグナルの解釈**: テクニカルシグナル集計を因果チェーンに反映する際、以下の優先度を考慮すること:
  - **高優先度シグナル**: SMAクロス（GC/DC発生時）、一目均衡表三役好転/三役逆転、マルチタイムフレームダイバージェンス
  - **中優先度シグナル**: MACD方向、ボリンジャーバンド極端値（±2σ超）、出来高ダイバージェンス
  - **低優先度シグナル**: RSI方向（50以上/以下の単純判定）
  - 高優先度シグナルが因果チェーンと矛盾する場合は、リスク要因として明示的に言及すること
- [ ] **半導体指標（AM）**: SOX指数の動向がテーマ・セクター分析に反映されている（特に半導体セクターへの言及時に必須）
- [ ] **バリュエーション（AM）**: WebSearchでPER情報が取得できた場合、バリュエーション参考水準への言及がある
- [ ] **SMAクロス（AM/PM）**: テクニカル環境テーブルにSMA25×75クロス判定が含まれている（取得成功時）
- [ ] **一目均衡表5線（AM/PM）**: テクニカル環境テーブルに三役好転/三役逆転の判定が含まれている（取得成功時）
- [ ] **出来高分析（AM/PM）**: テクニカル環境テーブルに出来高ダイバージェンス分析が含まれている（取得成功時）
- [ ] **週足RSI（AM/PM）**: テクニカル環境テーブルに週足RSI(14)が含まれている（取得成功時）
- [ ] **決算カレンダー（AM）**: 決算シーズン中は注目テーマに決算関連テーマが含まれている

## 異常値検出（簡易ルール）

| 指標 | 閾値 | 対応 |
|------|------|------|
| S&P500/NASDAQ/Dow | 前日比±5%超 | 原因を1文添付 |
| 日経平均 | 前日比±3%超 | 高ボラモードフラグ発動（±4%超: 翌日AM反動シナリオ必須） |
| ドル円 | 前日比±2円超 | 原因を1文添付 |
| VIX | 30超 | 高ボラモードフラグ発動 |
| VIX | 35超 | 危機モードフラグ発動 |
| VIX | 50超 | 警戒水準と明記 |

※ 旧正確性チェック（終値確定判定→複数ソースクロスチェック→異常値検出の3段階）は廃止。
yfinance値をそのまま信頼し、異常値のみフラグ。

### 高ボラモード・危機モード判定

以下の条件でモードフラグを設定し、output-formats.md の該当ルールに従う:

| モード | 発動条件 | フラグ |
|--------|---------|--------|
| 高ボラモード | VIX > 30 **または** 日経前日比 > ±3% | `high_volatility: true` |
| 危機モード | VIX > 35 | `crisis_mode: true`（高ボラモードも同時に発動） |
| 反動シナリオ必須 | 前日比 > ±4% | 翌日AMのシナリオ分析に反動シナリオを必ず含める |

**高ボラモード時の追加データ収集**:
- VIX値自体は既にyfinanceで取得済みのため、追加のVIX関連データ取得は不要
- 通常のデータ収集フローで十分（VIX先物タームストラクチャ等の追加取得は行わない）
