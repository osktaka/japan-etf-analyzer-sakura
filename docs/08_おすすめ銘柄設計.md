# おすすめ銘柄設計

## 1. 概要

### 目的
投資家の異なる投資目的や関心に基づいて、最適なETF銘柄を提案する機能を提供する。

### 設計思想
- **統一評価軸**: すべての銘柄を同じ5つの評価軸で評価し、一貫性を確保
- **重み付けモデル**: 切り口（投資目的）に応じて評価軸の重要度を変えることで、異なるニーズに対応
- **透明性**: スコア計算の根拠が明確で、「なぜこの銘柄が選ばれたか」を説明可能
- **拡張性**: 新しい切り口の追加は重み付けを定義するだけで実現可能

### 以前の設計からの変更点
- **タグベースの排除**: 「分散投資」「人気」のようなタグベースの選定を廃止し、すべてスコアリングベースに統一
- **切り口の見直し**: 5つの切り口から6つに拡張（high-dividend → dividend、beginner → stabilityに名称変更、volume/growth/balanceを追加）
- **評価軸の体系化**: バラバラだった指標を5軸に統一し、各軸の正規化方法を明確化

---

## 2. 統一評価軸（5軸）

すべての銘柄を以下の5つの軸で評価します。各軸は0〜1の範囲に正規化され、切り口ごとの重み付けによって総合スコアを算出します。

### 正規化方式（全軸共通）

**パーセンタイル正規化**を採用しています。これにより、以下の利点があります：

- **外れ値に強い**: 極端な値の影響を受けにくい
- **相対的評価**: 候補銘柄全体の中での相対的な順位で評価
- **固定レンジの問題回避**: 信託報酬1%超でもマイナスにならない

**計算方法**:
```python
# 昇順（高いほど良い指標）
rank = 対象値以下の銘柄数
score = (rank - 1) / (全銘柄数 - 1)

# 降順（低いほど良い指標、例: コスト）
score = 1 - (rank - 1) / (全銘柄数 - 1)
```

### 2.1 配当力（Dividend Power）

**定義**: 配当金による収益性を評価する軸

**指標**: `dividend_yield`（配当利回り）

**正規化方法**: パーセンタイル正規化（昇順）
- 配当利回りが高いほどスコアが高い
- 候補銘柄全体の中での相対順位で評価

**データ例**:
- 候補銘柄が10銘柄で、3番目に高い場合: (3-1)/(10-1) = 0.22
- 候補銘柄が10銘柄で、最も高い場合: (10-1)/(10-1) = 1.0

---

### 2.2 コスト効率（Cost Efficiency）

**定義**: 保有コストの低さを評価する軸

**指標**: `expense_ratio`（信託報酬率）

**正規化方法**: パーセンタイル正規化（降順、反転）
- 信託報酬が低いほどスコアが高い
- 1.0%超の銘柄でもマイナスにならない

**データ例**:
- 候補銘柄が10銘柄で、2番目に低い場合: 1 - (2-1)/(10-1) = 0.89
- 候補銘柄が10銘柄で、最も低い場合: 1 - (1-1)/(10-1) = 1.0

---

### 2.3 安定性（Stability）

**定義**: 純資産規模による安定性・信頼性を評価する軸

**指標**: `total_assets`（純資産総額、単位:百万円）

**正規化方法**: パーセンタイル正規化（昇順）
- 純資産が大きいほどスコアが高い
- 候補銘柄全体の中での相対順位で評価

**データ例**:
- 候補銘柄が10銘柄で、5番目に大きい場合: (5-1)/(10-1) = 0.44
- 候補銘柄が10銘柄で、最も大きい場合: (10-1)/(10-1) = 1.0

---

### 2.4 取引規模（Trading Volume）

**定義**: 売買のしやすさを評価する軸

**指標**:
- `trading_value`（売買代金 = 価格 × 平均出来高）- 50%
- `average_volume`（平均出来高、30日移動平均）- 30%
- `deviation_rate`（乖離率の絶対値）- 20%

**正規化方法**: すべてパーセンタイル正規化
- 売買代金・出来高: 昇順（高いほど良い）
- 乖離率: 降順（低いほど良い）
- 加重平均で最終スコア算出

**改善理由**:
- 売買代金を追加することで、価格水準の違いを吸収
- 高額ETFと低額ETFを公平に比較可能

**データ例**:
- 候補10銘柄で、売買代金5位、出来高6位、乖離率3位の場合:
  - 0.5 * 0.44 + 0.3 * 0.56 + 0.2 * 0.78 = 0.55

---

### 2.5 リターン実績（Return Performance）

**定義**: 過去のパフォーマンス実績を評価する軸

**指標**:
- `return_1y`（1年リターン）- 40%
- `return_3y`（3年リターン）- 60%

**正規化方法**: パーセンタイル正規化（昇順）
- リターンが高いほどスコアが高い
- 候補銘柄全体の中での相対順位で評価
- 加重平均で最終スコア算出

**データ例**:
- 候補10銘柄で、1年リターン4位、3年リターン6位の場合:
  - 0.4 * 0.33 + 0.6 * 0.56 = 0.47

## 3. 切り口の定義（6つ）

各切り口は、5つの評価軸に対する重み付けの組み合わせとして定義されます。

### 3.1 配当収入（dividend）

**説明**: 配当利回りが高く、定期的な配当収入を期待できる銘柄

**対象ユーザー**: 配当金による定期収入を重視する投資家

**重み付け**:
| 評価軸 | 重み | 理由 |
|--------|------|------|
| 配当力 | **50%** | 配当利回りが最優先 |
| コスト効率 | 10% | 長期保有を考慮 |
| 安定性 | 20% | 安定配当の裏付け |
| 取引規模 | 10% | 売買のしやすさ |
| リターン実績 | 10% | 参考程度 |

**期待される結果**: 高配当ETF（例: TOPIX高配当40指数、日経高配当50など）が上位

---

### 3.2 低コスト（low-cost）

**説明**: 信託報酬が低く、長期保有でコストを抑えられる銘柄

**対象ユーザー**: 保有コストを最小化したい長期投資家

**重み付け**:
| 評価軸 | 重み | 理由 |
|--------|------|------|
| 配当力 | 10% | 参考程度 |
| コスト効率 | **50%** | 信託報酬が最優先 |
| 安定性 | 20% | 運用の安定性 |
| 取引規模 | 10% | 売買のしやすさ |
| リターン実績 | 10% | 参考程度 |

**期待される結果**: 超低コストETF（例: TOPIXインデックス、日経225インデックスなど）が上位

---

### 3.3 安定性（stability）

**説明**: 純資産規模が大きく、安心して保有できる銘柄

**対象ユーザー**: リスクを抑えたい初心者・保守的な投資家

**重み付け**:
| 評価軸 | 重み | 理由 |
|--------|------|------|
| 配当力 | 10% | 参考程度 |
| コスト効率 | 20% | 長期保有を考慮 |
| 安定性 | **40%** | 純資産規模が最優先 |
| 取引規模 | 20% | 流動性の確保 |
| リターン実績 | 10% | 参考程度 |

**期待される結果**: 大型ETF（例: TOPIX連動型、日経225連動型など）が上位

---

### 3.4 取引規模（volume）

**説明**: 出来高が多く、売買が成立しやすい銘柄

**対象ユーザー**: 流動性を重視する短期トレーダー・アクティブ投資家

**重み付け**:
| 評価軸 | 重み | 理由 |
|--------|------|------|
| 配当力 | 10% | 参考程度 |
| コスト効率 | 10% | 参考程度 |
| 安定性 | 20% | 市場での信頼性 |
| 取引規模 | **50%** | 出来高・流動性が最優先 |
| リターン実績 | 10% | 参考程度 |

**期待される結果**: 取引量の多い主要ETF（例: 日経レバレッジ、日経ダブルインバースなど）が上位

---

### 3.5 成長性（growth）

**説明**: 過去の値上がり実績が良好な銘柄

**対象ユーザー**: キャピタルゲインを重視する成長志向の投資家

**重み付け**:
| 評価軸 | 重み | 理由 |
|--------|------|------|
| 配当力 | 10% | 参考程度 |
| コスト効率 | 10% | 長期保有を考慮 |
| 安定性 | 20% | 運用の安定性 |
| 取引規模 | 10% | 売買のしやすさ |
| リターン実績 | **50%** | 過去リターンが最優先 |

**期待される結果**: 高リターンETF（例: グロース株指数、テーマ型ETFなど）が上位

**注意**: UIで「過去の実績は将来を保証しません」の注意書きを表示推奨

---

### 3.6 バランス（balance）

**説明**: 複数の観点でバランス良く評価された銘柄

**対象ユーザー**: 特定の軸に偏らず、総合的に優れた銘柄を探している投資家

**重み付け**:
| 評価軸 | 重み | 理由 |
|--------|------|------|
| 配当力 | 20% | 均等配分 |
| コスト効率 | 20% | 均等配分 |
| 安定性 | 20% | 均等配分 |
| 取引規模 | 20% | 均等配分 |
| リターン実績 | 20% | 均等配分 |

**期待される結果**: 総合力の高いETF（例: 主要インデックス連動型など）が上位

## 4. 評価ロジックの詳細

### 4.1 スコア計算式

各銘柄の総合スコアは以下の式で計算されます:

```
total_score = Σ(normalized_score_i × weight_i) / Σ(weight_i) × 100
```

ここで:
- `normalized_score_i`: 各評価軸の正規化スコア（0〜1）
- `weight_i`: 切り口ごとの重み（0〜1）
- 総合スコアは0〜100の範囲に正規化

### 4.2 データ不足時の対応

**最小データ要件**:
- 5軸中3軸以上のデータがある銘柄のみ評価対象とする
- 3軸未満の銘柄はスコア0を返す（おすすめから除外）

**Partial Scoring（部分スコアリング）**:
- 各評価軸でデータが取得できない場合、その軸はスコア計算から除外
- 除外された軸の重みを除いた合計で正規化
- 例: 配当力のデータがない場合（4軸）、残り4軸で計算し、それぞれの重みの合計で割る
- 3軸以上あればスコア計算を実行、2軸以下は除外

**除外の理由**:
- データが少ない銘柄は評価の信頼性が低い
- 1-2軸のみで高スコアになることを防ぐ

### 4.3 足切りルール（除外条件）

推薦対象から除外する銘柄の基準:

| 除外条件 | 理由 | 判定方法 |
|---------|------|---------|
| レバレッジ/インバースETF | 日次リバランスリスク、初心者向けでない | 銘柄名に「レバレッジ」「インバース」「ダブル」「ベア」「2倍」「-2倍」を含む |
| AUM 1億円未満 | 繰上償還リスク | `total_assets < 100,000,000` |

**除外キーワード**:
- レバレッジ
- インバース
- ダブル
- ベア
- 2倍
- -2倍

**足切りタイミング**: スコア計算前に除外（計算効率化）

### 4.4 候補銘柄の絞り込み

スコアリング対象を効率化するため、切り口ごとに事前絞り込みを実施:

| 切り口 | 絞り込み条件 |
|--------|-------------|
| dividend | 配当利回りがNULLでない銘柄 |
| low-cost | 信託報酬がNULLでない銘柄 |
| stability | 純資産総額が上位の銘柄 |
| volume | 平均出来高が上位の銘柄 |
| growth | リターンデータがある銘柄 |
| balance | 全銘柄（フィルタなし） |

**処理順序**:
1. 足切りルール適用（レバ/インバース、AUM下限）
2. 切り口別の絞り込み
3. スコア計算
4. 上位N件を抽出

### 4.5 正規化の根拠

**パーセンタイル正規化の採用理由**:

従来の固定レンジ正規化には以下の問題がありました:
- コスト効率: `1.0 - ratio/1.0` → 信託報酬1%超でマイナスになる
- 配当力: `yield/10.0` → 10%上限は恣意的
- 相場環境変化に弱い（固定レンジが実態と乖離）

パーセンタイル正規化により:
- 候補銘柄全体の相対的な順位で評価
- 極端な値（外れ値）の影響を受けにくい
- 固定レンジの恣意性を排除
- すべての値域で正常にスコア計算可能

**母集団の統一**:
- スコア計算は常に**全ETFを母集団**として実施
- ページネーション前の全データでパーセンタイルを算出
- これにより、表示ページに関わらず同じETFは同じスコアになる

## 5. 実装の詳細

### 5.1 データ要件

**必要なデータ**:
- ETFマスタデータ: `code`, `name`, `dividend_yield`, `expense_ratio`, `total_assets`, `deviation_rate`
- パフォーマンスデータ: `return_1y`, `return_3y`（performance_cacheテーブル）
- 出来高データ: `average_volume`（新規追加が必要）

**データ更新頻度**:
- ETFマスタ（市場価格）: 日次（Yahoo Finance APIから取得、update_etf_data.py）
- 配当利回り: 日次（みんかぶスクレイピング、sync_dividend_from_minkabu.py）
- パフォーマンスデータ: 日次（既存のsync_performance.pyで対応）
- 出来高データ: 日次（新規スクリプトが必要）

### 5.2 モジュール構成

```
backend/src/services/
├── scoring_service.py      # 5軸評価 + 重み付けロジック
└── recommend_service.py    # 切り口定義 + おすすめ取得

backend/src/repositories/
└── etf_repository.py       # 出来高・リターン取得メソッド追加
```

### 5.3 API仕様

**エンドポイント**: `GET /api/v1/recommend?perspective={perspective_id}`

**レスポンス例**:
```json
{
  "perspective": {
    "id": "dividend",
    "name": "配当収入",
    "description": "配当利回りが高く、定期的な配当収入を期待できる銘柄"
  },
  "items": [
    {
      "code": "1489",
      "name": "NEXT FUNDS 日経平均高配当株50指数連動型ETF",
      "dividend_yield": 4.5,
      "expense_ratio": 0.32,
      "total_assets": 245000,
      "score": 78.5
    }
  ]
}
```
