# メール通知仕様

## 概要

Daily Advisor は ETF ポートフォリオの運用判断を支援するメール通知を 3 種類（+ 緊急アラート 1 種）送信する。
本ドキュメントは件名・本文の仕様、モバイル最適化ルール、用語翻訳、テスト戦略を一元管理する。
バッチスケジュール・依存関係は [`10_バッチ処理設計.md`](10_バッチ処理設計.md) を参照。

### Daily Advisor 3 種メール（+ alert）

| kind      | 配信タイミング       | 目的                                                |
| --------- | -------------------- | --------------------------------------------------- |
| morning   | 平日 07:00           | **寄り付き前のアクション提示**。米国 overnight 市況サマリ＋前夜決定事項リマインダー＋機械ルール＋次回リバランス基準日カウントダウン |
| evening   | 平日 17:30           | **終値ベースの完全状態確認＋翌営業日の発注材料**。A群/B群/現金配分サマリ＋銘柄別目標配分＋採用外保有＋売却/買付プラン |
| weekly    | 金曜 18:00           | 5 営業日のα・ベンチマーク比較と来週の推奨アクション |
| alert     | 9:00–15:00 平日 5 分間隔 | 機械ルール（損切・利確・N225急落・配分逸脱）即時通知（緊急アラート） |

**2026-05-14 改修**: 旧 `rebalance` kind（07:15配信）を廃止し、morning kind に統合した。

**2026-05-14（朝/夕構成リバランス）**: 配分・乖離・銘柄別目標・リバランス計画は「終値が確定して初めて正確な現状」になるため、これらをすべて evening kind に集約した。morning kind は寄り付き前の判断材料（米国 overnight・前夜決定事項リマインダー）に再定義され、銘柄別配分テーブル・採用外保有詳細・本日リバランス実行案内は morning から削除した。意思決定サイクルを「夕方で判断 → 朝で確認・実行」に整流化する。

### 文体方針: アナリスト視点

「機械的な数値羅列」ではなく「結論先出し → 文脈 → 根拠」のアナリストレポート文体で記述する。
リード文 `summary` は以下の 3 層構造を維持する。

1. **結論**: 今日（本日／今週）何をすべきか／通常運用継続か
2. **文脈**: 前日比・月初比・α・配分状態などの数値
3. **根拠**: critical 発動の戦略書条項 or 配分逸脱の警告閾値超過 pp

静観時も「特になし。通常運用継続」を明示し、ノーニュースもニュースとして扱う。

## 件名フォーマット

`SUBJECT_MAX_LEN = 40` 文字を目安にし、超過時は `notification_renderer` から WARNING ログを出して末尾を「…」に切り詰める。`user_id` は件名に含めない。

morning / evening は **kind プレフィックス（`【寄り付き前】` / `【終値ベース】`）＋ `Daily Advisor / M/D` ＋ 補足** の構造を採用する（朝/夕構成リバランスに伴うアイデンティティ明示）。weekly / alert は従来の `[M/D 区分] 結論` 形式を維持する。

| kind      | 静観時                                          | アクション/警告時                                          | 例外（複数件数時）                                                  |
| --------- | ----------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| morning   | `【寄り付き前】Daily Advisor / 4/30`            | `【寄り付き前】Daily Advisor / 4/30 リバランス売2買3`      | `【寄り付き前】Daily Advisor / 4/30 逸脱2件` / `... / 6/30 緊急`    |
| evening   | `【終値ベース】Daily Advisor / 4/29 -0.3%`      | `【終値ベース】Daily Advisor / 4/29 -1.2% 逸脱2件`         | `【終値ベース】Daily Advisor / 4/29 緊急`                           |
| weekly    | `[5/1 週次] α -1.0pp`                           | `[5/1 週次] α -3.0pp / 来週1件`                            | —                                                                   |
| alert     | —（trigger 0 件は通常配送なし）                 | `[4/29 緊急] 損切到達: 1306` / `[4/29 要確認] N225急落`    | `[4/29 緊急] 機械ルール3件発動`                                     |

実装は `backend/src/services/notification_renderer.py` の `subject_for()` および
`_subject_morning / _subject_evening / _subject_weekly / _subject_alert` を参照。
件名が `SUBJECT_MAX_LEN`（40 文字）を超えた場合は WARNING ログを出し、末尾を「…」に切り詰める。

## 本文構造（4 種共通）

すべて「結論 → 文脈 → 根拠」の 3 層を踏襲する。

| kind      | セクション順序                                                                                                       |
| --------- | -------------------------------------------------------------------------------------------------------------------- |
| morning   | 結論ボックス（寄り付き前のアクション提示・基準日カウントダウン）→ 文脈（前日比・月初比・現金比率・個別逸脱件数）→ **overnight 市況サマリ**（S&P500/NASDAQ/DOW/USDJPY/VIX/日経先物 NKD=F、`{% if overnight %}` でガード）→ **前夜決定事項リマインダー**（売却/買付件数＋top3、`{% if previous_evening_summary %}` でガード）→ 機械ルール → 戦略書フッター |
| evening   | 結論ボックス → 本日の市場文脈（前日比・月初比・現金比率）→ **配分サマリ**（A群/B群/現金 3行、`is_warn` バッジ）→ **採用銘柄配分テーブル**（8銘柄＋現金10%、乖離 pp 付き、`rebalance_plan` 有時のみ）→ **採用外保有**（次回リバランスで全量売却推奨）→ **本日リバランス実行 or 次回基準日への売却/買付プラン**（`is_rebalance_day` で分岐）→ 機械ルール → 戦略書フッター |
| weekly    | 結論ボックス（α + 配分逸脱件数）→ 5 営業日サマリ → 配分カテゴリ別（A群/B群/現金） → 採用外保有（あれば） → 来週の推奨アクション → 今週の機械ルール → 戦略書フッター |
| alert     | severity 別カラー結論ボックス（赤=critical / 黄=warn / 青=info）→ 各 trigger（推奨アクション・メッセージ・payload 縦並び）→ 戦略書フッター |

### morning kind: 寄り付き前のアクション提示（2026-05-14 朝/夕構成リバランス）

**役割**: 米国 overnight・前夜決定事項リマインダーを軽量提示し、寄り付き前に「今日は実行日か、通常運用か」を判断させる。銘柄別配分テーブル・売買プラン本体は前夜の evening kind に集約済みのため、morning は概要と誘導に専念する。

- **結論ボックス**: `rebalance_plan.is_rebalance_day=True` の場合「本日は四半期末リバランス基準日。詳細配分・売買計画は前夜の夕方レポート参照」、それ以外は「本日は通常運用日（次回リバランス `next_rebalance_date` まで `days_to_next_rebalance` 日）。詳細配分・売買計画は前夜の夕方レポート参照」を表示
- **overnight 市況サマリ**: `context.overnight`（dict）の各キー（`sp500` / `nasdaq` / `dow` / `usdjpy` / `vix` / `nikkei_futures`）を `_macros.j2:overnight_line_md / overnight_row_html` で 1 行ずつレンダリング。終値＋前日比%（VIX のみ change pt も併記）。取得失敗時は **当該セクションのみ skip**（本体メールは送信継続）
- **前夜決定事項リマインダー**: `context.previous_evening_summary`（dict）から `is_rebalance_day` / `sell_actions_count` / `buy_actions_count` / `sell_top3` / `buy_top3` を読み、簡潔に 1〜3 行で表示。JSON 欠落時は **当該セクションのみ skip**
- **次回リバランス基準日カウントダウン**: 結論ボックス末尾の補足として表示（`rebalance_plan.next_rebalance_date` / `days_to_next_rebalance` 参照）
- **削除されたセクション（旧 morning から evening に移管）**: 「採用銘柄配分テーブル（8銘柄＋現金）」「採用外保有詳細」「本日リバランス実行」
- 実装（context）: `backend/src/services/daily_advisor_contexts.py:build_morning_context()`
- バッチ: `backend/scripts/daily_advisor_morning.py`（07:00 JST 平日、`CRON_BATCH_PROFILE=dev` 限定）

### evening kind: 終値ベースの完全状態確認＋翌営業日の発注材料（2026-05-14 朝/夕構成リバランス）

**役割**: 終値が確定して初めて正確になる「銘柄別目標配分・採用外保有・リバランス売却/買付プラン」をすべて夕方に集約する。翌営業日の発注材料を完備した「判断完了レポート」として機能する。

- **配分サマリ（A群/B群/現金 3行）**: `allocation_drifts` から `bucket != "other"` をフィルタして表示（`is_warn` バッジ付き、現状維持）
- **採用銘柄配分テーブル**（**新規移管**）: `rebalance_plan.holdings_snapshots` から 8 銘柄＋現金の `target_pct / actual_pct / drift_pp / status` を表示。`_macros.j2:holdings_table_md / holdings_table_html` を再利用
- **採用外保有**（**新規移管**）: `rebalance_plan.holdings_snapshots | rejectattr("is_adopted")` で抽出し、`_macros.j2:non_adopted_md / non_adopted_html` で「次回リバランスで全量売却推奨」を提示
- **売買プラン概要**（**常時表示・2026-05-XX 段階表示再構成**）: 件数（売却 X 件 / 買付 Y 件）＋次回基準日カウントダウン＋主な売却/買付候補 **top3**（金額降順）。実装は `_macros.j2:trade_summary_md / trade_summary_html`。朝メールの「前夜決定事項リマインダー」と同等の見た目で、夕方は「確定情報」のニュアンスを見出しで示す
  - **表示閾値フィルタ（2026-05-20 追加）**: `DISPLAY_THRESHOLD_PP = 2.0`（pp）未満の採用済み銘柄は **top3 と件数の両方から除外**する。閾値は `backend/src/services/daily_advisor_service.py:DISPLAY_THRESHOLD_PP`、フィルタ関数は同モジュールの `filter_actions_for_display()`。`HoldingSnapshot.drift_pp` の絶対値で判定し、端数調整レベルの取引を概要から外して「今、本当にやるべき売買」を識別しやすくする
  - **採用外保有はスルー**: `HoldingSnapshot.is_adopted=False` の銘柄の sell アクションは閾値に関わらず常に top3 に表示（戦略違反のため）
  - **snapshot 欠落時のフォールバック**: `holdings_snapshots` に該当 code が無いアクションは「判定不能」とみなし、保守的に通過させる
  - **「該当なし」表示**: 閾値を満たす候補が0件の場合は、`主な売却候補` / `主な買付候補` セクション内に **「該当なし」を1行のみ表示**（閾値値は本文に出さない）。両方0件かつフィルタ前も0件のときは末尾に「売買アクションなし（次回基準日まで通常運用）。」を維持
- **売買プラン詳細表**（**条件付き表示・2026-05-XX 段階表示再構成**）: `rebalance_plan.is_rebalance_day` が True、または `rebalance_plan.days_to_next_rebalance <= REBALANCE_DETAIL_THRESHOLD_DAYS`（=3）の場合のみ表示。`is_rebalance_day=True` のときは「本日のリバランス実行」、それ以外は「次回基準日への売却/買付プラン（詳細）」を見出しに表示。本体は `_macros.j2:trade_actions_md / trade_actions_html` で `sell_actions` / `buy_actions` を全件一覧化。閾値ソース: `backend/src/services/daily_advisor_contexts.py:REBALANCE_DETAIL_THRESHOLD_DAYS`
  - **詳細表は `DISPLAY_THRESHOLD_PP` を適用しない**: 発注対象は端数も含めて忠実に提示する必要があるため、概要セクションの top3 とは異なり全件表示する（混同防止）
- **rebalance_plan が None の場合**: `allocation_drifts` の `other` バケットがあれば簡易採用外行のみ表示する fallback ロジックを維持
- 実装（context）: `backend/src/services/daily_advisor_contexts.py:build_evening_context()`
- top3 共通化: `backend/src/services/daily_advisor_service.py:compute_top_n_actions()`（夕方サマリ JSON ＝ `_persist_evening_summary` と同関数を使用）
- バッチ: `backend/scripts/daily_advisor_evening.py`（17:30 JST 平日、`update_etf_data` 16:00 後、`CRON_BATCH_PROFILE=dev` 限定）

### 共通リバランス計算仕様

- **目標配分**: A群（1655=15% / 314A=15% / 1629=15%）+ B群（1615=10.00% / 2646=10.00% / 1618=10.00% / 200A=10.00%）+ 現金=15%。合計 100.00%（SSOT: `docs/12_personal_strategy.md`）
- **次回リバランス基準日**: 3/6/9/12 月の最終営業日（`jpholiday` で土日・祝日を除外）。当日が基準日ならその日を返す
- **逸脱閾値**: `OK`（< ±`drift_ok_pp`pp） / `WARN`（±`drift_ok_pp` 〜 `drift_warn_pp`pp） / `CRITICAL`（≥ ±`drift_warn_pp`pp）。閾値は `mechanical_rules.drift_ok_pp` / `mechanical_rules.drift_warn_pp` から取得（既定 3.0 / 5.0）。採用外保有銘柄は常に `CRITICAL` 扱い
- **アクション算出**: `floor((目標金額 - 現在評価額) / 当日close)`。単元未満は次回繰越。採用外は全量売却
- **結論ボックスの色分け**: 通常日は青系（`#f7f9fc`）、四半期末リバランス基準日は黄系（`#fff8e1`）で「本日実行」を強調
- 実装: `backend/src/services/portfolio_rebalance_service.py:calculate_rebalance_plan()`（strategy DI 駆動）

### 取得失敗時の挙動（fail-soft）

| 失敗箇所 | 影響セクション | 本体メール |
|---------|--------------|-----------|
| overnight 取得失敗（yfinance 不通 等） | morning の overnight 市況サマリ | **送信継続**（該当セクション skip、warning ログ） |
| 前夜サマリ JSON 欠落（マシン停止・evening 失敗等） | morning の前夜決定事項リマインダー | **送信継続**（該当セクション skip、warning ログ） |
| evening のリバランス計算失敗 | evening の銘柄別配分・採用外詳細・売買プラン | **送信継続**（該当セクション skip、fallback の `allocation_drifts` 表示） |

### 永続化ファイル: 前夜サマリ JSON（evening → 翌朝の morning に橋渡し）

| 項目 | 内容 |
|------|------|
| パス | `reports/test/daily-tasks/evening_summary_YYYYMMDD.json`（test ユーザーのみ生成） |
| 生成元 | `backend/scripts/_shared/advisor_runner.py:_persist_evening_summary()`（evening 実行時の末尾） |
| 読込元 | `backend/scripts/_shared/advisor_runner.py:_load_previous_evening_summary()`（morning 実行時、当日 → 直近営業日まで最大 5 日前まで遡って fallback） |
| 失敗時の挙動 | 書込失敗・読込失敗いずれも warning ログのみ。メール本体は送信継続（前夜リマインダーは skip） |

**スキーマ**:

```json
{
  "date": "2026-05-16",
  "is_rebalance_day": false,
  "next_rebalance_date": "2026-06-30",
  "days_to_next_rebalance": 45,
  "sell_actions_count": 2,
  "buy_actions_count": 3,
  "sell_top3": [
    {"etf_code": "1306", "name": "TOPIX連動型上場投信", "amount": 45000}
  ],
  "buy_top3": [
    {"etf_code": "1547", "name": "iシェアーズ S&P500 米国株 ETF", "amount": 60000}
  ]
}
```

- `sell_top3` / `buy_top3` は **表示用フィルタ（`DISPLAY_THRESHOLD_PP=2.0`）適用後の金額降順上位 3 件**（2026-05-20〜）。採用済み `|drift_pp| < 2.0pp` の銘柄は除外され、採用外保有 (`is_adopted=False`) の sell アクションは閾値スルーで残る。金額は `int(round(action.amount))`（円）
- `sell_actions_count` / `buy_actions_count` も**フィルタ後のアクション件数**で永続化される（top3 と件数表示を一致させるため）。フィルタ前の全件カウントとは異なるので注意
- name は `rebalance_plan.holdings_snapshots` から逆引きし、欠落時は `etf_code` をそのまま表示
- 翌朝の morning が読み込んだ際、`sell_top3` / `buy_top3` が空配列のときは「該当なし」と表示される（前夜決定事項リマインダーセクション）

Markdown 版はスタイル不適用のため文体のみ統一し、装飾はしない（モバイル対応対象外）。

## モバイル対応 CSS ルール（HTML のみ）

Gmail iOS / Gmail Web / Apple Mail を主要ターゲットとする。
ダークモード対応は Gmail で実質無視されるためスキップする。

### 必須ルール

- `<meta name="viewport" content="width=device-width, initial-scale=1.0">` 設定必須
- `<meta name="x-apple-disable-message-reformatting">` で iOS 自動リフロー抑止
- レイアウトは 1 カラム、`<table>` 禁止
- `<div style="max-width:600px;margin:0 auto;padding:16px;">` を root コンテナに使用
- 「ラベル + 値」の並びは `<dl><dt><dd>` または `<p>` で縦並び
- フォントは最低 14px（推奨 16px）、`line-height:1.6`
- 配色固定: `background:#fff` / `color:#222`
- リンクのタップ領域は `padding:12px 16px;display:inline-block;`（44px 相当）
- CSS は全インライン、外部 CSS / `<font>` タグ禁止

### 結論ボックス

- 通常運用: `background:#f7f9fc;border-left:4px solid #2c5aa0;`
- alert critical: 赤系 `#fdecec / #c0392b`
- alert warn: 黄系 `#fff8e1 / #c79100`
- alert info: 青系 `#e7f1fb / #2c5aa0`

### evening 銘柄テーブル・リバランスプラン追加に伴う方針（2026-05-14）

夕方メールに「採用銘柄配分テーブル（8銘柄＋現金）」「採用外保有」「売却/買付プラン」を新規移管したため、モバイル幅（〜375px）で破綻しないよう以下を遵守する。

- **テーブルは `<table>` ではなく `<dl><dt><dd>`** または `<div>` ベースの縦並びカードに統一（既存の `_macros.j2:holdings_table_html` 系を継続使用し、列が多くなる場合は折り返し）
- **フォントサイズ**: テーブル/カード内も最低 13px を維持。本文 14px との差は 1px までに留める
- **数値桁あふれ対策**: 銘柄名は `name` フィールドを 12 文字程度で切り詰める運用は **行わない**（モバイルでも改行で表示）。代わりに `etf_code` を先頭に置いてグリッパビリティを確保
- **改行戦略**: 1 行 1 銘柄（`etf_code` + name + target_pct + drift_pp + status）でセル内改行を許容。`word-break:break-all` は使わず、CJK 自然改行に任せる
- **morning は変更なし**: overnight サマリと前夜リマインダーは元々短文の縦並びで、追加 CSS 不要

### morning overnight サマリの数値表示

- 各銘柄行は `name`／終値／前日比% の 3 要素のみ（VIX のみ change pt 併記）
- 数値は `±0.00%` で固定桁数。前日比 0% でも明示
- 取得失敗（None）の銘柄は 1 行 skip（セクションごと skip ではなく、行レベルで欠落）

詳細スタイルは `backend/src/services/templates/advisor/*.html.j2` のインライン CSS を参照。

### bucket（アロケーションのカテゴリ）

## ETF Rating 通知（終値ベース日次）

Daily Advisor 系（morning/evening/weekly/alert）・demo ポートフォリオ通知とは独立した、`/etf-rating` スキル専用の評価レポートメール。
target_holdings + watchlist の全銘柄を上昇10×下落10で採点し、Top5重み×2 を適用したネット中期スコア・3シナリオ・銘柄別フル詳細を1通に集約する。
評価フレーム・観点 YAML・採点履歴の詳細は [`13_銘柄評価設計.md`](13_銘柄評価設計.md) を参照。

### 概要

| 項目 | 内容 |
| ---- | ---- |
| 目的 | 個別銘柄の「現在の市場情勢への中期マッチ度」を毎営業日に定量化し、保有/買い増し/縮小の判断材料を提供する |
| 送信タイミング | 月-木 18:00 JST（evening 17:30 完了の30分後）／金 18:15 JST（weekly 18:00 完了の15分後、並列回避） |
| トリガー | `scripts/cron-etf-rating-daily.sh` → Claude CLI (`/etf-rating all --send-mail`) → Phase 3 で `reports/etf-rating/_payloads/{YYYYMMDD}_email_payload.json` 生成 → Bash 経由で `backend/scripts/etf_rating_send_mail.py --payload /app/reports/etf-rating/_payloads/{YYYYMMDD}_email_payload.json` 起動 |
| 宛先 | `NOTIFY_TO_EMAIL`（Daily Advisor 系と共有） |
| 実装 | `backend/src/services/etf_rating_notifier.py` |
| 送信スクリプト | `backend/scripts/etf_rating_send_mail.py`（`BaseBatchScript` 継承） |
| テンプレート | `backend/src/services/templates/etf_rating/{_macros,rating.md,rating.html}.j2` |

### 制御環境変数

| 環境変数 | 値 | 動作 |
| -------- | -- | ---- |
| `ETF_RATING_MAIL_ENABLED` | `0`（既定） | 送信しない（フェイルセーフ）。レポート生成と `email_payload.json` 作成は実行 |
| `ETF_RATING_MAIL_ENABLED` | `1` | 実送信を有効化 |
| `ETF_RATING_NONINTERACTIVE` | `1` | `--send-mail` と同等の自動実行モード（AskUserQuestion スキップ・既定選択肢採用） |

### 件名フォーマット

`SUBJECT_MAX_LEN = 40` 文字を上限とする（`calc_params.json` の `mail.subject_max_chars`）。
超過時は末尾を「…」に切り詰める（`etf_rating_notifier._truncate_subject()`）。

**標準フォーマット**（人が読みやすい "／" 区切り）:

```
[M/D ETF Rating] N銘柄 平均X.X点／強い追い風 K銘柄／警戒 W銘柄
```

| 状況 | 例 | 字数 |
| ---- | ---- | ---- |
| 通常（追い風のみ） | `[5/22 ETF Rating] 7銘柄 平均65.7点／強い追い風 5銘柄` | 35字 |
| 警戒併発 | `[5/22 ETF Rating] 8銘柄 平均48.3点／警戒 2銘柄` | 32字 |
| 強・警ゼロ | `[5/22 ETF Rating] 7銘柄 平均58.2点` | 25字 |

**集計ルール（最重要）**:

- 「強い追い風 K銘柄」「警戒 W銘柄」は **`payload.flags` リストの `type` 値で集計**
  - `type ∈ {strong_tailwind, strong_bullish}` → 強い追い風カウント
  - `type ∈ {severe_risk, critical_risk, warning}` → 警戒カウント
- ゼロ件のセクションは件名から省略（"強い追い風 0銘柄" は出さない）
- 平均ネット = `ratings[].net_score` の単純平均（小数1位）

**重要**: `payload.subject` に固定文字列が入っていても、**notifier 側で `flags` リストから常に再集計して件名を構築し直す**。
2026-05-22 のフル実行で `payload.subject` が `[5/22 ETF-Rating] N=7 平均65.7 強0警0` 固定文字列となるバグ（flags リストには strong_tailwind が5件あるのに「強0」と表示）が発生したため、件名生成の SSOT を
`etf_rating_notifier._build_subject()` に集約した（`payload.subject` は無視される）。

**短縮ルール**（40字超過時、notifier 側で段階適用）:

1. `"ETF Rating"` → `"ETF R"` に短縮: `[5/22 ETF R] 7銘柄 平均65.7点／強い追い風 5銘柄`
2. 末尾の警戒部を落とす
3. フラグ件数全体を省略: `[5/22 ETF R] 7銘柄 平均65.7点`
4. それでも超過する場合は末尾を「…」で切り詰める

### 本文構造（7セクション）

新フォーマットは **冒頭サマリ → 全銘柄スコア一覧 → 市場環境 → 銘柄別ブロック → フッタ** の順。
各銘柄ブロックは「ひとこと／Top5／リスク／3シナリオ」の4部構成とし、生の20項目スコア表は
各銘柄末尾の `<details>` 折りたたみ内に **1行サマリ** で格納する。

| # | セクション | 内容 | 折りたたみ |
|---|-----------|------|-----------|
| 1 | ヘッダ | 「M月D日 終値ベース ETF Rating レポートです」+ 採点ルール3行（100点満点・50点中立・70以上で強い追い風・30以下で警戒） | なし |
| 2 | 今日のひとこと | Phase 2 の300字総評（`payload.summary_text`）。市場局面ラベル含む | なし |
| 3 | 全銘柄スコア一覧 | 銘柄ごとに `銘柄/総合点/追い風/逆風/前日比/判定` の表。末尾に「平均X点／強い追い風 K銘柄／警戒 W銘柄」 | なし |
| 4 | いまの市場環境 | 為替・金利・コモディティ・地政学（`market_snapshot.summary_lines` 5件程度） | なし |
| 5 | 銘柄別ブロック | 各銘柄を「ひとこと／Top5（追い風の主役）／気をつけるべきリスク／3ヶ月の見通し（3シナリオ）」の4部で表示 | 各銘柄末尾 `<details>` で20項目スコアを1行サマリ |
| 6 | 観点鮮度の警告 | `criteria_warnings` がある場合のみ | なし |
| 7 | フッタ | 次回 tune 推奨日、送信時刻 | なし |

#### 文体ガイド

- **です・ます調**（必須）。ただし **尊敬語・謙譲語は使わない**（「いたします」「させていただきます」は禁止）
- 専門用語は日本語に言い換える:
  - `strong_bullish` / `strong_tailwind` → 「強い追い風」
  - `severe_risk` / `critical_risk` / `warning` → 「警戒」「重大警戒」
  - `top5_drivers` → 「Top5（追い風の主役）」
  - `top5_risk_drivers` → 「気をつけるべきリスク」
  - NIM → 「利ザヤ」
  - PBR → 「割安感（PBR）」または「PBR」を残し補足
  - 「下落W」「上昇W」「ネット中期スコア」など内部スコア名は表内のみ使用、本文中は使わない
- 数値密度を下げる: 文章中に必要な数値だけ自然に埋め込む。一覧表は冒頭の銘柄スコア一覧と詳細セクション（`<details>` 内）のみ

### HTML 版モバイル最適化

Daily Advisor 系（[モバイル対応 CSS ルール](#モバイル対応-css-ルールhtml-のみ)）と同じ方針を踏襲。追加方針:

- **初版から `<100KB` 厳守**: 各銘柄詳細は **生成時から「ひとこと＋Top5＋リスク＋3シナリオ」のみに絞る**。生の20項目スコア表（A-1〜B-10）は `<details>` 内に格納するが、各項目は **1行サマリ** に圧縮する。これにより後付け縮約フローを不要化（2026-05-22 の運用で初版260KB→縮約87KBの工程を経験したため、生成時点での縮約を仕様化）
- **`<details>` 折りたたみ**: 銘柄詳細の20項目スコアのみを折りたたみ対象とする。4部構成の本文（ひとこと／Top5／リスク／3シナリオ）は常時展開
- **`<div style="max-width:600px;margin:0 auto;padding:16px;">`** を root コンテナに使用
- **HTML サイズ監視**: `calc_params.json` の `mail.html_size_warn_kb=90` / `mail.html_size_error_kb=100` で監視。超過時は Phase 3 が自動追加縮約（`detail_summary_lines` を Top3 のみ → ランキング上位3件に削減 → `oversized: true` フラグ）
- **Outlook / iOS Mail 互換性**: `<details>` が非対応の場合は折りたたみが効かず全展開になるが、本文表示は維持される（YAGNI 方針）
- **CSS 全インライン**: 外部 CSS・`<font>` タグ禁止

### fail-soft 方針

| 失敗箇所 | 影響 | 本体 |
| -------- | ---- | ---- |
| Phase 0（市場スナップショット）失敗 | サマリ表の「市場局面」ラベルが「不明」表記 | **送信継続**（Phase 1 は個別検索で代替） |
| Phase 1 一部銘柄失敗 | 該当銘柄を「データ取得不可」マークでサマリに含める | **送信継続**（他銘柄は正常） |
| Phase 1 全銘柄失敗 | メール送信スキップ | スキル全体を exit 1 で中止 |
| `criteria/{code}.yaml` 欠損 | 該当銘柄スキップ・サマリに警告 | **送信継続** |
| SMTP 例外（接続失敗 等） | `etf_rating_notifier.send()` 内で捕捉、戻り値 False | **バッチ exit 0**（cron 全体を止めない、WARN ログのみ） |
| `email_payload.json` 不正 | `_load_payload()` が None を返す | **バッチ exit 1**（payload 自体が壊れている場合のみ失敗扱い） |
| HTML サイズ 100KB 超 | Phase 3 が自動縮約 → `oversized: true` フラグ | **送信継続**（縮約後本文を送信） |

## デモユーザー向けポートフォリオ変更通知

Daily Advisor 系（morning/evening/weekly/alert）とは独立した、**demo ユーザーの自動取引バッチ専用**のレポートメール。
`backend/scripts/execute_demo_trades.py`（cron Step 7）が `POST /api/v1/demo/trades` を完了した直後に送信する。
詳細なバッチ仕様は [`10_バッチ処理設計.md`](10_バッチ処理設計.md) 6.5節を参照。

### 概要

| 項目 | 内容 |
| ---- | ---- |
| 目的 | demo ユーザーの自動取引前後のポートフォリオ状態と当日の POST 結果を1通で通知する |
| 送信タイミング | `execute_demo_trades.py` 末尾（batch_logs 更新・マーカー作成の後） |
| 宛先 | `NOTIFY_TO_EMAIL`（Daily Advisor 系と共有） |
| 実装 | `backend/src/services/demo_portfolio_notifier.py:notify()` |
| テンプレート | `backend/src/services/templates/demo/portfolio_change.{md,html}.j2` |

### 件名フォーマット

`SUBJECT_MAX_LEN = 40` 文字目安。`user_id` は固定で `demo` のため省略しない（advisor 系との識別子）。

| 状況 | 例 |
| ---- | ---- |
| 通常（成功のみ） | `[5/14 demo] 取引2件・資産¥1,015,200 (+2.3%)` |
| 部分失敗 | `[5/14 demo] 取引2/3件成功 ⚠️ 資産¥1,008K (+1.6%)` |
| 全件失敗 | `[5/14 demo] 取引3件全失敗 ❌` |
| dry-run（trigger=always 時） | `[5/14 demo/dry-run] 提案3件 (POST未実行)` |

ETF 銘柄名・コードは件名に載せず、集計値のみで構成する（複数銘柄取引時の桁あふれ対策）。

### 本文構造（7セクション）

1. **結論ボックス**: 取引件数（succeeded/failed）・資産合計・前日比（HTMLは `#f7f9fc` 系の薄青ボックス）
2. **本日のPOST取引一覧**: ETFコード / 銘柄名 / 売買 / 数量 / 参考価格 / 約定金額 / 結果 / memo
3. **ポートフォリオ概況（取引後）**: 現金残高 / 保有銘柄数 / 評価額 / 資産合計 / 前日比
4. **保有銘柄スナップショット（構成比降順）**: etf_code / 銘柄名 / 数量 / 現在値 / 評価額 / 含み損益 / 構成比%
5. **過去1週間の資産推移**: `/demo/portfolio/valuation-history` の末尾7日
6. **失敗詳細**: `failed > 0` の場合のみ表示（エラーメッセージ・該当 trade 情報）
7. **フッタ**: ログパス（`logs/execute_demo_trades.log`）・`batch_logs.id`・関連レポート MD への誘導

### 送信トリガー

2段階の環境変数でフェイルセーフを構成する。

| 環境変数 | 値 | 動作 |
| -------- | -- | ---- |
| `DEMO_PORTFOLIO_REPORT_ENABLED` | `0`（既定） | trigger に関わらず送信しない（1段目フェイルセーフ） |
| `DEMO_PORTFOLIO_REPORT_ENABLED` | `1` | trigger の判定に従って送信判断する |
| `DEMO_PORTFOLIO_REPORT_TRIGGER` | `on_trade`（既定） | `effective_execute=True` かつ `succeeded + failed > 0` の場合のみ送信 |
| `DEMO_PORTFOLIO_REPORT_TRIGGER` | `always` | dry-run でも送信（テンプレ動作確認・件名検証用） |
| `DEMO_PORTFOLIO_REPORT_TRIGGER` | `never` | 送信しない |

SMTP 例外は `demo_portfolio_notifier.notify()` 内部で捕捉し、戻り値（bool）にのみ反映する。
`execute_demo_trades.py` の exit code は通知失敗に影響されない（WARN ログのみ残す）。

### モバイル最適化方針

Daily Advisor 系（[モバイル対応 CSS ルール](#モバイル対応-css-ルールhtml-のみ)）と同じ方針を踏襲。

- `<meta name="viewport" content="width=device-width, initial-scale=1.0">` 設定必須
- `<div style="max-width:600px;margin:0 auto;padding:16px;">` で 1 カラム
- CSS は全インライン、外部 CSS / `<font>` タグ禁止
- 取引一覧テーブルは縦並びカード化（モバイル幅で横スクロール回避）
- フォント最低 14px・`line-height:1.6`・配色固定（`background:#fff` / `color:#222`）
