# メール通知仕様

## 概要

Daily Advisor は ETF ポートフォリオの運用判断を支援するメール通知を 4 種類送信する。
本ドキュメントは件名・本文の仕様、モバイル最適化ルール、用語翻訳、テスト戦略を一元管理する。
バッチスケジュール・依存関係は [`10_バッチ処理設計.md`](10_バッチ処理設計.md) を参照。

### 4 種類のメール通知

| kind    | 配信タイミング       | 目的                                                |
| ------- | -------------------- | --------------------------------------------------- |
| morning | 平日 07:00           | 当日の発注（売却・買付）を通知し作業を案内          |
| evening | 平日 17:30           | 終値ベースの当日変動と配分・ルール状態を振り返る    |
| weekly  | 金曜 18:00           | 5 営業日のα・ベンチマーク比較と来週の推奨アクション |
| alert   | 9:00–15:00 平日 5 分間隔 | 機械ルール（損切・利確・N225急落・配分逸脱）即時通知 |

### 文体方針: アナリスト視点

「機械的な数値羅列」ではなく「結論先出し → 文脈 → 根拠」のアナリストレポート文体で記述する。
リード文 `summary` は以下の 3 層構造を維持する。

1. **結論**: 今日（本日／今週）何をすべきか／通常運用継続か
2. **文脈**: 前日比・月初比・α・配分状態などの数値
3. **根拠**: critical 発動の戦略書条項 or 配分逸脱の警告閾値超過 pp

静観時も「特になし。通常運用継続」を明示し、ノーニュースもニュースとして扱う。

## 件名フォーマット

全件名は `[M/D 区分] 結論` 形式。`SUBJECT_MAX_LEN = 40` 文字を目安にし、
超過時は `notification_renderer` から WARNING ログを出す。
`user_id` は件名に含めない。

| kind    | 静観時                       | アクション/警告時                                | 例外（複数件数時）                  |
| ------- | ---------------------------- | ------------------------------------------------ | ----------------------------------- |
| morning | `[4/30 朝] 通常運用日`       | `[4/30 朝] アクション2件・所要5分`               | `[4/30 朝] 配分逸脱2件`             |
| evening | `[4/29 夕] 本日 -0.3%`       | `[4/29 夕] 本日 -1.2% / 配分逸脱2件`             | —                                   |
| weekly  | `[5/1 週次] α -1.0pp`        | `[5/1 週次] α -3.0pp / 来週1件`                  | —                                   |
| alert   | —（trigger 0 件は通常配送なし） | `[4/29 緊急] 損切到達: 1306` / `[4/29 要確認] N225急落` | `[4/29 緊急] 機械ルール3件発動` |

実装は `backend/src/services/notification_renderer.py` の `subject_for()` および
`_subject_morning / _subject_evening / _subject_weekly / _subject_alert` を参照。

## 本文構造（4 種共通）

すべて「結論 → 文脈 → 根拠」の 3 層を踏襲する。

| kind    | セクション順序                                                                                                       |
| ------- | -------------------------------------------------------------------------------------------------------------------- |
| morning | 結論ボックス → 今日の発注（売却・買付 縦並び）→ 文脈（前日比・月初比・現金比率）→ 機械ルール → 戦略書フッター         |
| evening | 結論ボックス → 本日の市場文脈 → 配分（翻訳済 bucket、`is_warn` バッジ）→ 機械ルール → 明日の予定（無ければ「なし」明示） |
| weekly  | 結論ボックス（α + 配分逸脱件数）→ 5 営業日サマリ → 配分カテゴリ別 → 来週の推奨アクション → 今週の機械ルール → 戦略書フッター |
| alert   | severity 別カラー結論ボックス（赤=critical / 黄=warn / 青=info）→ 各 trigger（推奨アクション・メッセージ・payload 縦並び）→ 戦略書フッター |

Markdown 版はスタイル不適用のため文体のみ統一し、装飾はしない（モバイル対応対象外）。

## モバイル対応 CSS ルール（HTML のみ）

Gmail iOS / Gmail Web / Apple Mail を主要ターゲットとする。
ダークモード対応は Gmail で実質無視されるためスキップする。

### 必須ルール

- `<meta name="viewport" content="width=device-width, initial-scale=1.0">` 設定必須
- `<meta name="x-apple-disable-message-reformatting">` で iOS 自動リフロー抑止
- レイアウトは 1 カラム、`<table>` 禁止
- `<div style="max-width:600px;margin:0 auto;padding:16px;">` を root コンテナに使用
- 「ラベル + 値」の並びは `<dl><dt><dd>` または `<p>` で縦並び
- フォントは最低 14px（推奨 16px）、`line-height:1.6`
- 配色固定: `background:#fff` / `color:#222`
- リンクのタップ領域は `padding:12px 16px;display:inline-block;`（44px 相当）
- CSS は全インライン、外部 CSS / `<font>` タグ禁止

### 結論ボックス

- 通常運用: `background:#f7f9fc;border-left:4px solid #2c5aa0;`
- alert critical: 赤系 `#fdecec / #c0392b`
- alert warn: 黄系 `#fff8e1 / #c79100`
- alert info: 青系 `#e7f1fb / #2c5aa0`

詳細スタイルは `backend/src/services/templates/advisor/*.html.j2` のインライン CSS を参照。

## 用語翻訳表

`backend/src/services/templates/advisor/_macros.j2` で集中管理。テンプレートは必ず `{% from '_macros.j2' import bucket_label, rule_kind_label, action_label %}` で取り込む。

### bucket（アロケーションのカテゴリ）

| 内部値  | 表示       |
| ------- | ---------- |
| `core`  | コア（市場全体） |
| `theme` | テーマ     |
| `cash`  | 現金       |

### rule_kind（機械ルール種別）

| 内部値              | 表示                       |
| ------------------- | -------------------------- |
| `loss_cut`          | 損切りライン到達           |
| `take_profit_1`     | 利確ライン到達（第 1 段）  |
| `take_profit_2`     | 利確ライン到達（第 2 段）  |
| `n225_drawdown`     | N225 急落                  |
| `allocation_drift`  | 配分逸脱                   |

### action（売却/買付アクション）

| 内部値                    | 表示                |
| ------------------------- | ------------------- |
| `all`                     | 全量売却            |
| `schedule` / `sell_schedule` | 月次定期売却     |
| `dca` / `DCA`             | 定期積立（DCA）     |

## データコンテキスト（`NotificationContext`）

実装: `backend/src/services/daily_advisor_models.py:NotificationContext`。`@dataclass(frozen=True)` で不変。

| フィールド                | 型                          | 説明                                       |
| ------------------------- | --------------------------- | ------------------------------------------ |
| `kind`                    | `str`                       | `"morning" / "evening" / "weekly" / "alert"` |
| `today`                   | `date`                      | 通知基準日（JST）                          |
| `user_id`                 | `str`                       | 受信者識別。**件名には載せない**           |
| `strategy_revision`       | `date`                      | 戦略書 revision 日付（フッターに表示）     |
| `benchmark`               | `str`                       | ベンチマーク（既定 `^N225`）               |
| `sells_today`             | `Tuple[SellAction, ...]`    | 当日の売却予定                             |
| `buys_today`              | `Tuple[BuyAction, ...]`     | 当日の買付予定                             |
| `total_asset`             | `float`                     | 総資産（現金 + 評価額）                    |
| `total_value`             | `float`                     | 評価額                                     |
| `cash_balance`            | `float`                     | 現金残高                                   |
| `daily_change_pct`        | `Optional[float]`           | 前日比（%）                                |
| `holdings_count`          | `int`                       | 保有銘柄数                                 |
| `allocation_drifts`       | `Tuple[AllocationDrift, ...]` | 配分カテゴリ別の乖離                     |
| `triggers`                | `Tuple[RuleTrigger, ...]`   | 機械ルール発動                             |
| `alpha_pp`                | `Optional[float]`           | α（pp、weekly 専用）                       |
| `period_label`            | `Optional[str]`             | 期間ラベル（例: `過去5営業日`）            |
| `portfolio_return_pct`    | `Optional[float]`           | ポートフォリオリターン（%）                |
| `benchmark_return_pct`    | `Optional[float]`           | ベンチマークリターン（%）                  |
| `month_start_total_asset` | `Optional[float]`           | 月初時点総資産（None 時はテンプレで分岐）   |
| `month_start_change_pct`  | `Optional[float]`           | 月初比（%、None フォールバック）           |
| `extra`                   | `Dict[str, Any]`            | 拡張用                                     |

### 月初データの None フォールバック

`PortfolioService` に「月初時点総資産取得 API」が未実装のため、`month_start_*` は `None` で先行リリース。
テンプレートは `{% if month_start_change_pct is not none %}` で分岐し、
未取得時は当該行をスキップする。

### 派生フィールド（テンプレート渡し用）

`notification_renderer._context_to_params()` が以下も合わせて渡す。

| キー                | 算出元                              |
| ------------------- | ----------------------------------- |
| `urgency_tag`       | `urgency_tag(ctx)`（緊急/要対応/要確認/情報/静観） |
| `summary`           | `summary_for(ctx)`（3 行リード文）  |
| `action_count`      | `len(sells_today) + len(buys_today)` |
| `estimated_minutes` | `clamp(round(2 + 2.5 * action_count), 3, 30)` |

## テスト戦略

### 既存ユニットテスト

`backend/tests/unit/services/test_notification_renderer.py`

`subject_for / urgency_tag / summary_for / recommended_action / render` の挙動を 33 ケースで検証。
件名は文字列の構造（先頭が `[M/D 区分]` で始まる、`通常運用日` を含む等）を assert する設計とし、
将来のリライトに過度に脆くしない。

### スナップショットテスト

`backend/tests/unit/services/test_notification_renderer_snapshot.py`

11 ケース × md/html を `__snapshots__/` 配下のゴールデンファイルと完全一致比較する。

#### ケース一覧

| kind    | tag                  | 状況                              |
| ------- | -------------------- | --------------------------------- |
| morning | `seikan`             | 売買・トリガーなし                |
| morning | `action_buy_only`    | 買付のみ                          |
| morning | `action_sell_buy`    | 売却 + 買付                       |
| morning | `critical`           | loss_cut critical 発動            |
| evening | `seikan`             | warn なし                         |
| evening | `warn_drift`         | 配分逸脱 warn                     |
| weekly  | `seikan`             | α=-1.0（>-2.0、静観）             |
| weekly  | `warn_alpha`         | α=-3.0（≦-2.0、要確認）           |
| alert   | `critical`           | loss_cut critical                 |
| alert   | `warn`               | n225_drawdown warn                |
| alert   | `info`               | n225_drawdown info                |

#### 期待値の更新手順

```bash
# 期待値をリライト後の出力で上書き
docker compose exec -T -e SNAPSHOT_UPDATE=1 backend \
    pytest tests/unit/services/test_notification_renderer_snapshot.py -v

# 差分確認後にコミット
git diff backend/tests/unit/services/__snapshots__/
```

外部ライブラリ（syrupy 等）は不採用＝YAGNI。`SNAPSHOT_UPDATE` 環境変数による
シンプルな手書き比較で運用する。

### 開発用 artifact ダンプ

`backend/scripts/_dev/dump_email_artifacts.py`

リライト時の差分目視用。`tmp/email_artifacts_before/` または
`tmp/email_artifacts_after/` に 11 ケース × md/html を出力する。
本テストではないため `pytest` 配下には置かない。
