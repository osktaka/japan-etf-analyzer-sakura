# さくらレンタルサーバー（スタンダード）Flask + React SPA 構築ガイド

## はじめに

さくらレンタルサーバー スタンダードプランでFlask APIバックエンド + React SPAフロントエンドを動かすためのガイド。CGI実行モデル特有の制約と対策を体系的にまとめる。

### 制約サマリー

| 制約 | 内容 |
|------|------|
| Docker | 不可 |
| Node.js | 不可（サーバー側） |
| プロセス常駐 | 不可（gunicorn/uvicorn等は使えない） |
| OpenSSL | 1.0.2-chacha（古い） |
| OS | FreeBSD 13.0 |
| /tmp | noexecマウント（ビルド時に問題） |
| 実行モデル | CGI（毎リクエストでプロセス起動） |

### 2. Python依存関係の制約

#### OpenSSL 1.0.2互換

OpenSSL 1.0.2ではTLS 1.3非対応。以下のバージョン制約が**必須**。

```txt
# requirements.txt（制約部分）

# CHANGE_ME: プロジェクトで使うパッケージに合わせて調整

Flask==2.3.3
urllib3<2.0            # v2.0以降はOpenSSL 1.1.1+が必要
requests<2.29.0        # urllib3 v2依存を避ける
```

#### FreeBSDビルド制約

```txt
# FreeBSD環境でビルドが通るバージョンを指定
numpy==1.19.5          # メモリ消費が少なくFreeBSDでビルド可
pandas==1.3.5          # numpy 1.19.5との互換性
```

#### Rustビルド回避

cryptographyパッケージはデフォルトでRustコンパイラを要求するが、さくらサーバーにはRustがない。

```bash
# setup.sh内で設定（後述）
export CRYPTOGRAPHY_DONT_BUILD_RUST=1
```

#### TMPDIR問題

さくらサーバーの`/tmp`はnoexecマウントのため、pip installやビルド時にPermission deniedが発生する。

```bash
# ホームディレクトリ配下にtmpを作成
export TMPDIR="$HOME/tmp"
mkdir -p "$TMPDIR"
```

### 3. CGIでFlaskを動かす（核心）

#### index.cgiテンプレート

`api/index.cgi` に配置する。CGI経由でFlaskアプリを起動するエントリーポイント。

```python
#!/home/YOUR_USERNAME/.pyenv/versions/YOUR_PYTHON_VERSION/bin/python3
# CHANGE_ME: ↑ pyenvの絶対パスに変更（`which python3`で確認）
# -*- coding: utf-8 -*-
"""Flask CGI entry point."""

import os
import sys
from pathlib import Path

# __file__をresolve()で絶対パスに変換（CGIはCWDが不定のため必須）
APP_ROOT = Path(__file__).resolve().parent.parent  # CHANGE_ME: ディレクトリ階層に合わせる

# backendディレクトリをsys.pathに追加
sys.path.insert(0, str(APP_ROOT / "backend"))  # CHANGE_ME: バックエンドのパス

# venvのsite-packagesを追加（CGIはvenvを自動認識しない）
venv_site_packages = (
    APP_ROOT / "backend" / "venv" / "lib"
    / "python3.9"  # CHANGE_ME: Pythonバージョン
    / "site-packages"
)
if venv_site_packages.exists():
    sys.path.insert(0, str(venv_site_packages))

# .env手動パース（python-dotenvはimportコスト削減のため非使用）
env_file = APP_ROOT / ".env"
if env_file.exists():
    with open(env_file) as f:
        for line in f:
            line = line.strip()
            if line and not line.startswith("#"):
                key, _, value = line.partition("=")
                os.environ.setdefault(key.strip(), value.strip())

# 環境変数設定
os.environ.setdefault("FLASK_ENV", "production")
os.environ.setdefault("APP_BASE_DIR", str(APP_ROOT))
os.environ.setdefault("APP_DATA_DIR", str(APP_ROOT / "data"))

# DATABASE_URLは絶対パス必須（CGIのCWDは不定）
db_path = APP_ROOT / "data" / "etf.db"  # CHANGE_ME: DBファイルパス
os.environ["DATABASE_URL"] = f"sqlite:///{db_path}"

# CWDを固定（相対パスでファイルを参照するコードの保険）
os.chdir(APP_ROOT)

# Flaskアプリのimport（失敗時はプレーンテキストでエラー出力）
try:
    from src.app import app  # CHANGE_ME: Flaskアプリのimportパス
except Exception as e:
    # CGIエラー時はContent-Typeヘッダーを出力してからエラー内容を表示
    print("Content-Type: text/plain\n", flush=True)
    print(f"ERROR: Failed to load Flask app", flush=True)
    print(f"CWD: {os.getcwd()}", flush=True)
    print(f"DATABASE_URL: {os.environ.get('DATABASE_URL')}", flush=True)
    print(f"\n{e}", flush=True)
    import traceback
    traceback.print_exc()
    sys.exit(1)

from wsgiref.handlers import CGIHandler


class PrefixMiddleware:
    """RewriteRule後のPATH_INFOにプレフィックスを追加するWSGIミドルウェア。

    問題:
      リクエスト: /YOUR_APP_NAME/api/v1/health
      RewriteRule後: /YOUR_APP_NAME/api/index.cgi/v1/health
      PATH_INFO: /v1/health（/apiプレフィックスがない）
      Flaskルート: /api/v1/health（/apiプレフィックスがある）
    → PATH_INFOに/apiを付与して不一致を解消する。
    """

    def __init__(self, app, prefix=""):
        self.app = app
        self.prefix = prefix

    def __call__(self, environ, start_response):
        if "PATH_INFO" in environ:
            environ["PATH_INFO"] = self.prefix + environ["PATH_INFO"]
        # Authorizationヘッダー復元（後述の.htaccess設定と対）
        http_auth = environ.get("HTTP_AUTHORIZATION") or os.environ.get(
            "HTTP_AUTHORIZATION"
        )
        if http_auth and "HTTP_AUTHORIZATION" not in environ:
            environ["HTTP_AUTHORIZATION"] = http_auth
        return self.app(environ, start_response)


app = PrefixMiddleware(app, "/api")  # CHANGE_ME: Flaskルートのプレフィックス

if __name__ == "__main__":
    CGIHandler().run(app)
```

#### PrefixMiddleware解説

Apache RewriteRuleで `api/(.*)` → `api/index.cgi/$1` に書き換えた結果、CGIが受け取る`PATH_INFO`には`/api`プレフィックスが含まれない。一方Flaskのルート定義は`@app.route('/api/v1/...')`のようにプレフィックス付き。PrefixMiddlewareがこのギャップを埋める。

#### Authorizationヘッダー復元

Apache CGIはセキュリティ上の理由で`Authorization`ヘッダーをCGIスクリプトに渡さない。JWT認証等を使う場合は以下の2箇所の対応が必要:

1. **.htaccess側**: `RewriteRule`で環境変数に退避（[セクション4](#4-htaccess-必須設定)参照）
2. **CGI側**: PrefixMiddleware内で`os.environ.get("HTTP_AUTHORIZATION")`から復元

#### パフォーマンス設計指針

CGIは毎リクエストでPythonプロセスを起動するため、コールドスタートが発生する。

| 対策 | 説明 |
|------|------|
| importの最小化 | index.cgiのトップレベルimportは最小限に |
| lazy import | 重いライブラリ（pandas, numpy等）は使用時にimport |
| 軽量フレームワーク | Flask推奨。Django等はimportコストが大きい |
| requirements.txt | 不要なパッケージを入れない |

#### SQLite同時書き込み対策

CGIはリクエストごとに別プロセスで動くため、同時書き込みで`database is locked`が発生しやすい。

```python
# Flaskアプリの設定で以下を追加
# CHANGE_ME: タイムアウト値はアプリの特性に合わせて調整
SQLALCHEMY_ENGINE_OPTIONS = {
    "connect_args": {
        "timeout": 30,  # busy_timeout（秒）
    },
    "pool_pre_ping": True,
}
```

```sql
-- SQLiteのWALモード有効化（初回のみ実行）
PRAGMA journal_mode=WAL;
```

WALモードにより読み取りと書き込みの並行実行が可能になり、lockエラーが大幅に減る。

### 4. .htaccess 必須設定

以下はCGI + Flaskを動かすための**最小構成**。

```apache
# === CGI有効化（必須） ===
Options +ExecCGI
AddHandler cgi-script .cgi

# === RewriteEngine有効化 ===
RewriteEngine On
RewriteBase /YOUR_APP_NAME/  # CHANGE_ME: サブディレクトリ名（ルートなら /）

# === Authorizationヘッダー環境変数渡し（JWT等の認証を使う場合は必須） ===
# Apache CGIはAuthorizationヘッダーを渡さないため、環境変数経由で受け渡す
RewriteCond %{HTTP:Authorization} ^(.+)$
RewriteRule .* - [E=HTTP_AUTHORIZATION:%1]

# === API → CGIルーティング（必須） ===
# index.cgiを除外しないと無限ループになる
RewriteCond %{REQUEST_URI} !index\.cgi
RewriteRule ^api/(.*)$ api/index.cgi/$1 [L,QSA]
```

**ポイント**:

- `RewriteCond %{REQUEST_URI} !index\.cgi` がないと、`api/index.cgi/v1/health` が再度 `api/(.*)` にマッチして無限ループする
- `[L,QSA]`: `L`=最終ルール（後続ルール無視）、`QSA`=クエリ文字列を引き継ぐ

### 5. セットアップ・デプロイ

#### setup.sh テンプレート

```bash
#!/bin/bash
set -e

PROJECT_ROOT=$(cd "$(dirname "$0")" && pwd)
cd "$PROJECT_ROOT"

# === pyenv検出 ===
# CHANGE_ME: pyenvのバージョンパスを合わせる

    PYTHON_PATH="/usr/local/bin/python3"

# === venv構築 ===

# === TMPDIR変更（/tmpがnoexec） ===

if [ ! -f ".env" ]; then
    echo "Warning: .env file not found! cp .env.example .env"
fi

# === ディレクトリ・パーミッション ===
mkdir -p data
chmod 755 api/index.cgi  # CGIスクリプトは実行権限必須
chmod 755 setup.sh

```

### 6. cron運用

#### cron実行時の環境変数ロード

cronはログインシェルではないため、`~/.bash_profile`等が読まれない。pyenvのPATHが通らず`python3: not found`になる。

```bash
#!/bin/bash
# cron_wrapper.sh - cronから呼ぶラッパースクリプト
set -uo pipefail

PROJECT_DIR="/home/YOUR_USERNAME/www/YOUR_APP_NAME"  # CHANGE_ME
cd "$PROJECT_DIR"

# pyenvのPATHを明示的に設定
export PATH="$HOME/.pyenv/versions/YOUR_PYTHON_VERSION/bin:$PATH"  # CHANGE_ME

# venvアクティベート
source backend/venv/bin/activate

# ログ出力先
LOG_DIR="$PROJECT_DIR/logs"
mkdir -p "$LOG_DIR"
LOG_FILE="$LOG_DIR/cron_$(date +%Y%m%d).log"

# 実行
echo "=== $(date '+%Y-%m-%d %H:%M:%S') ===" >> "$LOG_FILE"
python backend/scripts/your_script.py >> "$LOG_FILE" 2>&1  # CHANGE_ME
```


### 7. トラブルシューティング

#### 500エラーデバッグフロー

```
500 Internal Server Error
  ↓
1. パーミッション確認: chmod 755 api/index.cgi
  ↓
2. shebang確認: head -1 api/index.cgi → pyenvパスが正しいか
  ↓
3. 改行コード確認: file api/index.cgi → LFであること（CRLFだと動かない）
  ↓
4. 手動実行: cd ~/www/YOUR_APP_NAME && python api/index.cgi
  → importエラーやパスの問題が表示される
  ↓
5. エラーログ確認: ~/log/error_log（さくらサーバー標準）
```

#### よくある問題

| 症状 | 原因 | 対策 |
|------|------|------|
| 500 Internal Server Error | index.cgiのパーミッションが644 | `chmod 755 api/index.cgi` |
| 500 Internal Server Error | shebang行のパスが間違い | `which python3`で確認 |
| 500 Internal Server Error | Windows改行コード（CRLF） | `dos2unix api/index.cgi` |
| ModuleNotFoundError | venvのsite-packagesがsys.pathにない | index.cgiのパスを確認 |
| database is locked | SQLite同時書き込み | WALモード + busy_timeout |
| pip install失敗 | /tmp noexec | `export TMPDIR="$HOME/tmp"` |
| pip install失敗（cryptography） | Rustコンパイラ不在 | `CRYPTOGRAPHY_DONT_BUILD_RUST=1` |
| urllib3/requestsエラー | OpenSSL 1.0.2非互換 | バージョン制約を確認 |
| Authorizationヘッダーがない | Apache CGIの仕様 | .htaccessとPrefixMiddleware |
| PATH_INFOがFlaskルートと不一致 | RewriteRule後のパス変換 | PrefixMiddleware |
| cronでcommand not found | PATHが通っていない | ラッパースクリプトでPATH設定 |
| 無限リダイレクト | .htaccessのRewriteRuleループ | `RewriteCond !index\.cgi` |
| 404 Not Found | RewriteBaseが間違い | サブディレクトリ名を確認 |

### 8. フロントエンドビルド戦略

さくらサーバーにはNode.jsがないため、ビルド済みファイルをサーバーに配置する必要がある。

#### dist/ Git管理 + pre-commit hook

本プロジェクトでは`frontend/dist/`をGit管理に含め、pre-commit hookで自動ビルドする方式を採用。

```bash
#!/bin/bash
# .git/hooks/pre-commit
# frontend/src/に変更がある場合のみビルド実行
FRONTEND_SRC_CHANGED=$(git diff --cached --name-only --diff-filter=ACM | grep '^frontend/src/' || true)

if [ -n "$FRONTEND_SRC_CHANGED" ]; then
    (cd frontend && npm run build)
    BUILD_STATUS=$?
    if [ $BUILD_STATUS -ne 0 ]; then
        echo "Error: Frontend build failed. Commit aborted."
        exit 1
    fi
    git add frontend/dist/
fi

exit 0
```

hookのインストール:

```bash
#!/bin/bash
# scripts/install-hooks.sh
cp scripts/pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

#### Vite base path設定

サブディレクトリに配置する場合、Viteのbase pathを設定する。


#### SPAフォールバック

React Router等のクライアントサイドルーティングを使う場合、存在しないパスを`index.html`にフォールバックさせる。

```apache
# 実ファイル・ディレクトリでなければindex.htmlへ

RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteCond %{REQUEST_URI} !^/YOUR_APP_NAME/api/  # CHANGE_ME
RewriteRule . index.html [L]

ErrorDocument 404 /YOUR_APP_NAME/index.html  # CHANGE_ME
```

#### OGP動的生成

SNSシェア時のOGPタグをサーバーサイドで生成する場合の例（notesパス）。

```apache
# /notes/記事スラッグ → CGIで動的HTML生成
RewriteRule ^notes/index\.html$ api/index.cgi/v1/notes/index.html [L]
RewriteRule ^notes/([^/.]+)\.html$ api/index.cgi/v1/notes/$1.html [L]
RewriteRule ^notes/([^/.]+)$ api/index.cgi/v1/notes/$1.html [L]
```

#### sitemap.xml動的生成

```apache
RewriteRule ^sitemap\.xml$ api/index.cgi/v1/sitemap.xml [L]
```

### 10. データベースマイグレーション

#### 2段階マイグレーション方式

本プロジェクトでは以下の2段階でDBスキーマを管理する。

1. **SQLファイル実行**: `scripts/migrations/*.sql`（ALTER TABLE等、既存テーブルの変更）
2. **Flask db.create_all()**: 新規テーブルの自動作成（モデル定義から）

#### migrate.sh の構造

```bash
#!/bin/bash
set -e

PROJECT_ROOT=$(cd "$(dirname "$0")" && pwd)
cd "$PROJECT_ROOT"

DB_PATH="$PROJECT_ROOT/data/etf.db"
BACKUP_DIR="$PROJECT_ROOT/data/backups"

# === バックアップ ===
mkdir -p "$BACKUP_DIR"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
cp "$DB_PATH" "$BACKUP_DIR/etf.db.backup_$TIMESTAMP"
echo "Backup: $BACKUP_DIR/etf.db.backup_$TIMESTAMP"

# === マイグレーション管理テーブル ===
sqlite3 "$DB_PATH" "CREATE TABLE IF NOT EXISTS migrations_applied (
    filename TEXT PRIMARY KEY,
    applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);"

# === SQLマイグレーション実行（冪等） ===
for sql_file in scripts/migrations/*.sql; do
    filename=$(basename "$sql_file")
    already=$(sqlite3 "$DB_PATH" "SELECT COUNT(*) FROM migrations_applied WHERE filename='$filename';")
    if [ "$already" = "0" ]; then
        echo "Applying: $filename"
        sqlite3 "$DB_PATH" < "$sql_file"
        sqlite3 "$DB_PATH" "INSERT INTO migrations_applied (filename) VALUES ('$filename');"
    else
        echo "Skip (already applied): $filename"
    fi
done

# === Flask db.create_all()（新規テーブル自動作成） ===
source backend/venv/bin/activate
python -c "
import os, sys
from pathlib import Path
PROJECT_ROOT = Path('$PROJECT_ROOT')
os.environ['APP_BASE_DIR'] = str(PROJECT_ROOT)
os.environ['APP_DATA_DIR'] = str(PROJECT_ROOT / 'data')
os.environ['DATABASE_URL'] = 'sqlite:///$DB_PATH'
sys.path.insert(0, str(PROJECT_ROOT / 'backend'))
from src.app import create_app
app = create_app()
with app.app_context():
    from src.database import db
    db.create_all()
"

echo "Migration complete."
echo "Rollback: cp $BACKUP_DIR/etf.db.backup_$TIMESTAMP $DB_PATH"
```

#### SQLマイグレーションファイルの命名規則

```
scripts/migrations/001_create_user_settings.sql
scripts/migrations/002_add_is_admin_to_users.sql
```

- 連番（既存の最大値+1）
- `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` で冪等性を確保
- `migrations_applied`テーブルで実行済み管理

### 11. バッチスクリプトのパス解決

#### CGI vs バッチの差分

| 項目 | CGI（index.cgi） | バッチスクリプト |
|------|------------------|----------------|
| 起動元 | Apache | cron / 手動実行 |
| CWD | 不定 | 不定 |
| 環境変数 | .htaccess + .env | 自分で設定が必要 |
| venv | sys.pathで手動追加 | activateまたはsys.pathで追加 |
| DB パス | index.cgiで設定済み | 自分で設定が必要 |

#### 冒頭テンプレート

`backend/scripts/`配下のPythonスクリプトは、以下のテンプレートを冒頭に記述する。

```python
"""バッチスクリプトのテンプレート。"""
import os
import sys
from pathlib import Path

# パス解決（backend/scripts/ → backend/ → project root）
SCRIPT_DIR = Path(__file__).resolve().parent
BACKEND_DIR = SCRIPT_DIR.parent
PROJECT_ROOT = BACKEND_DIR.parent  # CHANGE_ME: 階層に合わせる

# 環境変数設定（CGI経由でないため手動設定が必要）
os.environ.setdefault("APP_BASE_DIR", str(PROJECT_ROOT))
os.environ.setdefault("APP_DATA_DIR", str(PROJECT_ROOT / "data"))
db_path = PROJECT_ROOT / "data" / "etf.db"  # CHANGE_ME: DBパス
os.environ.setdefault("DATABASE_URL", f"sqlite:///{db_path}")

# backendをsys.pathに追加
sys.path.insert(0, str(BACKEND_DIR))

# === ここから下にビジネスロジックを記述 ===
# from src.app import create_app
# app = create_app()
```
