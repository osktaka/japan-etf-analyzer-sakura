### 2.2 依存関係ルール

- 上位レイヤーは下位レイヤーに依存可能
- 下位レイヤーは上位レイヤーに依存しない
- 外部ライブラリへの依存はInfrastructure Layerに集約

| 項目 | 対策 |

| CSRF | CSRFトークン |

## 7. 拡張性への配慮

### 7.1 Phase 2対応の設計ポイント

| 機能 | 設計上の配慮 |
|------|--------------|
| ユーザー認証 (F-104) | ミドルウェア層での認証チェック挿入を想定 |

### 7.2 モジュール分割方針

- 機能追加時は既存コードを修正せず、新規モジュールを追加
- インターフェースを明確に定義し、疎結合を維持
- 設定ファイルで機能のON/OFFを切り替え可能に

## 9. 実装パターン

### 9.1 Repository-Service-Route パターン（バックエンド）

すべてのドメイン（ETF, Favorite, Auth, Category, Tag）は以下の4層構造で実装：

| レイヤー | 役割 | ファイル例 |
|---------|------|-----------|
| models/ | データ定義（SQLAlchemy） | etf.py |
| repositories/ | DBアクセス（CRUD操作） | etf_repository.py |
| services/ | ビジネスロジック | etf_service.py |
| routes/ | APIエンドポイント | etf_routes.py |

新機能追加時は上記4ファイルを対応させる。

> **初期設計からの変更点:**
> - `metric.py`（指標エンティティ）は廃止し、ETFモデル（`etf.py`）に指標カラムを直接定義
> - `search_service.py`（検索ロジック）は `etf_service.py` + `etf_repository.py` に統合
> - `DetailPage.tsx`（銘柄詳細画面）は `ETFDetailModal`（モーダルコンポーネント）に変更

### 9.2 Barrel Export パターン（フロントエンド）

全ディレクトリで index.ts を使用し、インポートパスを短縮：

```typescript
// components/search/index.ts から
import { SearchBar } from '../components/search'

// hooks/index.ts から
import { useETFSearch } from '../hooks'
```
