## 2. レイヤードアーキテクチャ

### 2.1 バックエンドレイヤー構成

```
┌─────────────────────────────────────────────────────────────────┐
│                        Presentation Layer                        │
│                           (Routes)                               │
│   - HTTPリクエストの受付                                          │
│   - リクエストバリデーション                                       │
│   - レスポンス整形                                                │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                        Application Layer                         │
│                          (Services)                              │
│   - ビジネスロジック                                              │
│   - ユースケース実装                                              │
│   - トランザクション管理                                          │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                        Domain Layer                              │
│                          (Models)                                │
│   - エンティティ定義                                              │
│   - ドメインルール                                                │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                      Infrastructure Layer                        │
│                       (Repositories)                             │
│   - データベースアクセス                                          │
│   - 外部API連携（yfinance）                                       │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 依存関係ルール

- 上位レイヤーは下位レイヤーに依存可能
- 下位レイヤーは上位レイヤーに依存しない
- 外部ライブラリへの依存はInfrastructure Layerに集約

## 5. セキュリティ設計

### 5.1 Phase 1（MVP）

| 項目 | 対策 |
|------|------|
| 認証 | なし（公開情報のみ） |
| CORS | フロントエンドドメインのみ許可 |
| 入力検証 | すべてのAPIパラメータをバリデーション |
| SQLインジェクション | SQLAlchemy ORMによるパラメータバインド |
| XSS | Reactによる自動エスケープ |

### 5.2 Phase 2以降（ユーザー認証実装時）

| 項目 | 対策 |
|------|------|
| 認証 | セッションベース認証 |
| セッション管理 | HTTPOnlyクッキー、Secure属性 |
| CSRF | CSRFトークン |
| パスワード | bcryptによるハッシュ化 |

## 6. エラーハンドリング方針

### 6.1 バックエンド

```python
# エラーレスポンス形式
{
    "error": {
        "code": "ERR_NOT_FOUND",
        "message": "指定された銘柄が見つかりません",
        "details": {}
    }
}
```

| HTTPステータス | 用途 |
|----------------|------|
| 200 | 正常 |
| 400 | リクエスト不正 |
| 404 | リソース未検出 |
| 500 | サーバーエラー |

### 6.2 フロントエンド

- APIエラー: ユーザーフレンドリーなメッセージを表示
- ネットワークエラー: リトライ案内を表示
- 予期しないエラー: エラーバウンダリでキャッチ

## 7. 拡張性への配慮

### 7.1 Phase 2対応の設計ポイント

| 機能 | 設計上の配慮 |
|------|--------------|
| ユーザー認証 (F-104) | ミドルウェア層での認証チェック挿入を想定 |
| お気に入り (F-102) | user_idカラム追加でテーブル拡張可能 |
| 比較機能 (F-103) | 複数銘柄取得APIは検索APIで対応可能 |
| 売買履歴 (F-105) | transactionsテーブル追加で対応 |

### 7.2 モジュール分割方針

- 機能追加時は既存コードを修正せず、新規モジュールを追加
- インターフェースを明確に定義し、疎結合を維持
- 設定ファイルで機能のON/OFFを切り替え可能に

## 8. 技術的考慮事項

### 8.1 さくらサーバー制約への対応

| 制約 | 対応策 |
|------|--------|
| Docker不可 | CGI/FastCGI経由でFlask実行 |
| Python 3.8 | 互換性のあるライブラリバージョンを使用 |
| Node.js不可 | ビルド済み静的ファイルをデプロイ |
| ファイル書き込み | データディレクトリのパーミッション設定 |

### 8.2 パフォーマンス考慮

| 項目 | 対策 |
|------|------|
| APIレスポンス | 3秒以内（要件準拠） |
| データベースクエリ | インデックス最適化 |
| 外部API | キャッシュ活用、バッチ取得 |
| フロントエンド | 遅延読み込み、コード分割 |

## 9. 実装パターン

### 9.1 Repository-Service-Route パターン（バックエンド）

すべてのドメイン（ETF, Favorite, Auth, Category, Tag）は以下の4層構造で実装：

| レイヤー | 役割 | ファイル例 |
|---------|------|-----------|
| models/ | データ定義（SQLAlchemy） | etf.py |
| repositories/ | DBアクセス（CRUD操作） | etf_repository.py |
| services/ | ビジネスロジック | etf_service.py |
| routes/ | APIエンドポイント | etf_routes.py |

新機能追加時は上記4ファイルを対応させる。

### 9.2 Barrel Export パターン（フロントエンド）

全ディレクトリで index.ts を使用し、インポートパスを短縮：

```typescript
// components/search/index.ts から
import { SearchBar } from '../components/search'

// hooks/index.ts から
import { useETFSearch } from '../hooks'
```
